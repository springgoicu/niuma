## 产品概述
在现有牛马园区中加入一套随时可玩的 1v1 互动层：点人即可约战，双方接受后进入街头摇骰子、灵魂猜拳或野外切磋。赌注由服务端托管并按规则结算，附近路人能在双方头顶看到像素演出，钱包仍只活在本次进程与浏览器本地，不引入持久化。

## 核心功能
- **街头摇骰子（gameType=1）**：支持 0 / 10 / 50 / 200 牛马币或自定义押注；服务端为双方各生成 3 颗 1~6 点骰子，1.8 秒后按「豹子 > 顺子 > 总点数」结算，平局退本金，赢家拿走奖池 95%，5% 为园区税。双方头顶先快速翻滚 1.5 秒，再定格为最终骰子与 WIN / LOSE 标志，持续 4 秒后淡出，附近 AOI 玩家都能围观。
- **灵魂猜拳（gameType=2）**：接受后弹出石头 / 剪刀 / 布三个大按钮，5 秒盲选；超时未选由服务端随机出拳。双方出拳后广播头顶像素手势并结算，平局自动加赛，最多 3 轮，第 3 轮仍平则退款。
- **野外单挑切磋（gameType=3）**：广场、草地任意位置可约战；接受后双方头顶出现 100 HP 像素血条与 30 秒倒计时。E 键头槌按暴击 / 护甲等级计算伤害并大幅击退，Space 跳起提供 0.4 秒闪避无敌帧；HP 归零、跑出约定中心点 220px 或超时判负，赢家拿走双方赌注并扣 5% 税，无关路人不受伤。
- **快捷打赏**：点人菜单新增「直接打赏 10 币」按钮，无需二次确认，双方头顶冒出 +XX币 飘字，当前按 0% 税执行。
- **像素表现**：骰子、石头剪刀布手势、WIN / LOSE 标志全部用程序化像素画生成纹理，1:1 nearest，不引入任何外部图片资源。

## 视觉与交互效果
挑战入口从固定押注改为「玩法选择 + 押注选择」浮层；邀请浮窗与对局条按玩法显示名称、押注、税率和倒计时；猜拳期间三个大按钮占据屏幕下方，出拳后锁定并显示已选；切磋期间头顶血条随受击抖动，时间条随剩余秒数变色；所有演出结束后平滑淡出，不遮挡昵称与聊天气泡。


## 技术栈
- Monorepo：pnpm 10 + Turborepo 2 + TypeScript 5 strict。
- 服务端：Bun WebSocket + 20Hz 固定 Tick，权威世界状态只存进程内存；随机骰子使用 `node:crypto` 的 `randomInt`。
- 客户端：Next.js 15 App Router、React 19、Tailwind CSS v4、Zustand 5、PixiJS 8；默认渲染循环运行在 Dedicated Worker。
- 协议：手写二进制帧，客户端与服务端共用 `packages/shared-types`，不新增 JSON 通道。
- 复用：`ChallengeBus`（邀请 / 托管 / 对局 / 退款）、`EconomyService`（钱包 / 冻结 / 结算 / 打赏）、`Player.stats.critLv / armorLv`、`EntityView.labels` 头顶标签层。

## 实现策略
1. **协议先行**：在共享包中重排三种玩法编号，新增行动包、亮牌包与切磋状态包，先保证双端可编译、可解析，再接玩法逻辑。
2. **总线只做通用能力**：抽税、AOI 广播、行动路由、切磋战斗端口都收敛在 `ChallengeBus`，三个玩法只实现 `ChallengeHandler`，不重复写邀请、退款与断线清理。
3. **骰子先算后演**：服务端在开局时一次掷出双方骰子并算好胜负，立即下发亮牌包供客户端播放 1.5 秒滚动动画，1.8 秒后再真正结算；这样视觉与结算共用同一份随机结果，不会出现「动画结果和到账不一致」。
4. **猜拳多回合复用同一局**：每轮结束时只广播亮牌包，平局则推进 `match.endsAt` 并清空双方出拳，最多 3 轮；总线的硬超时仍以当前 `endsAt + 5s` 兜底，不会被多轮拖死。
5. **切磋独立战斗域**：给 `resolveVents` 注入可选 `DuelCombatPort`，切磋中只允许命中对手、走独立伤害与大击退，不倒地、不进执法统计，也不影响擂台。
6. **表现留在渲染线程**：`GameSession` 与 `GameRenderer` 同线程，亮牌包直接驱动 PixiJS 头顶层；主线程只接收猜拳回合事件与既有 HUD 状态。Worker 模式下补齐当前缺失的经济 / P2P 回调转发。
