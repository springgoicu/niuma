## 产品概述
护士急救站里经常同时聚集很多角色。现场看到的"人多"，本质是**治疗完成的伤员（真人与 NPC）起身或下床后原地停在床尾/落点，不再移动**，越积越多，站内显得拥挤、像堵住了一样。

## 核心功能
- 伤员治疗结束、下床过渡完成后，系统立即接管其位置，让其**沿站内走廊逐帧走出站体**，最终停在西门外的服务广场铺装上，站体内部不再滞留康复者。
- 真人与 NPC 一视同仁：真人出院期间由服务端独占坐标（玩家暂时无法自主移动），到站外后恢复操作并领取护盾；NPC 出院完成后续接原有巡逻/盯梢行为。
- 出院是**连续逐帧位移**（可见地走出来），不是瞬间消失；全程走现有门禁与走廊，不穿墙、不塞进障碍。
- 出站后立即发放原有的 15 秒工伤免疫与康复播报，玩法数值口径不变。
- 新增一份架构决策记录，说明本次"系统护送出院"与旧规则"伤员自己走出去"的差异，作为后续唯一事实源。

## 明确不做
- 不改网络协议字段、不新增包类型、不写任何持久化状态（仍只在进程内存）。
- 不改变倒地、排队、派车、上床、治疗时长、免疫时长等既有玩法数值。
- 不改造站体几何、不新增美术资产、不做场景外观重做。
- 不强制清理"正在急救链中"的伤员（躺床、挂车、被护送、过渡中的人）。


## 技术栈
沿用现有工程，不引入新依赖：
- 服务端模拟：`apps/game-server/src/sim/clinic.ts`（TypeScript，Tick 驱动，服务端时钟）。
- NPC 行为层：`apps/game-server/src/npc/director.ts` / `brain.ts`（仅调整调用时机与康复期间ownership，不改接口）。
- 客户端：`apps/web/lib/game/session.ts`（PixiJS + ECS；推荐方案下预期零改动，仅做时序核对）。
- 共享几何/门禁：`packages/shared-types/src/world/clinic.ts`、`clinic-gate.ts`。
- 测试：bun test / vitest 风格，命令见文末；决策记录 `docs/adr/`。

## 推荐方案工作原理（高层）
1. 治疗到期后不再直接进入"康复完成"，而是先插入一段**出院阶段**：把康复者登记进 clinic 内部 `discharges` 表，走一条由几何派生的短航点路径（床尾/落点 → 走廊 → 西门门洞 → 站外铺装 `CLINIC_SPILL_POINT` 附近）。
2. 每 Tick 沿航点逐帧推进坐标并刷新 AOI/网格；每帧位移上限复用现有 tween 量级（远小于 60px），保证客户端看到的是连续走出而非跳变。
3. 真人：出院期间 `patientState` 保持 `Treating`，客户端 `patientLocked=true`，本地预测让位服务端，杜绝"服务端推、客户端拉"的坐标打架；走到站外后再调用 `grantImmunity` 发 `Shielded`，玩家恢复自由移动并领 15 秒护盾。
4. NPC：出院期间保持 `incapacitated=true` 且站姿/走姿，使 `brain.updateAgent` 首行直接 return，不会与服务端位移抢写；到站外后再走既有 `restoreNpc`（清状态 + `recovery.restore` 续接巡逻）。护士（ENTITY_ROLE_NURSE）**排除在出院之外**，继续走 `beginBack` 回站位常驻。
5. 打断与健壮性：`downPlayer` 再次命中、`onDisconnect` 掉线时，必须销毁对应 discharge 记录（与现有 `tweens.delete(playerId)` 同级处理），否则会出现"出院途中被打倒仍被继续推着走"。

## 关键时序决策（重点）
- 选择"出院完成再发 Shielded"，而非"先发 Shielded 再加新锁"：这样客户端零改动、协议零改动，代价仅是护盾/免疫起点与康复播报推迟约 1~2 秒（出院时长）。该推迟在 ADR 中显式记录为新口径。
- 现有测试 `clinic.test.ts` 中"Shielded 时 `isInClinicInterior()===true`"、"康复瞬间人在床尾"的断言需要随之更新为"出院瞬间仍在站内、Shielded 时已在站外"，这是预期变更，不是回归。
- `recovery.restore` 的调用时机从"治疗结束瞬间"后移到"出院到站外之后"；其接口与"只清状态不写坐标"的语义保持不变，`npc/director.test.ts` 中"restore 不写坐标"的断言仍然成立。

## 性能与可靠性
- 出院表规模等于同时在院的康复者数量（个位到小几十），每 Tick 遍历一次，O(n)；航点数量固定（约 4 段），无重复寻路、无 N+1。
- 坐标写入沿用 `advanceTweens` 的既有模式：仅在位移有效时 `dirty=true`、`grid.update`；AOI 刷新按需触发，避免每帧全量广播。
- 采用**位移超时兜底**（复用 `NURSE_STUCK_MS` 同量级）：若出院路径卡死（碰撞/门洞堵塞），到期直接落到站外安全点并结束出院，保证任何异常都不会把人永久留在院内，也不会无限占用 discharge 记录。
- 不落盘、不改协议，`world-state.json` 与包结构零影响。

## 架构基线与改动层
- `BASELINE | sim/clinic（急救调度器） | expected: 康复收尾单一汇合点、只依赖几何与窄端口、不碰 npc 层 | observed: finishStay/restoreNpc/grantImmunity 是真人+NPC 的共同收尾，但无出院动作、发 Shielded 即解锁 | fit: partial | violations: 无新 X-*，缺"康复后离场"职责 | suggestion: 在该汇合处新增 discharge 阶段，作为最低可行改动层`
- `BASELINE | npc/director+NpcRestorePort | expected: 只清状态不写坐标、依赖 inward | observed: restore 已满足，仅调用时机需后移 | fit: align | suggestion: 保持接口不变，让 clinic 决定何时交还`
- `BASELINE | web/session.ts patientLocked | expected: 位置所有权单一、与服务端逐帧位移同权 | observed: Shielded 即解锁，是本次时序冲突根因 | fit: partial | suggestion: 不改代码，靠服务端调整发 Shielded 的时机消除冲突`
- 改动层结论：config → 产品 API → 工具 → 副作用 → **核心库（sim/clinic 汇合处）**；拒绝新增协议状态或跨端抽象。

interface DischargePoint { x: number; y: number }

/** 一次逐帧出院；登记在 sim/clinic 内部 Map<playerId, Discharge> */
interface Discharge {
  playerId: number;
  path: DischargePoint[];
  index: number;
  isNpc: boolean;
