## 产品概述
园区游戏内存在一批「看起来是真数据、实际是凭空编造」的内容：工号、部门、班次由昵称哈希随意派生；工牌上的条码、二维码、金色芯片与 `NIOMA HR · VERIFIED` 印章伪装成可验证凭证；出勤地点在接口失败时假装是「赛博空间 · 边缘节点」；公告栏常驻一条编造的「园区重装修完成」；黄历的宜忌、鸡汤与连休天数由日期哈希抽取或直接写死；木鱼敲击飘出「放假进度 +1s」等假进度话术。本次要把这些无来源内容清掉，只保留能对得上真实数据与真实状态的部分。

## 核心功能
- 工牌与考勤档案：移除工号、部门、班次三项编造身份；保留职级称谓、首次入职、出勤地点、园区区域、今日工时、今日如厕占比、行为统计、同屏劳模榜名次、点赞、成就。
- 证件页：移除条码、伪二维码、金色芯片、`VERIFIED` 认证字样与「系统自动签发、无需主管签字」说明；盖章区只保留由真实工时、步数、摸鱼、名次派生的称号标签。
- 分享卡：移除条码、`VERIFIED` 字样与随机职场金句；保留真实头像、昵称、职级、地点、今日工时、如厕、名次与统计。
- 出勤地点：查不到归属地时明确显示「未上报」，不再显示编造的地名；同一会话仍只查询一次。
- 园区公告栏：移除写死的装修通知，只保留真实的微信群二维码区块。
- 放假告示板：移除「宜 / 忌」两组抽签与六句鸡汤，移除节日卡上的「连休 N 天」，保留本周下班倒计时、本周工时进度条、节日倒计时与木鱼功德计数。
- 赛博木鱼：飘字只保留「功德 +1」，其余假进度话术删除。
- 欢迎横幅：移除写死的「shift 03」班次字样。
- 视觉结果：工牌从「像证件套件」变为「一张干净的信息卡」，卡片更短、层级更清晰，不再有伪装成可扫描凭证的图案；告示板从三块便签变成两块，留白更整齐。

## 保持不变
- 选园页的在线人数放大展示逻辑。
- 服务端 NPC 的一切（随机姓名、状态、籍贯、合成考勤、默认数量）。
- F2 代码工位（假仓库源码、终端日志、git 状态）。
- 首页营销站文案与数字。
- 首次进园的随机昵称（生成的是会落本地存档的真实昵称）。

## 技术栈
沿用现状，不新增依赖：Next.js 15 App Router + React 19 + TypeScript（strict）+ Tailwind v4；纯前端展示层剥离，无协议改动、无服务端 Tick 改动、无新增持久化。

## 实现策略
1. **单一展示模型收口**：`BadgeArchive` 仍是唯一展示模型（`apps/web/lib/game/archive.ts`）。所有删除都从「模型字段 → 组件」正向清理，不在组件里做假数据兜底。
2. **只做减法，不做兼容层**：工号 / 部门 / 班次是纯派生值、无协议字段、无落盘，直接删除函数与字段即可；同步删掉对应单测断言，避免 `pnpm typecheck` 断裂。
3. **伪造凭证整体移除**：`badge-art.ts` 与 `BadgeArt.tsx` 两个文件直接删除（`barcodeBars` / `qrCells` / `Barcode` / `FakeQr` / `Chip` 无其他引用）；`StampSeal` 降级为纯文字标签，保留真实派生的 `getStampTitle()` 结果。
4. **分享卡去凭证化**：`ShareCardData` 去掉 `employeeNo` / `department` / `shift` / `quote`；`drawBarcode`、`drawQuote` 删除，卡面留白用现有分隔线与详情区自然填充；文件名与水印改用昵称。
5. **地点改为诚实空值哨兵**：`GeoInfo` 允许 `region` / `city` 为空串表示「未上报」。`/api/geo` 在解析失败或内网 IP 时返回空串对象，客户端 `sanitizeGeo` 接受空串（保证 sessionStorage 命中、每会话仍只请求一次，避免反复打外部 IP 服务），UI 统一渲染「未上报」。
6. **黄历只留时钟真值**：删除 `ALMANAC_GOOD` / `ALMANAC_BAD` / `ALMANAC_MOTTOS` / `pickTwo` / `dailyAlmanac` / `Almanac` / `djb2`，删除 `restDays` 字段与 `holidayRestLabel`；保留 `weekendCountdown` / `weekProgress` / `upcomingHolidays` / `LUNAR_TABLE`（农历公历对照是真实数据，表外已显示「待更新」）。

## 性能与可靠性
- 工牌每次推送（2Hz）与 2 秒轮询都会重建 `BadgeArchive`；本次只删除 `djb2` 哈希与 LCG 条码生成，属净减法，无新增计算。
- `dailyAlmanac` 原在面板打开时计算一次，删除后减少一次哈希与两次取模。
- 地点查询保持「每会话一次」语义不变：空哨兵写入 sessionStorage 后 `readCachedGeo()` 仍命中，不会退化成每次挂载都请求。
- 无协议、无落盘、无服务端状态变更，回滚成本低（纯前端 + 一个 Route Handler 返回值语义）。

## 架构影响
链路不变：`CareerSummary` / 本地 store → `buildSelfArchive` / `buildRemoteArchive` → `BadgeArchive` → `IdentityPanel` / `BadgeArchiveDialog` / `BadgeCard` / `toShareCardData`。只是模型瘦身，组件仍只读 `BadgeArchive`，不新增抽象。

## 执行注意
- 删除导出符号前用 `lsp-code-analysis` 做一次引用核查（`employeeNo`、`departmentOf`、`shiftOf`、`barcodeBars`、`qrCells`、`dailyAlmanac`、`holidayRestLabel`），确保无遗漏调用点。
- `BadgeArchiveDialog` 用 `archive.employeeNo` 作为 effect 依赖与分享参数，改字段时必须同时改依赖数组，否则分享卡拿到 `undefined`。
- 组件里不要用 `0` 或占位假地名冒充缺失数据：地点为空一律「未上报」，与既有 `hasCareer === false` 的口径一致。
- 本次不跑测试、不做额外验证（遵循用户长期偏好）；也不执行 git 提交，因此不追加 `apps/web/data/release-notes.json` 条目。
- 不改动 `park-display.ts`、`apps/game-server/src/npc/**`、`code-studio.ts`、`components/site/**`。
