## 用户需求
把页面里和「赌」相关的描述整体换成合法、中性的说法，覆盖骰子馆与其余押注玩法，视觉布局与玩法数值不变。

## 产品概述
园区游乐大街的「摸鱼大赌场」更名为「摸鱼骰子馆」，全部玩家可见文案按统一口径去赌化：押注/下注改为投入/投选，彩池改为奖池，注额改为投入额，抽水改为服务费，封盘改为截止，观战押注改为观战投选。招牌、门牌、导览、小地图、HUD 区域名、到达横幅、交互提示、键帽按钮、面板与结算浮层读起来像园区里的娱乐小游戏，不再出现赌场、押注、彩池、抽水等字样。

## 核心功能
- 场所更名：所有出现「摸鱼大赌场」的入口（招牌、门牌、导览列表、小地图地标、HUD 区域标签、到达横幅）统一显示「摸鱼骰子馆」，五字等长，牌面与布局不变。
- 骰子馆面板：阶段标签改为等待开局/投选中/摇骰中/结算，奖池、服务费比例、投入额输入框、本局已投入、已截止等文案全部中性化；档位「豹子」改为「同点」。
- 观战投选：八角笼面板标题改为观战投选，红池/蓝池改为红方池/蓝方池，按钮与阶段原因（比赛进行中、等下一场、本场已投入）同步改写。
- 1v1 挑战：投入、全部投入、余额不足、邀请提示与结算浮层的投入金额文案统一；玩法名「街头摇骰子」去掉街头赌摊联想。
- 交互与提示：上下文提示（HINT、键帽按钮、触屏提示三处一致）、交互动作名（投入/投选）与拒绝原因（投入额不合法）同步。
- 版本工报：清理历史条目里的赌场/赌桌/赌局/押注字样并保持原意，同时追加一条本次改动记录。
- 边界：仅改玩家可见字符串；协议枚举、代码标识符、落盘账本、坐标与碰撞、灯光与场景绘制零改动。


## 技术栈
沿用现有 pnpm monorepo：TypeScript + Next.js（apps/web）、共享包 @niuma/shared-types、bun test（`bun test lib`）、`tsc --noEmit`、`node scripts/check-release-notes.mjs`。不引入新依赖。

## 实施策略
以「单一事实源分层替换」推进，先改数据源头再改消费端，避免遗漏：

1. 场所名唯一源头在 `packages/shared-types/src/world/districts.ts`（`VENUES` 与 `NAV_SOURCES` 两处），改一处会经 `regionAt()`（layout.ts）、`NAV_TARGETS`、门牌、小地图、HUD 区域名与到达横幅传导；`layout.ts` 的 `buildings` 表（按名反查房间）与 `dice-hall-view.ts` 招牌 Pixi Text 是另外两个手写点，必须同步。
2. 文案集中在 `apps/web/lib/game/hint-copy.ts` 的 `HINT` / `HINT_BUTTONS` / `TOUCH_HINTS` 三张表；三者以 `HINT.*` 值作键，必须一次性同步，否则触屏说法与键帽映射漂移。
3. 面板文案在 `DiceHallDialog`、`ArenaBetDialog`、`ChallengeDialog`、`MatchOverlay`、`InviteToast`，交互动作名与拒绝原因在 `GameViewport` 的映射表，档位名在 `dice-hall.ts` 的 `DICE_SIDE_NAME`，玩法名在 `challenge.ts` 的 `P2P_GAME_NAME`。
4. 只改字符串字面量与键，不改 `DICE_SIDE`、`INTERACT_ACTION.DiceBet`、`P2P_MAX_WAGER`、协议字段与 `world-state.json` 落盘结构。

### 关键决策与理由
- 保留标识符与协议：改名若触及枚举会触发服务端/协议/落盘迁移，收益为零、风险极高，故限定在展示层字符串。
- 「豹子」改「同点」：该词属骰宝术语，等长两字替换，不破坏牌面与结算单排版。
- 「大 / 小」保留：本身中性，改为「大数/小数」只在 380px 面板里增加宽度，无合规收益。
- 长度受限容器用短同义：`持仓`类按钮「全押」→「全部」；骰子面板「公共池」若加「奖」后换行则用「奖池」；「0% 抽水 · 押中档位按注额分走全池」改写为「0% 服务费 · 猜中按投入额分走奖池」，不超原串长度。
- 历史工报按用户显式口径清理（与 AGENTS.md「不改历史记录」惯例不同），在 ADR 中记录为一次性例外并写明理由。

## 性能与可靠性
纯字符串常量替换，零运行时开销、零包体增长。新增的文案守护测试是构建期 O(n) 全量扫描（n 为数百条文案 + 工报条目），不进入运行时；正则用「赌(场|桌|局|博)」而非裸「赌」，避免「赌气」这类正常词误报。迭代（如 `Record<VariantId,string>`）在提交前跑 `pnpm typecheck` 与 `pnpm test` 兜底，协议与落盘零改动使 blast radius 限定在展示层。

## 执行要点
- 三处提示表以 `HINT.*` 作计算键：改值即全链路生效，禁止只改其中一处或另写字符串。
- 面板容器宽度固定：替换后不得比原串更长；「本场已押注」→「本场已投入」（等长），「押 {n} 币 · 红方」→「投入 {n} 币 · 红方」。
- `arrival-copy.ts` 的键若与场所名不一致不会报错，只会静默回落到大区副标题（「摸鱼合法区，输了算工伤」），改完必须跑测试确认。
- 工报 id 必须 `2026-11-16-11`（当日已有 -10 在最前），改完跑 `pnpm changelog:check` 校验顺序/长度/敏感词。
- 不触碰协议、落盘、坐标、碰撞、灯光与 Pixi 绘制逻辑；代码标识符 `diceHall` / `DICE_SIDE` 保持原样。
- 提交前依次执行 `pnpm typecheck`、`pnpm test`、`pnpm changelog:check`，并全仓 grep `赌场|赌桌|赌局|押注|下注|彩池|注额|抽水|封盘|豹子` 确认玩家可见处零残留（ADR/历史工报说明性文字除外）。
