## 需求概述
调整园区地图的交互与氛围内容：让地图上所有椅子（含长椅）均可被角色坐下，且只保留兔子作为地面小动物，并显著提升兔子的可爱度与坐姿表现。

## 核心功能
- **所有椅子可入座**：工位椅、会议椅、影厅座椅、木凳、石鼓凳、沙发、马桶等现有座位保持可用；地图上 16 张长椅（中央广场 4、道路休息点 7、南侧庭院 3、游乐园 2）全部接入座位系统，靠近按 Z 即可坐下。
- **交互与起身一致**：保留现有 Z 键入座方式，不做自动坐下；入座后移动即起身，提示文案、动作条、服务端占座与旧存档 seatId 均保持兼容。
- **长椅视觉与碰撞不变**：长椅仍由现有道具管线绘制，保留 40×16 碰撞；座位系统只提供坐点，不重复绘制第二张长椅。
- **地面动物仅保留兔子**：移除猫、狗及其生境权重，任何种子下 72 只地面小动物全部为兔子；蝴蝶与湖中小鱼数量和行为保持不变。
- **兔子外形重绘**：长耳与粉色耳内、圆头大眼带高光、小粉鼻与 W 嘴、圆润身体、绒球尾、折叠后腿与并拢前爪、胸腹高光；正/侧/背三视图与三套配色保持一致。
- **兔子坐姿与待机动画**：新增坐姿帧，待机时呈现坐姿并穿插抖耳、眨眼、低头啃草等小动作；行走与逃跑仍使用站立行走帧。
- **全局一致性**：所有长椅、所有兔子在任意地图区域、任意随机种子下表现一致。


## 技术栈
- 现有 pnpm + Turbo monorepo：
  - `packages/shared-types`：布局、座位、碰撞数据（TypeScript + Vitest）
  - `apps/web`：Pixi.js 渲染与 Pixi 图集烘焙、Bun 测试
  - `apps/game-server`：权威座位占用与 20Hz Tick
- 不引入新依赖、不新增协议字段；沿用 ADR-0020 / 0031 / 0032 / 0042 的既有契约。

## 实现策略

### 1. 长椅接入座位系统
- 在 `packages/shared-types/src/world/campus.ts`：
  - `SeatKind` 追加 `'bench'`；
  - `seatPose` 保持「仅 bed 躺、其余坐」，bench 自动落坐姿；
  - 新增并导出 `BENCH_SEAT_OFFSET = 12`（坐点在长椅底座前方 12px）；
  - `PROP_FOOTPRINT.bench` 保持 40×16 不变，碰撞仍由 `propSolid` 生成。
- 在 `layout.ts`：
  - 保持 `SEAT_DRAFTS` 原有顺序，将 `SEATS` 的实际生成移到 `PROPS` 之后；
  - 从 `PROPS.filter(kind === 'bench')` 派生 16 个 bench 座位，追加到座位表末尾：
    `{ x: prop.x, y: prop.y + BENCH_SEAT_OFFSET, facing: Direction.Down, kind: 'bench', desk: -1 }`；
  - 追加位置保证既有工位/床/马桶/影厅座位 id 不漂移，兼容 `niuma:session:v1`。
- 在 `apps/web/lib/game/seat-art.ts`：
  - `OTHER_SEATS` 增加 `bench: { w: 40, h: 18, sink: 0 }`；
  - `OTHER_CONTACT` 增加 `bench: -22`（长椅座面顶在帧内 y=8，坐点在椅前 12px，故相对锚点 -22）；
  - `seatLift('bench', facing) = 21`，角色臀底落在长椅座面；
  - 保持现有 couch / cinema 分支不变。
- 在 `apps/web/lib/game/props.ts`：
  - 座位渲染循环开头 `if (seat.kind === 'bench') continue;`，长椅视觉继续由 `addProp` 的道具管线绘制，避免重复精灵；
  - 长椅碰撞、深度、裁剪与遮挡逻辑完全沿用现有 props 实现。
- 在 `apps/web/lib/game/badge.ts`：
  - `seatLabel` 增加 `bench -> '长椅'`，避免落到 `'马桶'` 分支。
- 服务端 `SeatRegistry`、`findNearestSeat`、`HINT.seat`、移动起身逻辑均无需改动：非 bed 座位会自动纳入 `sit`。

### 2. 兔子只保留一种物种
- `critter-spawn.ts`：
  - 删除 `pickSpecies`、`NEAR_FLOWER` / `NEAR_GROVE` / `NEAR_ROAD` 及配套距离函数；
  - `GroundSpawn` 去掉 `species`，只保留 `variant`；
  - 撒点逻辑、72 只人口、80px 间距、户外草地/碰撞约束不变；
  - 蝴蝶与小鱼撒点函数不改。
- `critter-motion.ts`：
  - 删除按 species 索引的 `WALK_SPEED` / `RUN_SPEED` / `SCARE_RADIUS` 数组，改为单组兔子常量（建议沿用 42 / 120 / 96）；
  - `GroundCritter` 去掉 `species`；
  - `createGroundCritter` 初始帧改为坐姿帧；
  - `animate` 的 idle 分支改为坐姿小动作序列（SIT_A ↔ SIT_B，偶尔 GRAZE），walk / flee 仍用 WALK_A / WALK_B。
- `critters.ts`：
  - `groundBase` 改为 `variant * GROUND_VIEWS * GROUND_FRAMES`；
  - `groundCell` 调用改为 `(variant, view, frame)`。
- `critter-art.ts`：
  - `SPECIES = 1`，`COATS` / `SIDE` / `FRONT` 只保留兔子；
  - 图集改为 1 物种 × 3 配色 × 3 视图 × 5 帧 = 45 格 + 蝴蝶 6 + 小鱼 6 = 57 格；`CRITTER_ROWS` 从 10 改为 5，`CRITTER_COLUMNS` 保持 12（60 格中留 3 格空位）；
  - 保留单图集、一次 `generateTexture`、32px 格、`CRITTER_FEET = 29` 与运行期零分配的既有约束。

### 3. 兔子美术与坐姿
- 帧定义：`FRAME_SIT_A = 0`、`FRAME_SIT_B = 1`、`FRAME_GRAZE = 2`、`FRAME_WALK_A = 3`、`FRAME_WALK_B = 4`，`GROUND_FRAMES = 5`。
- 侧视：
  - 身体为圆润蹲坐椭圆，臀部/后腿折叠成贴地大鼓包；前爪并拢直立撑在胸前；
  - 头部略大、长耳两根（前后错位、粉色耳内、1px 描边），眼睛带白色高光，小粉鼻与 W 嘴，脸颊胡须点；
  - 绒球尾挂在臀部上缘；SIT_A 耳朵直立，SIT_B 一只耳朵微斜并眨眼，GRAZE 头部下沉、耳朵后贴。
- 正视 / 背视：
  - 梨形身体、底部加宽，两侧露出不落地的大腿鼓包；两条前爪并拢；
  - 正面大眼 + 鼻嘴 + 胡须，背面只留耳背、背线与绒球尾；
  - 行走帧前后爪交替，身体 1px 起伏。
- 采用「先整体描边、再整体填充、最后整体压暗边」的并集画法，避免多块圆形重叠处出现内部暗边；所有笔画严格落在 32px 格内，脚底线保持 y=29。

### 4. 性能与一致性
- 图集从 12×10 缩为 12×5，纹理更小，仍为单张 TextureSource、一次烘焙，绘制批次不增加。
- 地面动物仍按视口裁剪，屏外不跑状态机；兔子坐姿只是帧号切换，不新增每帧分配。
- 长椅座位只增加 16 个静态座位锚点，服务端 `SeatRegistry` 数组仍为 `Uint16Array`，查询复杂度不变。
- 所有改动通过共享布局数据驱动，客户端、服务端、Worker 三端自动一致。

## 实施注意事项
- 编辑前重新读取目标文件：当前工作区有大量未提交改动（`props.ts` 已新增 cinema / couch 渲染），不要回退并发修改。
- 只改本次相关逻辑，不顺手修基线中与任务无关的类型/测试问题；若 typecheck 暴露既有错误，记录并绕过。
- 长椅坐点固定在椅前 12px，保证 `isBlocked` 不压长椅自身 40×16 碰撞；所有长椅坐点都需通过 `isOnLand`、`isWaterAt` 与两两间距 > 40 的既有测试。
- 兔子图集格数变化会改 `CRITTER_ROWS`，需同步检查 `bakeCritterArt` 的切片数量与所有 `groundCell` 调用；不要保留 species 维度的乘数。
- 帧循环保持零分配：坐姿动画只改 `frame` 标量，不新建对象/闭包。
- 调试开关 `?critters=debug` 仍应打印 72 只地面动物与图集构造耗时，便于验收。
- 不修改历史 ADR；如需记录本轮关键决策，可在 `docs/adr/` 按现有格式新增一条，但不作为功能验收前置条件。
- 用户未要求提交，不要主动 commit；提交前才需要追加 `apps/web/data/release-notes.json` 并运行 `pnpm changelog:check`。

  - Expected outcome: 输出一份精确的现状清单，标明需要改动的行号/符号与不可回退的并发改动，供后续编码直接使用。
