## 产品概述
牛马园是一块手写坐标的像素风多人园区，玩家在其中走动、入座、被保安押送、逛游乐园与三处景观湖。本轮把整张地图收紧：陆地整体缩小约 20%，卫生间与小黑屋单独改小，游乐园、三湖、摸鱼亭等外围场所向中心靠拢，减少「走很久只有草」的走廊，让一屏之内能读到更多内容。

## 核心功能
- **地图收紧**：陆地由 3805×4212 收到约 3040×3368（x 2560–5600 / y 2412–5780）。中央广场、出生点、四角院落、三间大房（工作区 / 会议室 / 宿舍区）与欢迎地标保持原位；游乐园、三湖、摸鱼亭、南庭院、影音室 / 小黑屋整体向心收拢。
- **卫生间改小**：由 460×360 收到 340×300，贴东南角；内部改为男 2 格 / 中央洗手池 / 女 2 格，马桶由 6 个变 4 个；门洞、门前铺装、洗手池、logo、宫灯与导览到达点一起挪。视觉上更像一间紧凑的公共卫生间，而不是半座空房。
- **小黑屋改小**：由 460×320 收到 320×240，西墙与门洞仍压在 y=4950 这条支路上，门前铺装与押送路线不变；三个并排反省位保留，只是彼此更紧凑。
- **外围场所内收**：游乐园搬到北门正对的空地，成为北向主路尽头的地标；摸鱼湖、沉思浅塘、涟漪湖只平移不改形，摸鱼亭跟着湖岸走；湖岸长椅、路灯、野餐桌、树丛与花海重新布点，填掉新边界附近的空草地。
- **配套同步**：13 个导览目标、区域名、碰撞、小地图、押送寻路、节日装饰与室内陈设全部跟随新坐标；布局测试、README 地图段落与 ADR 一并更新。

视觉结果是：从广场走到任一场所的步数明显变短，地图边缘不再有大片纯草；北门一抬头就是游乐园，三湖像内嵌在院落周围；卫生间与小黑屋体量更小、更符合实际使用人数。

## 技术选型
- 仓库：pnpm 10 + turbo 的 TypeScript monorepo（Node ≥20.11），服务端 Bun，Web 端 Pixi。
- 单一事实源：`packages/shared-types/src/world/*`（布局、房间、游乐园、碰撞），被 `apps/game-server`（碰撞 / 押送 / NPC 采样）、`apps/web`（地形、渲染、小地图、室内陈设、节日装饰）与三端测试共用。
- 测试：`packages/shared-types` 用 vitest，`apps/web` / `apps/game-server` 用 bun:test。
- 坐标纪律沿用 ADR-0028：坐标手写整数，禁止 `Math.random / Math.sin / Math.cos`，**不做运行期缩放**；世界画布仍为 8192，避免扩散到协议与网络层。

## 实施方案

### 总体策略
先在 `shared-types/world` 把「世界是什么」改对，再让渲染层与服务端从同一份常量派生；只改数据与两处派生（游乐园门的方向、卫生间装饰偏移），不新增模块、不改协议。中心区（广场、四角院落、欢迎地标、竹林、太湖石、供案、茶台）保持原值以控制爆炸半径。

### 关键决策与取舍
| 决策 | 收益 | 代价 / 约束 |
|---|---|---|
| 岛界 3040×3368，画布仍 8192 | 面积 −36%、步行时间变短；协议与网络层零改动 | 布局常量与测试大改，双端必须同版本发布 |
| 游乐园北移 | 北门正对有空地、能直接接北向主路；南庭院保持居中 | 东 / 北门语义要重排：改为南门 + 东门，`parkFencePosts` 需要按边开缺口 |
| 三湖只平移不改形 | 保住每湖 6 条鱼的离岸 / 间距采样与湖岸观感 | 湖岸道具、导览点、路径端点要重排 |
| 卫生间 4 坑位 | 宽度能真正从 460 降到 340 | 少 2 个马桶，后续座位 id 整体前移 2（本地快照按新表校验） |
| 小黑屋 320×240 | 门线、铺装、押送 BFS 与门外点全部不动 | 「与影厅同尺寸」断言改成「同北线、东侧、更小」 |
| 不做运行期缩放入口 | 双端逐像素一致、测试可断言 | 所有坐标手写，改动面大但可机械校验 |

### 性能与可靠性
- 押送 BFS 网格按岛界派生：24px 网格从约 2.8 万格降到约 1.8 万格（−36%），启动预热更快；运行期碰撞空间哈希规模不变。
- 布局密度测试的 64px 采样点减少约 36%，测试更快；渲染端只做视口裁剪，不增加每帧开销。
- 所有共享常量派生关系不变：`WORLD_BOUNDS / isOnLand / isBlocked / 小地图 / 相机夹取 / NPC 采样` 自动跟随；服务端 NPC 与押送继续读 `JAIL_ANCHOR / JAIL_DOOR_PAVING`，无需改逻辑。
- 已知风险：`niuma:session:v1` 里存的 seatId 会因马桶减少而错位；`resolveSpawn` 已对「座位不存在 / 被占」回退，但可能落到另一张合法座位，需在 ADR 记录为可接受代价。
- 测试脆弱点：`theater-park-layout.test.ts` 用 `paths[paths.length - 1]` 取影厅支路，改为按终点查找，避免路径顺序变化造成假失败。

## 架构设计
数据流保持单向：`shared-types/world`（唯一坐标真相）→ 服务端 sim（碰撞 / 押送 / NPC）与 Web（地形 / 渲染 / 小地图 / 室内陈设）→ 测试断言。本次只在数据层改常量，并新增一个「门在哪条边」的字段让栅栏缺口按边生成；不引入第二套坐标、不做运行期偏移计算。

## 实施注意事项
- 先改 `world` 再跑 `pnpm --filter @niuma/shared-types test`，按「岛界 → 场所矩形 → 道路 → 道具/植被 → 导览/区域 → 房间」顺序推进，避免一边改坐标一边改测试。
- 三湖只做平移，不改多边形点数与形状，保证每湖 6 条鱼的离岸 60 / 间距 100 采样仍然成立。
- 树丛中心与花海必须重新手写在岛内，**不要用放宽密度阈值来过关**；树间隙 ≥80、树丛中心间距 ≥220、树 ≥90、散树 ≥30、树丛 ≥12、花海 ≥6。
- 路径数组保持 `paths[0]` 为北向主路（现有测试依赖），并在改动后显式检查每条中心线在陆地、不落水、不穿四间房。
- 游乐园所有内部绝对坐标按 `(+1336,−2960)` 机械平移，平移后逐项复核：滑道折线在垫内、两个门可通行、大件两两 ≥20px、器械底座不挡门与落点。
- 卫生间装饰偏移不要留 460 宽的硬编码；`interior-art.ts` 的污渍 / 地漏 / 提示牌 / 干手器 / 绿萝 / 香薰至少按新房间宽度夹取，防止画到墙外。
- 无运行期日志需求；这是静态布局改动，重点是可复现的坐标与测试，不引入采样或缓存。
- 共享常量双端共用，服务端与 Web 必须同版本发布；不改协议、不改存档格式。
