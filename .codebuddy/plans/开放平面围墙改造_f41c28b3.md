## 用户需求
把地图上所有场所的「围墙」拆掉，只保留少数必须封闭的场所；围墙拆除后，场所边界改用地面材质与地面色带表达，不再用墙体围合。

## 范围与结论
**保留围墙（视觉 + 碰撞都不动）**
- 小黑屋（JAIL）
- 医务室 / 护士急救站（CLINIC 围挡）
- 卫生间（含男女分区隔墙、四片坑位隔断）
- 别墅小院（院墙 + 院门锁）
- 擂台八角笼（围栏）
- 牛马公寓楼体（建筑实体，不属于围墙）

**拆除围墙（视觉与碰撞一起拆，玩家可直接走进去）**
- 工作区：北 / 西楼体外墙
- 会议室：四面墙与南墙门洞
- 发泄区：四面墙与北墙门洞
- 宿舍区：四面墙与北墙门洞
- 家庭影音室：四面墙与东墙门洞
- 企业楼走廊西端封口墙
- 公园：外围一圈装饰矮栅栏

## 视觉预期
- 木地板、瓷砖、地毯、水泥、橡胶垫的色块直接接到草地与铺装，场所之间靠地面材质与 2–4px 地面收边区分。
- 地图不再是一格格被灰墙框住的房间，企业区、生活区、游乐区连成一片可自由穿行的开放园区。
- 仅小黑屋、卫生间、医务室、别墅、擂台、公寓仍保留围合感，形成明确的反差。
- 不新增花箱、绿篱、灯位与动效；室内原有桌椅、床位、屏幕、陈设全部保留，位置不变。

## 约束
- 房间矩形、桌椅座位、导览到达点、服务端协议、NPC 路径坐标一律不动，只删墙与随之失效的渲染反查。
- 拆墙后不允许出现「看不见的空气墙」。

## 技术栈
- pnpm workspace monorepo：`packages/shared-types`（TypeScript + vitest）、`apps/web`（PixiJS 渲染 + bun test）、`apps/game-server`（复用同一份世界几何）。
- 世界几何与碰撞的唯一事实源是 `WORLD_LAYOUT.solids`：客户端预测、服务端裁决、寻路网格、地面绘制（`props.ts` 的 `fillSolidFlat`）全部读它。

## 实现方案
**核心策略：在共享布局层删墙，一次改动同时作用于碰撞与渲染。**
`WORLD_LAYOUT.solids` 是唯一入口，删除墙体矩形后，客户端与服务端碰撞、寻路、地面墙带绘制同步消失，不会出现「视觉拆了、碰撞还在」。

数据流：

```
packages/shared-types/world/campus.ts  CAMPUS_SOLIDS ─┐
packages/shared-types/world/park.ts    parkFencePosts ─┴→ WORLD_LAYOUT.solids
        ├→ 客户端 / 服务端碰撞与寻路
        ├→ props.ts fillSolidFlat 地面墙带
        └→ venue-art.ts / interior-art.ts 的墙体反查（需同步清理）
```

**关键决策**
1. 只改 `campus.ts` 的 `CAMPUS_SOLIDS` 与 `park.ts` 的装饰栅栏；`clinic.ts`、`villas.ts`、`ring.ts`、`apartment.ts` 的墙体定义完全不动，别墅门锁、擂台报名、救护车通道、小黑屋押送继续读原碰撞。
2. 删除门洞后，`paintVentThreshold`（靠北墙缺口反查）与其依赖的 `northDoorGap` 一并删除；发泄室改用现有 `buildVentAlert` 的四沿色带表达边界。
3. `depthFacades` 的 `FACADE_PROFILES` 从 6 项收敛到「卫生间、小黑屋」；其余条目即使自动跳过也应删除，避免留下会误导后来者的死配置。
4. `interior-art.roomOf` 的 10px 兜底**保持不变**：无墙时它正好成为地面收边，有墙的卫生间 / 小黑屋行为完全不变，避免把装饰推到贴边。
5. 不新增任何渲染对象、光源或每帧分配；solids 数量减少约 20 余个矩形，碰撞与寻路遍历负担只降不升。

**性能与可靠性**
- 碰撞判定为线性遍历，删墙后每帧比较次数下降，无新增热点。
- 无协议变更、无落盘字段变更、无坐标变更，回滚只需还原 `CAMPUS_SOLIDS` 与 `parkFencePosts` 两处，不存在数据迁移。

## 实施注意
- `campus.ts:836-849` 的注释与数组已不一致（注释写「工作区不加墙」，数组仍含 `...workroomSolids`），本次一并修正为「只有卫生间与小黑屋有墙」。
- `MEETING_DOOR` / `VENT_DOOR` / `LOUNGE_DOOR` 删除后，`venue-art.paintCompanyCorridor` 里两个 `gateChevron` 的硬编码 x 会失去来源：直接删除这两枚箭头（房间已全开，无需指向门洞），禁止保留重复魔法数字与过期注释。
- `buildVentAlert` 当前从 `y + 10` 起画（原墙内沿），无墙后要贴到 `VENT_ROOM` 外沿，否则房间顶部会留 10px 空档。
- `paintCompanyCorridor` 的 `x0 = corridor.x + 10` 是为让开西端封头墙，改为 `corridor.x`，走廊地面铺满整条。
- 宿舍区 `decorateLounge` 的北窗、壁灯、暖气片按「贴地边缘装饰」复核一次：只做必要位移或删除，不加新陈设、不加灯。
- 公园只删装饰栅栏；`PARK_SOUTH_GATE.gap` / `PARK_EAST_GATE.gap` 作为门口宽度语义保留，铺装与导览不动。
- `layout.ts` 的 `DOOR_PLAQUES` 只同步失效注释（门洞已不存在），坐标一律不动。
- 不新增日志；版本工报只写玩家可感知结果，不写文件名、内部实现与坐标。

## Agent Extensions
### Skill
- **pixel-venue-polish**
  - Purpose: 按项目像素场所规范验收拆墙后的地面材质、边界表达与分层，确保不加新装饰、不加光源、不引入每帧分配。
  - Expected outcome: 五个开放场所仅靠地面色块即可读懂范围，`?venue=0` / `?light=0` 两个灰度视角均无漏光、黑块或悬空装饰。
- **principal-software-architect**
  - Purpose: 为 ADR-0103 提供轻量决策记录结构：约束、非目标、反向成本与 30 天回滚路径。
  - Expected outcome: 一份可追溯的开放平面决策记录，说明保留清单为何是这六处，以及回滚只需还原两处 solids 数组。

### SubAgent
- **code-explorer**
  - Purpose: 全库排查仍假设「场所有墙」的墙体反查与门洞偏移（`kind === 'wall'`、`+ 10` 墙厚让位、`northDoorGap` 一类）。
  - Expected outcome: 输出一份残留引用清单并逐条确认已修复或确认为无需改动，避免拆墙后留下悬空装饰或错位色带。
