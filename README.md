# 牛马 NIOMA

一座永不下班的 2D 像素多人在线办公园区。选一头牛或一匹马，走进工位、打字聊天、坐下躺平。

**核心约束：零持久化。** 世界只活在游戏进程内存里，昵称与外观只写进浏览器 `sessionStorage`。关掉标签页，你就自由了。

## 技术栈

| 层 | 选型 |
|---|---|
| Monorepo | pnpm 10 + Turborepo 2 + TypeScript 5（strict） |
| Web | Next.js 15 App Router · React 19 · Tailwind CSS v4 · Zustand 5 |
| 渲染 | PixiJS 8（WebGPU 优先，自动回落 WebGL2）· bitecs 0.4（SoA + TypedArray） |
| 美术 | 程序化生成 64×64 分层像素图集，16 列帧预算（走 6 拍 / 待机呼吸 + 眨眼 / 坐躺 / 叫唤） |
| 服务 | Bun `Bun.serve` WebSocket（内部即 uWebSockets）· 20Hz 固定 Tick |
| 协议 | 手写二进制帧，移动包固定 **8 字节**；无 JSON、无轮询 |
| 数据 | 进程内存（唯一真相）+ 浏览器会话缓存；无数据库、无 ORM |

## 快速开始

```bash
pnpm install
pnpm dev
```

- 园区首页 <http://localhost:3000>
- 捏人工作台 <http://localhost:3000/create>
- 进入园区 <http://localhost:3000/play>
- 服务器状态 <http://localhost:3001/health>

需要 Node ≥ 20 与 pnpm 10。Bun 作为工作区开发依赖安装（`node_modules/.bin/bun`），无需全局安装。

想直接进服，可以用深链：`/play?name=夜班实习生&species=horse`。

## 角色与动画

角色是 `packages/pixel-assets` 里的程序化像素画，不依赖任何外部美术工具：

- **网格与帧预算**在 `src/layout.ts` 一处定义：64×64 帧、每方向 16 列，idle 0-2、walk 3-8（六拍 80ms）、
  sit 9-10、lie 11-12、emote 13-15。生成器按列作画，客户端按同一份布局切片与播放。
- **画法**是硬朗卡通：每个形体只有「本体 + 一档阴影」，阴影靠整块偏移而不是逐列扫描，
  描边统一 1px 并补对角针孔。牛与马共用 48 texel 的站立总高（差 1.3），
  靠躯干 23 : 19、腿 17.5 : 20、颈 8.2 : 10.5、吻 10 : 6.8 分开剪影（见 ADR-0010）。
- **分层染色**：图集导出成 `tail / body / pattern / bodyLight / hoof / eyes / eyeLight / extra / snout`
  九张灰度图，运行时逐层 `Sprite.tint`。`bodyLight` / `eyeLight` 是纯白层，靠把本体色往白里混
  得到提亮——`tint` 是乘法，没有独立图层就画不出月牙高光与眼神光（见 ADR-0006）。
  配件（帽子 / 眼镜 / 颈饰 / 发型）同样是灰度小图，各自跟随所属属性的色槽染色（见 ADR-0011）。
- **播放**：`apps/web/lib/game/clip.ts` 把 manifest 的逐帧时长预编译成时间轴，相位按 `netId`
  哈希错开，所以同一屏里的人不会同时抬腿。
- **纸娃娃顺序**收敛在 `apps/web/lib/game/pony.ts` 的 `PONY_LAYER_ORDER` 一处：
  tail → body → pattern → bodyLight → hairstyle → headwear → hoof → extra → eyes → eyeLight
  → eyewear → snout → neckwear。鬃毛排在眼睛之前是**刻意**的：让鬃毛压住眼睛会吃掉表情，
  读脸优先级高于「鬃毛在最上层」（ADR-0013）。
- **微动效**是纯函数 `pony-motion.ts`：`ponyMotion(pose, elapsedMs, netId)` 给出
  `{ bobTexels: 0 | -1, shadow: 0 | 1 | 2, blinking }`。待机 3.4s 一个呼吸、行走 240ms
  一个起伏，**只抬高不下沉**（角色永远不会陷进地面）；阴影用三张预烘焙椭圆换纹理做
  squash & stretch，不做浮点缩放。眨眼每 35s（±5s 抖动）由客户端注入闭眼列——
  图集里那一列仍属于 idle，只是不再进循环（见 ADR-0013 第 9 条）。

改帧数只需动 `layout.ts` 再跑 `pnpm assets`：布局会重新写到
`apps/web/lib/game/sprite-layout.generated.ts`，客户端与落地页的 CSS mask 都读它。

## 地图与地形

园区是一座手写海岛（`packages/shared-types/src/world/layout.ts`），服务端、客户端与小地图共用同一份坐标：

- 陆地收到内容包围盒外 50–80px，四周是深海；北、东、南中、西南各留一处海湾，切掉没有内容的空草地；
- 岛心是围栏圈起的办公广场，四个门洞各通一条土路；
- 东侧是「摸鱼湖」（沙滩 + 多边形水面），西侧是「周报河」（阶梯河段 + 木桥），三片「加班林」共约 500 棵树；
- 海岸线就是地图边界：围栏、树干、花箱、湖面、河面与海都挡人，门洞与桥面可通行；贴着栏板或海岸走会滑行，不会卡死；
- 尺度以角色为准：站立 48 texel，树高是它的 2.25 倍、围栏齐胸、地砖边长为身高的 1/3。

碰撞由服务端权威结算：`applyMove` 限速截断后调用 `resolveMotion`，客户端用同一个函数做本地预测，
因此不会出现「先穿墙再被拉回」。`isBlocked` 先判 `isOnLand` 再查障碍，海即墙（ADR-0012）。
地形是静态内容，不进协议、不落库，改地图要双端一起发版。

渲染侧所有地形纹理都在 `renderer.init()` 内一次性生成（1:1 + nearest，ADR-0005）。
海面铺在世界外层，草地用海岸线多边形遮罩裁成岛，边缘依次是浅滩、沙滩与草地；
相机被夹在岛屿包围盒内，走到岸边也不会露出世界外的黑色。
小地图直接按世界→画布变换画布局，底色是海、岛形由同一份海岸线描出，视野 900px 内的人和地形同屏可见。

地面过渡不是贴图拼的（ADR-0013）：

- 土路、广场、林地都用**圆角轮廓 + 遮罩平铺**：`autotile.ts` 输出半径 16 的解析圆角轮廓
  （林地再叠一层平滑噪声外推成有机边界），`TilingSprite` 用这张轮廓做遮罩裁切，
  外侧沿轮廓画 2px 草缘与每 6px 一个的 1px 细草齿，内侧压 2px「本体色压暗 40%」的暗边。
  平铺相位按世界坐标对齐，四条路撞在路口时纹理不会各走各的。
- 草地上再叠一层**贴花**（`decals.ts`）：64px 栅格上按位置哈希以 12% 命中率撒三叶草、雏菊、
  草尖与小石粒，水面/广场/土路/桥面不生成。同一格永远是同一株，来回走不会换位置。
- 树拆成**树干 + 树冠两张同帧纹理**，与围栏、花箱、角色一起按脚底 y 排序。角色走到树后时，
  只有树冠淡到 0.85（树干保持不透明），离开即恢复；判定走一棵 128px 的树冠网格索引。
- 整张地图画完后，在 `app.stage` 上覆盖一层屏幕空间的 `multiply` 柔光：按本地时刻在
  清晨暖金、白日中性、黄昏暖橙、夜间冷蓝之间插值，30s 采样一次。

两个灰度开关：`?flat=1` 退回矩形平铺（方便定位圆角/草缘的观感回归），`?light=0` 关掉柔光层。

## 二进制协议

移动包固定 8 字节，小端：

```
[op 1B][entityId 2B][x 2B][y 2B][state 1B]
```

- 坐标：1/8 像素定点，u16 覆盖 8192×8192 世界
- state：`dir(2b) | pose(3b) | moving(1b)`
- 同步包：`[op][tick u32][count u16]` + 每个实体 7 字节
- 外观：32 字节定长（物种 1 + RGB565 十一色 22 + 部件 4 + 配件 4 + 保留 1），配件槽为 头饰 / 眼镜 / 颈饰 / 发型
- 排队：位次快照 16 字节（ticket u32 + 位次 / 队列长度 / 预计等待 / 容量 u16 + 主导维度 u8 + 水位千分比 u16），拒绝包 2 字节

客户端与服务端共用 `packages/shared-types/src/protocol.ts`，不允许各自实现一份。

## 性能

- AOI：512px 单元，900px 视野，跨格才重算订阅；广播量随视野人数增长，而非全图
- 碰撞：128px 网格索引 + 4px 子步，单次查询只遍历邻近桶；200 人 × 20Hz 仍可忽略
- 地形：全部纹理与圆角轮廓在初始化时烘一次，树与贴花按视口裁剪；帧循环只滚水面平铺偏移
- 遮挡：树冠 128px 网格索引，每帧只比 60 个角色 × 邻近 8 棵树；进入/离开用两个复用 Set 收差异，零分配
- 贴花：约 900–1200 个精灵，命中率与位置都是位置哈希算出来的，不查表不建对象
- 特效：接触阴影全局共用三张纹理（按形态换引用），踏步扬尘是固定 48 个精灵的对象池，帧循环不 new 对象
- 广播：可见性对称，`known` 集合本身就是订阅者列表，Tick 内不再做空间查询
- 渲染：分层灰度图 + `Sprite.tint`，数学上等价于调色板替换，但完全合批、每帧零开销
- 状态：帧循环只读写 TypedArray 与精灵位置，运行期不产生对象；React 不参与帧循环

本机实测（Windows，200 个机器人客户端与服务器同机竞争 CPU）：

| 场景 | p50 | p95 | 单客户端下行 |
|---|---|---|---|
| 200 人稀疏分布（出生半径 3000px） | 7.0 ms | 9.2 ms | 2.3 KB/s |
| 200 人全部同屏（出生半径 240px，全互联最坏情况） | 9.3 ms | 13.9 ms | 22.7 KB/s |
| 6 人 | 0.33 ms | 0.55 ms | — |

已知尖刺：200 个连接在同一秒内涌入时，每名新玩家的首次视野结算会让 Tick 出现一次百毫秒级长帧
（实测 max ≈ 158ms）。常态加入（服务器启动后逐个进入）不触发该问题。压测命令：

```bash
GAME_SPAWN_RADIUS=3000 BENCH_BOTS=200 BENCH_MS=12000 pnpm bench
```

## 准入与排队

园区按「三维水位取最大」自动开关闸门，越限时新到访者进入 FIFO 队列，而不是被直接断开（见 ADR-0009）。

- **判据**：出口带宽（`Transport.send` 处实测字节，50ms 环形桶）、在线人数、Tick p95。任一维度超过 0.85 关闸，回落到 0.65 才重开——滞回是为了让排队屏不在临界点闪烁。
- **容量自适应**：稳定 30s 容量 +2；持续越界按 25% 收缩，最多每 10s 一次，下限 10 人。Tick 瞬时尖刺不砍容量，连续 3 次达到 2 倍预算才熔断。队列上限 = `clamp(容量 × 2, 50, 1000)`，随容量一起变化。
- **排队者不进世界**：不占 AOI、不产生同步广播，每秒只收一条 16 字节位次快照；界面显示位次、预计等待与触发原因（带宽 / 人数 / 负载）。
- **放行限速**：每 Tick 最多 2 人（约 40 人/秒），避免开闸瞬间的首次视野结算把 Tick 压成长帧。
- **掉线立即释放**位次；被拒后不自动重连，由用户显式点「重新排队」。

开关与阈值全部可用环境变量覆盖，默认值面向 2C2G / 3M：

| 变量 | 默认 | 说明 |
|---|---|---|
| `GAME_QUEUE_ENABLED` | `1` | 设 0 回到「满员直接拒绝」的旧行为 |
| `GAME_MAX_ONLINE` | `60` | 容量基准，也是 AIMD 扩容上限 |
| `GAME_MAX_EGRESS_KBPS` | `320` | 出口带宽预算（3Mbps 扣 TCP/TLS 开销） |
| `GAME_TICK_BUDGET_MS` | `25` | Tick p95 预算，超过半个周期就收紧 |
| `GAME_ADMIT_PER_TICK` | `2` | 放行速率，2 × 20Hz ≈ 40 人/秒 |
| `GAME_QUEUE_MAX_WAIT_MS` | `180000` | 单次排队上限，超时劝退 |

压测与验证：

```bash
BENCH_BOTS=120 BENCH_QUEUE_PROBE=1 BENCH_MS=20000 pnpm bench
```

`/health` 返回 `egressKbps` 与 `admission`（闸门状态、容量、队列长度、水位千分比与主导维度），`BENCH_QUEUE_PROBE` 会额外打印峰值排队人数、首个放行时延与平均等待。

## 已知边界

不含多地图/分线、好友私聊、Redis 分片、完整反作弊、移动端虚拟摇杆；
地图只有一座手写海岛，地形碰撞是静态几何，不含寻路、可破坏物与游泳；美术是脚本生成的像素画，
替换 `apps/web/public/sprites/` 下的图集与 `manifest.json`（`version: 4`：64×64 帧、`origin`、
20×20 配件与 clips 结构）即可接入正式美术。
