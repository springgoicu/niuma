# 牛马 NIOMA

一座永不下班的 2D 像素多人在线办公园区。选一头牛或一匹马，走进工位、打字聊天、坐下躺平。

**核心约束：服务端落盘园区共享运行态与按设备号归户的钱包、骰桌战绩（ADR-0081 / ADR-0104 / ADR-0110）。** 世界仍活在游戏进程内存里，写进
本地快照 `world-state.json` v4 的有：老板血量与下一次回满时刻、擂台局号与上一局名次、
两栋小院的冠名权、按匿名设备号累计的赞与擂台奖牌、同一设备号的钱包账本
（余额 / 四维 / 背包 / 装扮 / 分 key 托管），以及骰桌战绩账本（累计输赢与最近 20 局逐局记录）。
玩家会话、聊天、考勤与外观依旧只在内存与浏览器 `localStorage` 里：昵称、外观、状态与上次的落点只写进浏览器
`localStorage`，关掉浏览器再回来还站在自己的工位上，换设备则重新开始。浏览器里已有存档时，重新打开域名会跳过首页直达
上次选的那座园区；没选过则先到选园页。站内点 Logo 或「打卡下班」回首页仍正常展示首页（ADR-0038）。

**时间只有一个来源：服务端时钟 + 园区时区偏移（ADR-0081）。** 擂台倒计时、老板跨日回满、「今天」的工时与日切、
签到上香、节日与季节判断全部按服务器时间与园区时区算；浏览器时钟只用于显示，电脑时间不准或人在别的时区都不会把园区带歪。

园区可以有多座：一台机器一座独立进程，之间没有任何连接，也不需要分片协议（ADR-0043）。
不同园区的人互相看不见，工牌与外观通用；只部署一台时就是单园区形态，零配置即可运行。
部署方式（1 台 / 2 台 / N 台）见 [`docs/deploy-multi-park.md`](docs/deploy-multi-park.md)。

## 技术栈

| 层 | 选型 |
|---|---|
| Monorepo | npm workspaces + TypeScript 5（strict） |
| Web | Next.js 15 App Router · React 19 · Tailwind CSS v4 · Zustand 5 |
| 渲染 | PixiJS 8（默认 WebGL2，`?gpu=webgpu` 灰度 WebGPU）· bitecs 0.4（SoA + TypedArray） |
| 美术 | 程序化生成 64×64 分层像素图集，34 列帧预算（走 6 拍 / 待机呼吸 + 眨眼 / 坐躺 / 跳 / 站坐躺三套发泄 / 站坐躺三套挥手） |
| 服务 | Node.js `ws` WebSocket · 20Hz 固定 Tick |
| 协议 | 手写二进制帧，79 个编号 / 78 个在用操作码（`0x01`–`0x5f`），移动包 8 或 14 字节；无 JSON、无轮询 |
| 数据 | 进程内存（唯一真相）+ 浏览器 `localStorage` 会话 + 六段共享运行态快照（含钱包与骰桌战绩账本）；无数据库、无 ORM |

## 快速开始

```bash
npm install
npm run dev
```

- 园区首页 <http://localhost:3000>
- 捏人工作台 <http://localhost:3000/create>
- 选择园区 <http://localhost:3000/enter>（只配一座园区时自动跳到 /play）
- 进入园区 <http://localhost:3000/play>
- 服务器状态 <http://localhost:3001/health>

需要 Node ≥ 20。依赖与脚本统一走 npm workspaces，无需全局安装 pnpm 或 Bun。

想直接进服，可以用深链：`/play?name=夜班实习生&species=horse`。
捏人页也认物种：`/create?species=horse` 直接用马开工（优先级：URL 参数 > 本地存档 > 上次显式选择 > 牛）。

## 角色与动画

角色是 `packages/pixel-assets` 里的程序化像素画，不依赖任何外部美术工具：

- **网格与帧预算**在 `src/layout.ts` 一处定义：64×64 帧、每方向 34 列，idle 0-2、walk 3-8（六拍 80ms）、
  sit 9-10、lie 11-12、jump 13-15、vent 16-18、sitVent 19-21、lieVent 22-24、
  wave 25-27、sitWave 28-30、lieWave 31-33。
  生成器按列作画，客户端按同一份布局切片与播放。发泄、跳与打招呼是姿态之外的叠加动作
  （ADR-0051 / ADR-0019）：按 C 抬前蹄挥手，站 / 坐 / 躺各一套，行走中不接。
- **画法**是硬朗卡通：每个形体只有「本体 + 一档阴影」，阴影靠整块偏移而不是逐列扫描，
  描边统一 1px 并补对角针孔。牛与马共用 48 texel 的站立总高（差 1.3），
  靠躯干 23 : 19、腿 17.5 : 20、颈 8.2 : 10.5、吻 10 : 6.8 分开剪影（见 ADR-0010）。
- **分层染色**：图集导出成 `tail / body / pattern / bodyLight / hoof / eyes / eyeLight / extra / snout`
  九张灰度图，运行时逐层 `Sprite.tint`。`bodyLight` / `eyeLight` 是纯白层，靠把本体色往白里混
  得到提亮——`tint` 是乘法，没有独立图层就画不出月牙高光与眼神光（见 ADR-0006）。
  配件（帽子 / 眼镜 / 颈饰 / 发型）同样是灰度小图，各自跟随所属属性的色槽染色（见 ADR-0011）。
- **播放**：`apps/web/lib/game/clip.ts` 把 manifest 的逐帧时长预编译成时间轴，相位按 `netId`
  哈希错开，所以同一屏里的人不会同时抬腿。
- **纸娃娃顺序**收敛在 `apps/web/lib/game/pony.ts` 的 `PONY_LAYER_ORDER` 一处：
  tail → body → pattern → bodyLight → hairstyle → headwear → hoof → extra → eyes → eyeLight
  → eyewear → snout → neckwear。鬃毛排在眼睛之前是**刻意**的：让鬃毛压住眼睛会吃掉表情，
  读脸优先级高于「鬃毛在最上层」（ADR-0013）。
- **微动效**是纯函数 `pony-motion.ts`：`ponyMotion(pose, elapsedMs, netId)` 给出
  `{ bobTexels: 0 | -1, shadow: 0 | 1 | 2, blinking }`。待机 3.4s 一个呼吸、行走 240ms
  一个起伏，**只抬高不下沉**（角色永远不会陷进地面）；阴影用三张预烘焙椭圆换纹理做
  squash & stretch，不做浮点缩放。眨眼每 35s（±5s 抖动）由客户端注入闭眼列——
  图集里那一列仍属于 idle，只是不再进循环（见 ADR-0013 第 9 条）。

改帧数只需动 `layout.ts` 再跑 `npm run assets`：布局会重新写到
`apps/web/lib/game/sprite-layout.generated.ts`，客户端与落地页的 CSS mask 都读它。

## 动作与互动

按键：`Z` 坐、`X` 躺、`C` 打招呼、`E` 发泄、`Space` 跳、`F` 互动，`Enter`（含小键盘）打开聊天并聚焦输入框。

- **坐 / 躺由座位种类决定**：椅子、长椅、凳子、沙发与马桶落坐姿，单人床落躺姿（`seatPose`，ADR-0026）。
  靠近座位按对应的键会自动吸附到最近的空位；移动即起身，地面坐 / 躺同样以移动或对应按键起身。
- **互动**：靠近售货机、饮水机或咖啡机按 `F`，角色头顶冒一句生活化气泡（只在本地显示，不新增协议）；
  躺在床位上静置 5s 后，每 9s 冒一次「Zzz…」。走到中央广场北缘的**牛马榜公告栏**旁按 `F`
  打开的是全园榜单面板（ADR-0054），不冒气泡。
- **失败有回执**：赌桌 / 擂台 / 别墅 / 搬砖 / 悬赏等被服务端拒绝时回 `S2C_INTERACT_REJECT (0x5a)`，
  提示条直接说「先入座 / 离太远 / 阶段不对 / 余额不足」，不再点了没反应；入座后提示与 `F` 走同一套
  热区优先级，坐在工位椅上靠近茶台也不会提示与动作各说各话。
- **聊天**：`Enter` 随时打开面板并聚焦输入框（面板已展开但失焦时也会重新聚焦）；`Esc` 收起、焦点还给游戏。
  发言以全屏弹幕上屏，频道列表保留完整记录（ADR-0056）。中文输入法选词期间按 `Enter` / `C` / `Z` / `X` / `Space`
  不会误触发送或动作。
- **发泄（`E`）**：一记牛马式冲撞，站 / 坐 / 躺各一套三拍动画
  （后撤蓄力 → 前冲头槌 → 后坐力）。命中由服务端在 Tick 里裁决：身前 64px、60° 扇形内最近的
  一名玩家被推开 32px 并强制躺地 1.5s，硬直期间起不来；空放只有一声破空，命中是「砰」的钝击音
  （Web Audio 实时合成，无音频资源）。已经入座的人（办公、睡觉、蹲马桶、坐凳子都算）不会被创飞：
  出招落在他身上按空放处理，也不会穿透去打他身后的人（ADR-0065）。行走中按 `E` 会立刻停下出招。
  企业楼发泄室里的老板也吃这一招：不推开、不击倒，只扣他一点血（ADR-0070）。
  点击角色只查看工牌，不出招。右上角喇叭按钮可静音，偏好只存本地。

## 弹幕（ADR-0056）

- 聊天走**屏幕空间弹幕**：不跟角色走，也不受相机平移与缩放影响；滚动弹幕从右缘匀速飞过（约 6~7 秒），
  顶部 / 底部固定弹幕居中停留 4 秒后淡出。文本统一 2px 纯黑描边。
- 输入框上方工具栏：8 种预设色（默认白 / 薄荷绿 / 警示红 / 高光金 / 赛博蓝 / 赋能紫 / 落日橙 / 发疯粉）、
  `➡ 滚动 / ⬆ 顶端 / ⬇ 底端` 轮转、6 条职场黑话快捷词条（点击填入输入框，不直接发射）。
- 齿轮面板：弹幕总开关、20%~100% 不透明度（默认 85%）、全屏 / 半屏 / 精简三档覆盖；偏好存
  `niuma:danmaku_pref:v1`。关掉只停渲染，聊天照常进频道列表。
- 协议（硬切，双端必须同版本发布）：
  `C2S_CHAT = [op][colorIndex u8][danmakuMode u8][len u16][utf8]`，
  `S2C_CHAT_BROADCAST = [op][entityId u16][msgId u16][colorIndex u8][danmakuMode u8][len u16][utf8]`。
  颜色索引越界回落 0（默认白），模式越界回落 0（滚动）；审核、打码与 5s/3 条限速不变，历史条目不含外观字段。
- 调试开关：`?danmaku=0` 关掉整层，`?danmaku=stress` 本地压 100 条并发。

## 工牌与状态

左上角工牌卡在名字下方有一行状态：点一下展开输入面板，可写 16 显示宽（8 个汉字或 16 个半角以内，
字节上限 48B），配一排常用 emoji 快捷插入。`Enter` 保存、`Esc` 或点画面空白处收起，保存后输入框失焦、WASD 立刻可用。

- 状态常驻在**头顶昵称上方**，字号比名字小一号、薄荷绿；聊天气泡会再整体让出一行，三者永不重叠。
- 刷新或重开浏览器后自动恢复；服务端不落库，换设备就是新状态（与昵称、外观同一策略，见 ADR-0035）。
- 审核与昵称同一套：政治类直接清空，脏话按打码结果上屏；服务端再复核一次并做 200ms 广播节流。
- 协议是纯追加：`C2S_HELLO` / `S2C_ENTITY_SPAWN` 尾部各带一段可选状态，
  运行时改动走 `C2S_SET_STATUS (0x1b)` / `S2C_STATUS (0x1c)` 广播；空状态不写任何字节，旧客户端行为不变。
- **改名**（ADR-0062）与改状态共用同一条保存路径（`niuma:profile:v2`，旧 `v1` 迁移键仍在）：
  `C2S_SET_NAME (0x28)` / `S2C_NAME (0x29)` 与状态包同构，只广播真的变了的字段；
  空名与政治敏感由服务端保留原名，改完立刻刷新头顶昵称、小地图与工牌锚点。

### 牛马考勤档案（ADR-0052 / ADR-0086）

点自己或别人，打开的都是同一张「牛马考勤档案」：职级、今日工时、今日如厕占比、首次入职、
出勤地点、园区区域、姿态 / 入座、行为统计、同屏劳模榜名次、今日称号、点赞与分享入口。

工号、部门 / 班次、条码 / 二维码与 `VERIFIED` 认证字样已删除（ADR-0086）：它们由昵称哈希编出，
没有任何数据来源；归属地查不到时统一显示「未上报」，不再用编造地名兜底。

- 考勤历史与行为累计只存在**本人浏览器**；进园时随 `C2S_HELLO` 的 `0xfc` 尾部段上报，在线每 20 秒
  用 `C2S_CAREER (0x22)` 补报一次（服务端按连接 10 秒限频）。摘要为 **v4**：定长 24B + 省份（≤30B），
  新增擂台金 / 银 / 铜三枚奖牌计数。服务端只做内存转发（`Player.career`），进程重启即清空——
  它属于会话数据，不在 ADR-0081 的落盘范围。
- 切日口径同样在浏览器侧，但用的是**服务器时钟 + 园区时区**（`serverNow()` / `serverDateKey()`）：
  客户端的「今日工时」「本周工时」不会因为本机时钟或时区不同而与邻座差一天。
- 补报后服务端向 `known` 广播 `S2C_CAREER (0x23)`，正在围观的人立刻刷新；新增视野的人从入场包直接拿到摘要。
- 他人工牌只显示**省级**地点，`city` / `isp` 永不下发；省份是唯一自由文本，走与昵称 / 状态同一套审核。
- 摘要由本人客户端自报，改包可以伪造，因此只用于展示，不参与移动、碰撞、座位、发泄等任何权威判定。
- 行为统计（步数 / 里程 / 摸鱼 / 击倒 / 被喷 / 加班）落在 `niuma:career:v1`，与考勤一样 30 秒批处理落盘；
  他人工牌显示的是「截至上次上报」的累计值。击倒只认服务端 `S2C_VENT` 且本人是攻击者、`targetId != 0` 的
  成功命中；空放与他人互殴不计。
- 「同屏劳模榜」只统计当前视野内、且已上报工时的人，UI 明确标注「视野内」，不伪装成全服榜。
- 他人工牌头部可以**点赞**（ADR-0057 / ADR-0081）：同一次在园对同一块工牌只能点一次，点赞数记在
  匿名设备档案里（客户端生成的设备号，不做账号），与擂台奖牌一起写进快照的 `profiles` 段。改名、离园、
  服务端重启都不会清零；换浏览器或清掉站点数据则重新开始，面板仍写本园区口径，不承诺跨园区汇总。

### 牛马榜公告栏（ADR-0054）

中央广场北缘、出生点斜北侧立着一块木框纸签公告栏（`WELCOME_LANDMARKS.rankBoard`）。
靠近 96px 出现「按 F 查看牛马榜」，按 `F` 打开面板，`Esc` / 点遮罩关闭；关闭后焦点回到画布。

- **五个「今日」榜**：在岗分钟、如厕分钟、击倒他人、被他人击倒、搬砖步数（指标编号 7–11）。
  一次打开拉全部五榜，页签切换零往返；每 20 秒自动刷新，手动刷新 3 秒冷却。旧版 1–6 编号
  （本周工时 / 摸鱼次数 / 人气等）已全部不再接受。
- **只排已上报的人**：五榜都只统计当次在园、且已上报今日摘要的人；没上报的显示「未上报」，
  离线即离榜，NPC 不进榜。快照头部另带服务端下发的 `online` / `slacking`（当前坐 / 躺人数）。
- **可信度分层**：五个数值全部是本人客户端自报（改包可伪造），只用于展示，面板标注「最多 20 秒延迟」；
  榜单不发币、不参与准入或任何权威判定。点赞数不设榜单，只挂在工牌上。
- **防放大**：服务端校验 240px 距离门、1500ms 限频、Top 10、名字 48B / 数值 u32 上限；
  坏包与未知指标整条丢弃，客户端保留上一份快照。
- **快照形状**：`C2S_BOARD (0x24)` 只带 1 字节指标（0 = 一次拉五榜）；回包 `S2C_BOARD (0x25)` 是
  13 字节定长头（指标 / 在线 / 坐躺 / 条数 / 自己名次 / 自己数值）+ 每条 7 字节 + 昵称，前十名单包 ≤ 563B。
- **世界对象与碰撞是静态内容**：改坐标或碰撞要双端一起发版；只发一端会出现「看得到牌、走不过去」
  或「穿模」的漂移。

### 发泄区（ADR-0070）

企业楼（广场正西那栋两层小楼）南排是整间发泄室（`VENT_ROOM`），室内铺了一块 420×300 的橡胶垫
（`BOSS_ARENA`），正中站着一只 200×256、双手背在身后的老板（`BOSS`，`x` 是横向中心、
`y` 是脚底南沿），推门进来就是正面（ADR-0097 起发泄区不再在室外庭院）。
碰撞只挡脚底 160×44，玩家可以贴到肚子底下出招，
不用隔着两百像素空踢。

- **一万点血**：`BOSS_MAX_HP = 10000`，每脚真实命中扣 1 点，全园区共享一条血条；
  血量与「10000 / 10000」数字靠全园区广播 `S2C_BOSS (0x2c, 6 字节)` 同步，低于三成转橙。
- **每日回满**：血量与 `resetAt` 写进快照的 `boss` 段（ADR-0081），重启后按快照续血；
  只有跨过本地零点、或停机跨了零点，才在下一次命中前回满。
- **倒下**：归零那次整只换成去饱和灰纹理，头顶木牌换纸板「老板倒下」，血条停在 0 / 10000；
  主线程给一条 4.5s 的轻提示，次日回满时自动收起。
- **掉落（老板 2.0）**：每次真实命中掉 2–5 牛马币，暴击翻倍（暴击率 = 暴击等级 ×5%，封顶 35%）；
  归零那一脚另发尾刀 500 币（`WALLET_REASON.BossReward`）。
- **画饼冲击波**：每掉满 2500 血触发一次，预警 2s、半径 320px、击退 48px、硬直 1500ms；
  预警与结算各广播一条 `S2C_BOSS_SHOCK (0x57)`（含命中人数）。
- **判定**：沿用发泄的扇形（身前 64px、60°），目标点取受击矩形上离玩家最近的一点
  （`bossHitPoint`），站斜一点也能踢到肚子；命中是钝击音，空挥只有破空音。
- **提示**：到受击矩形最近点 72px 内出现「[E] 发泄 · 踹老板一脚」，触屏是动作盘上的「发泄」。
- **导览**：`NAV_TARGETS` 里它是 15 个导览目标之一（`bossArena`，归企业区），导览卡点一行就自动走到垫内左下角；
  中央广场的指路牌只列**五座区门**，块数随 `DISTRICTS` 派生，不另存一份清单（ADR-0097）。

## 牛马币与钱包（ADR-0082）

园区里所有进项与花销都过同一个钱包。**服务端 `WalletBook` 按匿名设备号保存账本（ADR-0104）**：
余额、四维、背包、已解锁装扮与分 key 托管写进 `world-state.json` 的 `wallets` 段（v3），
重启后按设备号接着用；浏览器 `niuma:economy:v1` 只做进园首帧的本地镜像，收到
`S2C_WALLET_SYNC(reason=init)` 后被服务端账本覆盖。

- `C2S_HELLO` 的 `0xf7` 经济段只在**首次见到该设备号**时导入一次，余额上限
  `GAME_WALLET_IMPORT_MAX`（默认 100000）；之后同一设备号再进园一律忽略这段，改包撑不出额外余额。
- 没有有效设备号（旧客户端 / 隐私模式）退化为会话内临时钱包，不落盘、不导入。
- `GAME_WALLET_PERSIST=0` 回到「浏览器是永久层」的旧行为；`GAME_STATE_PATH=''` 关闭全部持久化。
- 托管按「玩法 + 桌 / 局 + 玩家实体」分账：`dice:<桌号>:<玩家>`、`ring:<玩家>`（报名费）、
  `ring:bet:<玩家>`（观战押注）、`p2p:<局号>`；任一玩法只清自己的 key，启动时把残留托管原路退回。
- `S2C_WALLET_SYNC` 的背包段后追加可选装扮段 `[count u8][cosmeticId u8]×N`；
  旧客户端读完背包就停，不会因为尾段报错。

- **上限**：余额 999,999,999；属性等级 0–10；单件道具 99；装扮目录 18 件（存档最多记 24 个键）。
- **进项**：擂台名次 300 / 150 / 80（只发前三）、击倒他人 12、老板尾刀 500、每日悬赏 40–80、
  搬砖工资 15–120、赌桌派彩、抢红包 10–40、查岗全勤 60、摇钱树 25/分钟、打赏。
- **花销**：属性升级、道具、装扮、赌注与报名费、小院冠名 1000、打赏。
- **属性**（价格 `base + step × 当前等级`）：

| 属性 | 首级 | 每级递增 | 效果 |
|---|---|---|---|
| 攻速 | 120 | 80 | 发泄冷却每级 −70ms，10 级锁在 500ms |
| 工效 | 100 | 60 | 搬砖产出每级 +8% |
| 暴击 | 140 | 90 | 踢老板暴击每级 +5%，封顶 35% |
| 护甲 | 110 | 70 | 预留属性，目前只展示 |

- **装扮货架**：赛博茶水强化站的第三页签，四槽 `head / eyes / neck / hair`，18 件 200–680 币，
  买了直接进 `unlockedCosmetics`，捏人页同名配件立刻可选。
- **协议**：`C2S_SHOP_BUY (0x37)`；回包 `S2C_WALLET_SYNC (0x38)` 是完整背包快照而不是增量——
  `[0x38][coins u32][4×属性 u8][reason u8][count u8]` + n×`[itemId u8][count u16]`，一次替换即幂等。
  `reason` 为 0–31 的原因码（擂台奖金 / 赌桌派彩 / 搬砖工资 / 抢到红包 / 踢老板掉落 / 查岗全勤…），只追加不复用。
- **打赏**：`C2S_TIP (0x35)` / `S2C_TIP (0x3c)` 12 字节，`flags bit0` 表示收包人是收钱那方。

## 道具与 Buff（ADR-0085）

七件道具（线协议 id 只追加，1 与 3 永久留空）：

| id | 道具 | 价格 | 目标 | 效果 |
|---|---|---|---|---|
| 2 | 彩带礼花 | 40 | 他人 | 在目标头顶炸一把彩带，纯演出 |

## 工位搬砖与每日悬赏（ADR-0088 / ADR-0093）

## 摸鱼骰子馆（ADR-0087 / ADR-0093 / ADR-0110 / ADR-0111）

（座位组 `dice-a` / `dice-b`）。玩家可见文案按 ADR-0111 统一用「投入 / 奖池 / 服务费 / 同点」，

  不进胜负。面板三页签（本局结算 / 我的战绩 / 排行榜）里，后两者共用一次
  `C2S_DICE_BOARD (0x5c)` 拉取：`S2C_DICE_BOARD (0x5d)` 同时回榜单与本人三份累计口径
  （总榜 / 两桌）和最近 20 局逐局记录。榜单可切总榜与单桌、按累计净收益或胜率排序，
  胜率 = 胜 /（局数 - 退款局），没有有效局显示「—」。拉榜按玩家 2s 冷却，不扫热路径。
- **落盘**：骰桌战绩账本按匿名设备号归户（`deviceId` 不出网、不写进任何包），与钱包一起进
  `world-state.json` v4 的 `dice` 段；最多 200 人 × 每人 20 局，按「最久未见」淘汰。

## 诊所与工伤（ADR-0084 / ADR-0090 / ADR-0092 / ADR-0107）

- **窗口探头**：站在 301 门口 64px 内按 `F`，人就从 4 层 × 5 列共 20 个窗口里挑一个空位探头；
  再按 `F` 回到门口台阶。楼内没有可走空间，所以没有室内房间、户型与家具（ADR-0098 撤掉），
  `0x4d`–`0x50` 四个编号随之永久留空。
- **同步**：`S2C_APARTMENT_PEEK (0x59)` 是全量快照（`count` + `playerId / slot / window` 各一条），
  `slot` 恒为 0，只在进楼、出楼、断线、入场各发一次，稳态零流量；收到整份替换。
- **导览**：`NAV_TARGETS` 里的「牛马公寓」送到 301 栋门口台阶。
- **花园**：石板小径与灌木随 `?decor=0` 整体退场；夜里不添灯，靠石径中段一层烘焙暖光提亮。

## 别墅小院（ADR-0087）

生活区东侧并排两栋 220×170 的院子，中间留 40px 通道：**摸鱼一号院**与**摸鱼二号院**，院门朝南。

- **冠名**：无主时门口牌匾标价 1000 币，按 `F` 买下「本运行周期」的冠名权，牌匾实时显示房主名；
  冠名权写进快照的 `villas` 段，服务端重启后仍保留，清档才会重新挂牌。
- **归属（ADR-0104）**：`S2C_VILLA_STATE` 带 `owned` / `mine` 两个标志；房主离线时 `ownerId` 归零，
  但院子仍显示已拥有，不会再出现「待售 / 买下」按钮。
- **锁门**：房主可切换锁门，门洞变成一道动态门栅——只挡客人，房主照进。
- **摇钱树**：院内每分钟结 25 币，最多囤 10 分钟（250），站到树旁按 `F` 收走。
- **协议**：`C2S_VILLA (0x48)` / `S2C_VILLA_STATE (0x49)`，两栋一包；买院 / 锁门 / 收币失败回
  `S2C_INTERACT_REJECT (0x5a)`（已售出、仅房主、暂无可收、余额不足等）。

## 园区同事（ADR-0061）

每台 game-server 进程启动时自动生成 2 位普通同事 + 3 位保安，共 5 位服务端权威 NPC，和真人走同一条实体通道：同样的工牌、外观、AOI 与地形碰撞；除保安警灯外，客户端不需要为它们的行走与互动做额外适配。

- **行为**：整座岛随机选点，走遍广场、工作区、宿舍、会议室、庭院与林间小路；停顿分三档（1.2–3s / 3–12s / 20–60s），停下时每 0.8–2.5s 换一次视线；步速 0.62–0.95 倍真人，同一屏内不会整齐划一。
- **互动**：停顿时有人靠近会转头看过去，迎面 80px 内会停下让路，小概率招手；被玩家创飞后躺 1.5s，自己爬起来继续走，不还手。
- **只做动作**：NPC 不在频道发言、也不写聊天历史；频道里只有真人说话。
- **避障**：与服务端移动包共用一个 `resolveMotionInto`（4px 子步 + 单轴滑动）；连续两次挪不动就换落点，五次就原地歇 20–40s，绝不传送。
- **口径**：NPC 不占真人名额、不进牛马榜、不计入 `/health.online`；`/health` 单独给 `npcs`、`npc.count`、`npc.guards` 与 `npc.updateMs`。出口带宽按实测计入（物理共享），要给真人留余量就调低数量。
- **工牌**：名字由常见姓与普通名 / 牛马梗名随机组合（如「张伟」「李静」「王加班」），本次开服内稳定、重启换一批且互不重名；配随机外观、常驻状态与合成考勤，点开能看到合理的在岗时长与工时（NPC 不进榜、不计入 `/health.online`）。
- **保安**：3 位固定保安穿整套警服（大檐警帽 + 肩章 / 胸前反光条），头顶红蓝警灯约每 400ms 交替；身份由 spawn 可选尾段下发，普通同事与真人都没有警灯。
- **回滚**：`GAME_NPC_COUNT=0` 或 `GAME_NPC_ENABLED=0` 重启即完全关闭（含保安），无协议、无客户端、无数据迁移。

| 变量 | 默认 | 说明 |
|---|---|---|
| `GAME_NPC_ENABLED` | `1` | 设 0 关闭整批同事与保安 |
| `GAME_NPC_COUNT` | `2` | 普通同事数量；0 等价整批关闭（含保安），上限 64；保安固定 3 位 |
| `GAME_NPC_SEED` | 进程随机 | 固定后整场行为可复现，便于回归与截图 |
| `GAME_NPC_INTERACT` | `1` | 设 0 关掉对视、让路与招手 |
| `GAME_NPC_CONFIG` | 空 | 可选 JSON：`speed` / `pauseMs` / `socialIntervalMs`；文件不可用只告警并回退默认 |

落点每次都会过 `isBlocked`，不会把同事送进海里或墙里；全岛采样失败时就近脱困，绝不传送。

`GAME_NPC_CONFIG` 的 JSON 形状（只写想改的字段，其余保留默认）：

```json
{
  "speed": { "min": 0.55, "max": 0.9 },
  "pauseMs": { "short": [800, 2000], "normal": [2500, 9000], "long": [15000, 45000] },
  "socialIntervalMs": 600
}
```

## 小黑屋与执法（ADR-0072 / ADR-0074 / ADR-0080 / ADR-0090）

服务区广场南面一间隔壁（`JAIL`，320×240 @ 4600,4040，只有西门开向广场，门内三个反省位），
接在两条服务端权威的执法链上：

- **骚扰案**：只认真人玩家在别人 56px 内完成的「坐 → 站」循环；单次坐姿限 150–1200ms、
  相邻循环 ≥150ms，只统计最近 8 秒，循环点漂移超过 32px 就清零。
- **响应**：第 3 次循环只私下警告本人；第 6 次或 3 秒内第 4 次确认，广播
  「{name} 被保安请进了小黑屋：园区内不许色色。」
- **打人案**：真人命中记在 2 分钟滑动窗口里——第 2 次私下警告，第 3 次建案；
  **打保安或护士零容忍，一次即成案**（ADR-0090）。
- **押送**：最近的空闲保安以 1.3 倍速赶来，26px 内按肩 0.6 秒，再以 0.85 倍速拖行，必须走西门；
  12 秒追不到、15 秒拖不到就原地松手，绝不传送（ADR-0061）。押送期间硬直 5s。
- **没有刑期**：送到反省点即释放——清硬直、落站姿、恢复移动与聊天，玩家自己走出小黑屋。
- **回滚**：`GAME_JAIL_ENABLED=0` 重启即关闭判定与押送，小黑屋退回普通空房；
  没有保安（`GAME_NPC_COUNT=0`）时同样不启用。

## 地图与地形

园区是一块手写矩形陆地（`packages/shared-types/src/world/layout.ts` 与 `districts.ts`），
服务端、客户端与小地图共用同一份坐标。ADR-0097 把它重做成**五区小城**：

- 陆地是 3040×3368 的矩形（x 2560–5600 / y 2412–5780），四边之外不是海而是一片不可通行的密林；
- 岛心是**中央迎宾广场**（720px 石砖圆庭）：出生点在圆庭正中，56px 内无碰撞；南缘是迎宾拱门，
  东侧立一块只列五座区门的导览牌，东西两侧对称摆着售货机、咖啡机、长椅与复古路灯；
  五条街从这里分别通往**企业区**（西）、**游乐区**（北）、**生活区**（南）、
  **服务区**（东）与**景观区**（西主路尽头），每个方向各有一座区门（门框 + 区色匾额 + 门灯）；
- **企业区**：广场正西的前庭之后是一栋 920×776 的两层小楼——北排工作区（无内墙、八个背靠背工位）
  与会议室，中间一条 56px 走廊（东端敞口就是公司大门，ADR-0099 由 40px 加宽），南排整间**发泄室**：
  橡胶地上一万血老板，进门就能踹（ADR-0070 的判定与回满规则不变）；
- **游乐区**：北向主路尽头一条**游乐大街**串起三处——西端摸鱼大赌场（半开敞亭子 + 两张 6 人赌桌）、
  街中段路南的绩效八角笼（围栏、报名点、观战长椅与领奖台）、以及原地的游乐园
  （滑梯塔楼在东北角、摩天轮占东南角，东门留作侧门）；
- **生活区**：南向主路两侧两排联排公寓（门牌 301–306，巷宽 48px，ADR-0099 由 40px 加宽），沿**生活大街**排开
  宿舍区（上下铺与双人沙发）、家庭影音室（三排五列影厅座椅）与两栋小院；
- **服务区**：东主路尽头 860×860 的服务广场，北面卫生间（男 / 洗手池 / 女三区、全园 4 个马桶），
  南面小黑屋（西门开出广场），东面护士急救站（西侧人行门只供出站，南侧救护车通道留给救护车）；
- **景观区**：三处内嵌景观湖原样保留（东南摸鱼湖、东北沉思浅塘、西侧涟漪湖），
  摸鱼湖东北岸是一片连续草地（原摸鱼亭已拆除，ADR-0105），竹林与花海落在西带与东南草甸；
  水系只按 ADR-0030 保持可涉水，湖里仍有纯客户端游动的小鱼；
- 室内陈设按房间分头补完（`interior-art.ts`，ADR-0046）：工作区有走线槽 + 接线盒、纸箱、打印机、
  零食推车与白板立架；宿舍区有看得见雪夜的窗、暖气片、挂钟、壁灯、衣柜、书架、行李架与圆毯；
  卫生间有墙裙、镜子、洗手液、烘手机、防滑垫、地漏与半掩的隔间门；两道内隔墙**有碰撞**，
  贴图由 `interior-art.ts` 按同一份 solids 绘制（ADR-0053）。以上陈设全部**无碰撞、贴墙摆放**；
- 植被改为 2–5 棵一簇的树丛 + 沿主路错列的林荫道，任意两棵树间隙 ≥80px；
  六片花海、三叶草、雏菊与林间落叶贴花，加上沿路休息角填掉空草地；
- 矩形四边就是地图边界：树干、花箱、房间墙体与边界外的密林都挡人；贴着墙体或边界走会滑行，不会卡死；
  边界内侧有一条 26px 沙滩装饰带，可走但不可越过；
- 尺度以角色为准：站立 48 texel，树高是它的 2.25 倍、树篱齐膝、地砖边长为身高的 1/3。

### 按 F 的热区与座位门禁

「按 F 能做什么」只有一张表（`WORLD_HOTSPOTS`，24 条）：客户端按 kind 优先级取最近命中并按同一 kind 分发，
服务端用 `hotspotById` + 距离校验（另加 **240px** 延迟余量，伪造包在离场后刷请求会被丢掉）。

- **优先级**：告示板 → 牛马榜 → 供案 → 茶台 → 工位 → 赌桌 → 擂台 → 观战长椅 → 小院门 → 摇钱树 → 公寓门。
- **半径**：告示板 64 / 牛马榜 96 / 供案 72 / 茶台 48 / 工位 84 / 赌桌 96 / 擂台报名 72 /
  观战长椅 56 / 小院门 64 / 摇钱树 48 / 公寓门 64。
- **座位门禁**（ADR-0093）：声明了 `seatGroupId` 或 `deskIndex` 的玩法（赌桌、观战押注、搬砖）
  必须坐在对应座位上，否则提示改成「按 Z 坐进本桌凳子再押注」这类指路文案。
- **面板不穿透**：模态打开时 `GAME_KEYS`（WASD / 方向键 / Space / Z / X / C / E / F / G）全部吞掉，
  关闭用 `Esc` 或点遮罩，遮罩另有 400ms 防误触窗口。

  牛马公寓、宿舍区、家庭影音室、摸鱼一号院、摸鱼二号院（生活区）；卫生间、护士急救站（服务区）。
  每个目标另带可站立的 `arrive` 点；景观区已无导览目标，沿湖步行前往。
  护士急救站的到达点落在**西门外铺装**上（ADR-0107）：导览不会把人送进站内，但区域名仍显示「护士急救站」。
- **回中央广场**：广场不属于任何大区，不做成场所目标，走导览卡底部单独一行，终点是出生点。
- **读数**：距离与方位按区域几何中心算，步行秒数 = 距离 / 165 px/s（至少 1 秒），八向档位喂给世界指路牌的像素箭头。
- **自动走**（ADR-0099）：先沿路网节点图走到目标所在大区的门口，再由格子 A* 收口进门；
  路点半径 10px 切换、12px 内算到达；连续 700ms 没有位移就先原地换一条路，再不动才停下并交还控制权。
- 导览卡与广场指路牌同源，区门那 5 块由 `DISTRICTS` 派生，不另存一份清单。

碰撞由服务端权威结算：`applyMove` 限速截断后调用 `resolveMotion`，客户端用同一个函数做本地预测，
因此不会出现「先穿墙再被拉回」。`isBlocked` 先判 `isOnLand` 再查障碍，矩形边界即墙（ADR-0064）。
地形是静态内容，不进协议、不落库，改地图要双端一起发版。

渲染侧所有地形纹理都在 `renderer.init()` 内一次性生成（1:1 + nearest，ADR-0005）。
林地铺在世界外层，草地直接平铺到矩形，边缘依次是沙滩与草地；
矩形外两排确定性树影连成林墙（`border-forest.ts`，纯渲染、不参与碰撞），
相机被夹在陆地包围盒内，走到边界也不会露出世界外的黑色。
小地图直接按世界→画布变换画布局，底色是密林、陆地由同一份矩形描出，视野 1000px 内的人和地形同屏可见。

地面过渡不是贴图拼的（ADR-0013）：

- 土路、广场、林地都用**圆角轮廓 + 遮罩平铺**：`autotile.ts` 输出半径 16 的解析圆角轮廓
  （林地再叠一层平滑噪声外推成有机边界），`TilingSprite` 用这张轮廓做遮罩裁切，
  外侧沿轮廓画 2px 草缘与每 6px 一个的 1px 细草齿，内侧压 2px「本体色压暗 40%」的暗边。
  平铺相位按世界坐标对齐，四条路撞在路口时纹理不会各走各的。
- 草地上再叠一层**贴花**（`decals.ts`）：64px 栅格上按位置哈希以 12% 命中率撒三叶草、雏菊、
  草尖与小石粒，水面/广场/土路/桥面不生成。同一格永远是同一株，来回走不会换位置。
- 树拆成**树干 + 树冠两张同帧纹理**，与树篱、花箱、角色一起按脚底 y 排序。角色走到树后时，
  只有树冠淡到 0.85（树干保持不透明），离开即恢复；判定走一棵 128px 的树冠网格索引。
- 整张地图画完后，在 `app.stage` 上覆盖一层屏幕空间的 `multiply` 柔光：按本地时刻在
  清晨暖金、白日中性、黄昏暖橙、夜间冷蓝之间插值，30s 采样一次。

三个灰度开关：`?flat=1` 退回矩形平铺（方便定位圆角/草缘的观感回归），`?light=0` 关掉柔光层，
`?bands=0` 退回单容器深度排序（定位遮挡回归，见 ADR-0024）。

## 冬季

本地日期落在 11 月至次年 2 月时，园区自动入冬（ADR-0046）。整套雪景**纯客户端**：
服务端、协议、碰撞与 `packages/shared-types` 零改动，因此**不需要双端发版**，
冬季也不会改变任何一条可行走区域。

- **飘雪**：屏幕空间的对象池（视口面积决定 48–200 粒），两种雪粒靠 alpha 与速度分远近；
  挂在 `stage` 上、柔光之下，所以雪和整张图在同一层光里。
- **覆雪**：草地、林地、花海与广场铺一层雪面；沙滩、土路、木桥、码头、水面与室内保持原样，
  读作「被踩化 / 被浪打湿 / 被屋檐挡住」。草缘换成雪缘，土路轮廓上不再冒绿草尖。
- **水面**：湖、河、海换一套冷调纹理（不是 `tint`——multiply 压不出「更冷更淡」），
  岸边内侧画 3–4px 薄冰带与碎冰，水面照旧滚动。
- **树冠**：上半部按行宽铺雪帽、下半部只在枝尖点雪，树根补一圈积雪。
- **脚印**：复用扬尘的同一条触地通路（`onFootfall`），只在 `isOutdoorGround` 的雪面留 9s 渐隐的 3×2 压痕。
- **道具**：中庭与庭院摆雪人与雪堆，每 9 棵树挂一串暖色灯串（夜间才亮），
  有墙房间的横向墙下沿挂 3–6px 冰棱。全部**不参与碰撞**。

三个开关，写法与 `?light=0` 一致：

| 参数 | 作用 |
|---|---|
| `?season=winter` | 7 月也强制入冬，用于验收与截图 |
| `?season=off` | 1 月强制退回常夏园区，等价于线上关闭冬季 |
| `?snow=0` | 只关飘雪粒子，覆雪地面与冬季道具保留 |

四季判定集中在 `apps/web/lib/game/season.ts`，其余图层只消费一个 `winter` 布尔量。

## 节日装饰

园区全年常驻一层节日装饰（ADR-0063），纯客户端、**不参与碰撞**，服务端与协议零改动：

- **跨路彩旗**：广场向外**五向出街**（西 / 北 / 南 / 东 / 西北主路尽头）各挂 1 条，挂在成对路灯之间；
  灯柱里夹着长椅的那一对自动跳过，所以实际条数少于理论值，布点全部由路网常量派生；
- **门楣彩旗**：挂在带牌坊的门楣横枋上（企业楼现在只有东侧一个大门口，不再有工作区 / 会议室两座独立牌坊），
  卫生间门洞上沿补 1 条；
- **树梢灯笼**：只挂在贴着主路的林荫道散树上，隔一棵挂一串，每串两盏小宫灯；
- **夜间**：主路口那几条彩旗接入真实光池（半径 48 的暖红），其余灯笼按 30s 采样昼夜，只调 `tint`；
- **画法**：整数抛物线串线、三角旗宽高都是偶数、中央大灯笼复用 `paintLantern()`；竖挂彩旗用整 90° 旋转，不做非整角重采样；
- **自适应**：贴图构造期 1:1 烘焙 + nearest，挂点全部整纹素，统一继承世界容器由 `pixelMetrics` 算出的整数缩放，横竖屏与各档 DPR 下都不糊边。

布点是 `WORLD_LAYOUT` 的纯派生（`festival-decor.ts`），渲染在 `festival-art.ts`，接入 `renderer.ts` 的构造、光池注册与 `destroy()`。

| 参数 | 作用 |
|---|---|
| `?festival=0` | 关闭整层节日装饰（不烘焙纹理，运行时零开销） |
| `?festival=1` | 强制开启，用于验收与截图 |

手测：进园区先看广场四向与主路入口；`?festival=0` 确认整层消失且可行走区域不变；等入夜看 6 处暖红光池与其余灯笼的亮核层次。

## 二进制协议

全部小端。移动包 8 字节，带时序时 14 字节：

```
[op 1B][entityId 2B][x 2B][y 2B][state 1B]
+ [clientSequence 2B][clientTimestampMs 4B]   // 可选
```

- 坐标：1/8 像素定点，u16 覆盖 8192×8192 世界
- state：`dir(2b) | pose(2b) | wave(1b) | moving(1b) | vent(1b) | jump(1b)`；
  后三位是一次性叠加动作，与姿态正交，播完由客户端清位（ADR-0051 / ADR-0019）
- 外观：32 字节定长（物种 1 + RGB565 十一色 22 + 部件 4 + 配件 4 + 保留 1），配件槽为 头饰 / 眼镜 / 颈饰 / 发型
- 枚举里 79 个编号，其中 78 个在用，最高 `0x5f`；`0x20`（原吃草）、`0x2a` / `0x2b`（原滑梯）、
  `0x3d`（旧道具效果，已被 `0x44` 取代）、`0x4d`–`0x50`（原公寓串门与家具）**永久留空不复用**——
  旧客户端仍按旧表解析该字节

| 0x5c / 0x5d | C2S_DICE_BOARD / S2C_DICE_BOARD | ↑ ↓ | 3 / 7+10n+本人段 | 拉榜 `[op][scope u8][metric u8]`；回包 `[op][scope u8][metric u8][total u16][count u8]` + n×`[rank u8][nameLen u8][name][net i32][winPct u8][rounds u16][flags u8]`（winPct 255 表示无有效局），再跟 `[hasSelf u8]`；有本人段时 3×`[rounds/wins/losses/refunds u16×4][totalBet/totalPayout/net/bestWin u32×4]` + `[histCount u8]` + n×`[table u8][round u16][d0-d2 u8][hit u8][bet u32][payout u32][net i32][flags u8]` |
| 0x5e | S2C_ACTIVITY | ↓ | 9+utf8 | 全园区播报（ADR-0112）：`[op][kind u8][actorId u16][x u16][y u16][len u8][utf8]`，文案上限 120 字节；只发给看不见主角的人，强演出必达、生活类合并、常规动作受令牌桶限制 |
| 0x5f | C2S_ACTIVITY | ↑ | 3 | `[op][kind u8][sub u8]`，只接受纯观感白名单（上香 / 续杯 / 设施 / 场所台词 / 常规动作），每玩家 1 条/秒，坐标取服务端权威位置 |

**HELLO / SPAWN 尾部扩展段**（按追加顺序，读端读到不认识的魔数即停）

| 魔数 | 段 | 长度 | 用途 |
|---|---|---|---|
| `1` | resume | 8 | `[ver][x u16][y u16][state u8][seatId u16]`，落点续站 |
| `0xff` | 常驻状态 | 2 + n | `[len u8][utf8]`，≤ 48B |
| `0xfd` | 同步能力 | 2 | `[format u8]`（1 = 6 字节紧凑条目）；SPAWN 里同号段承载角色 `role` |
| `0xfc` | 考勤摘要 | 2 + n | v4 定长 24B + 省份（≤ 30B）；缺段回退「未上报」 |
| `0xfa` | 会话续算 | 5 | `[sec u32]`，上限 86400s |
| `0xf8` | 设备号 | 9 | 8 字节二进制，只用于点赞与奖牌聚合 |
| `0xf7` | 经济摘要 | 2 + 9…57 | `[coins u32][4×属性 u8][itemCount u8]` + n×`[itemId u8][count u16]` |
| `0xfb` | 点赞数 | 3 | 仅 SPAWN，`[likes u16]`，0 赞不写 |
| `0xfe` | 已在线秒 | 5 | 仅 SPAWN，`[onlineSec u32]` |

客户端与服务端共用 `packages/shared-types/src/protocol.ts`，不允许各自实现一份。

## 性能

**网络**

- AOI：512px 单元，1000px 视野，跨格才重算订阅；广播量随视野人数增长，而非全图
- 广播：可见性对称，`known` 集合本身就是订阅者列表，Tick 内不再做空间查询
- 同步条目：`writeSyncEntry(writer, id, x, y, state)` 只写标量。200 人全同屏每 Tick 4 万次，
  传对象等于每秒 80 万个短命字面量（先前的 GC 抖动源）
- 变化驱动：三元组（量化坐标 + state）没变就不置 dirty，也不写包头；静止人群整 Tick 零发包（ADR-0043）
- 入场补发：名字 + 外观编码成 `Player.spawnBody` 缓存一次，坐标与状态每次现写；
  自己的包在循环外算一次，N 个已在场者共用同一份字节（ADR 未单独立项，见下节微基准）
- 客户端收包：`readSync(data, visit)` 逐条写成 TypedArray，不建数组、不建对象
- 远端回放：固定 80ms 延迟 + 4 帧环形快照，位置与 state 取自同一采样点（ADR-0025）

**画面**

- 深度排序：按 256 纹素切 y-band，静态物体构造期归桶一次，角色只在跨桶时换父容器。
  屏内有人走动不再触发全图重排（ADR-0024）
- 离屏剔除：相机范围外的角色不写位置、不写深度、`renderable = false`（本体与昵称一起关）
- 地形：全部纹理与圆角轮廓在初始化时烘一次，树与贴花按视口裁剪；帧循环只滚水面平铺偏移
- 遮挡：树冠 128px 网格索引，每帧只比 60 个角色 × 邻近 8 棵树；进入/离开用两个复用 Set 收差异，零分配
- 贴花：约 900–1200 个精灵，命中率与位置都是位置哈希算出来的，不查表不建对象
- 特效：接触阴影全局共用三张纹理（按形态换引用），踏步扬尘是固定 48 个精灵的对象池，帧循环不 new 对象
- 渲染：分层灰度图 + `Sprite.tint`，数学上等价于调色板替换，但完全合批、每帧零开销
- 状态：帧循环只读写 TypedArray 与精灵位置，运行期不产生对象；React 不参与帧循环

**线程**（ADR-0049）

- 游戏循环整体在 Dedicated Worker 里：WebSocket、二进制编解码、bitecs ECS、PixiJS 与帧循环。
  主线程只剩外壳 UI、键盘监听与尺寸同步，高刷屏的 8.3ms 预算不再和 React 提交抢
- 画布通过 `transferControlToOffscreen()` 移交，移交后主线程不再有任何绘制：主画面与小地图都不在主线程画
- 高频通道是一块 80 字节的定长控制内存（按键掩码 / 摇杆 / 视口 / 落点快照）：跨源隔离可用时是
  `SharedArrayBuffer`（零消息），否则退化成定长消息，引擎侧读写代码不变
- 低频事件才走消息：stats 2Hz、工牌 2Hz（小地图仍 4Hz）、落点回执 2s；聊天、状态、提示都是事件驱动
- 灰度开关：`?render=main` 强制回主线程（跑同一份引擎）、`?render=worker` 强制 Worker；
  `?gpu=webgpu` 打开 WebGPU（默认 WebGL2，理由与回滚路径见 ADR-0071）

**走路**

- 本地预测：与服务端共用 `resolveMotionInto`，零网络延迟，贴墙滑行与门洞通行不变
- 他人移动：`now - 80ms` 时刻在环形缓冲里插值，抖动被吸收成匀速位移，不外推
- 上行：有变化才发（上限 20Hz），静止降到 250ms 保活；叠加动作到期那一帧必须发，否则远端会一直播下去（ADR-0043）

**服务端实测**（Windows，机器人客户端与服务器同机竞争 CPU）：

|---|---|---|---|

| 60 人在线（默认容量满载） | 0.006 ms | 2.03 ms | 8.12 KB/s |
| 60 在线 + 60 排队（准入闸门闭合） | 1.62 ms | 2.15 ms | — |

## 准入与排队

园区按「三维水位取最大」自动开关闸门，越限时新到访者进入 FIFO 队列，而不是被直接断开（见 ADR-0009）。

- **判据**：出口带宽（`Transport.send` 处实测字节，50ms 环形桶）、在线人数、Tick p95。任一维度超过 0.85 关闸，回落到 0.65 才重开——滞回是为了让排队屏不在临界点闪烁。
- **容量自适应**：稳定 30s 容量 +2；持续越界按 25% 收缩，最多每 10s 一次，下限 10 人。Tick 瞬时尖刺不砍容量，连续 3 次达到 2 倍预算才熔断。队列上限 = `clamp(容量 × 2, 50, 1000)`，随容量一起变化。
- **排队者不进世界**：不占 AOI、不产生同步广播，每秒只收一条 16 字节位次快照；界面显示位次、预计等待与触发原因（带宽 / 人数 / 负载）。
- **放行限速**：每 Tick 最多 2 人（约 40 人/秒），避免开闸瞬间的首次视野结算把 Tick 压成长帧。
- **掉线立即释放**位次；被拒后不自动重连，由用户显式点「重新排队」。

开关与阈值全部可用环境变量覆盖，默认值面向 2C2G / 3M：

| 变量 | 默认 | 说明 |
|---|---|---|
| `GAME_QUEUE_ENABLED` | `1` | 设 0 回到「满员直接拒绝」的旧行为 |
| `GAME_MAX_ONLINE` | `60` | 容量基准，也是 AIMD 扩容上限 |
| `GAME_MAX_EGRESS_KBPS` | `320` | 出口带宽预算（3Mbps 扣 TCP/TLS 开销） |
| `GAME_TICK_BUDGET_MS` | `25` | Tick p95 预算，超过半个周期就收紧 |
| `GAME_ADMIT_PER_TICK` | `2` | 放行速率，2 × 20Hz ≈ 40 人/秒 |
| `GAME_QUEUE_MAX_WAIT_MS` | `180000` | 单次排队上限，超时劝退 |
| `GAME_STATE_PATH` | `data/world-state.json` | 园区共享运行态快照；**留空即完全关闭持久化**，回到纯内存 |
| `GAME_STATE_SAVE_MS` | `1000` | 变更后的落盘防抖窗口，写盘只在窗口末尾发生一次 |
| `GAME_STATE_MAX_PROFILES` | `512` | 匿名设备档案上限，超出按「最久未见」淘汰（另有 90 天过期） |
| `GAME_STATE_MAX_WALLETS` | `1024` | 钱包账本容量上限；只淘汰离线且托管为零的最久未进园记录 |
| `GAME_WALLET_PERSIST` | `1` | 钱包是否走服务端账本；`0` 回到浏览器永久层（ADR-0082 回滚开关） |
| `GAME_WALLET_IMPORT_MAX` | `100000` | 首次导入存量余额的上限，防改包一次性填满 |
| `GAME_TZ_OFFSET_MIN` | 宿主机时区 | 园区时区（分钟）；固定偏移，不进夏令时。擂台/回满/切日都按它算 |

默认值仍按 2C2G / 3M 标定。**5M 机器**（例如 2C4G/5M）去脏之后带宽不再是唯一瓶颈，
建议放宽到：

```bash
GAME_MAX_EGRESS_KBPS=530   # 5Mbps ÷ 8 × 0.85，0.85 水位再当安全垫
GAME_MAX_ONLINE=100        # 只是 AIMD 的上限，实际容量按实测水位收敛
```

不要一次调到 200：人数水位一旦成为主导，带宽兜不住时就是丢包 + RTT 抖动，
比排队更难受。改完看 `/health` 的 `admission.dominant`，长期是 `Players` 才说明该继续加。

压测与验证：

```bash
BENCH_BOTS=120 BENCH_QUEUE_PROBE=1 BENCH_MS=20000 npm run bench
```

`/health` 返回 `egressKbps` 与 `admission`（闸门状态、容量、队列长度、水位千分比与主导维度），`BENCH_QUEUE_PROBE` 会额外打印峰值排队人数、首个放行时延与平均等待。

## 内容审核

园区里只有两处自由文本，走的是同一套规则（ADR-0028）：

- **工牌名**：入场页与捏人页保存时就地校验。命中政治类不允许上岗；命中污言秽语打码后允许进入。
  服务端在 `C2S_HELLO` 再判一次兜底，伪造客户端也送不出违规名字。
- **园区频道**：政治类整条不广播，发送者收到 `S2C_CHAT_REJECTED` 回执；污言秽语打码后照常广播，
  发送者与旁听者看到的是同一份。

匹配前统一做 NFKC、去噪（空格 / 标点 / 零宽字符）、叠字折叠与数字替字，`敏 感 词`、`ＳＨＩＴ`、`sh1t`
这类写法都逃不掉。词库分两层：内置表随版本发布，服务端可用外置 JSON 覆盖或追加。

| 项 | 默认 | 说明 |
|---|---|---|
| `GAME_MODERATION_LEXICON` | 空 | 外置词库 JSON 路径；为空只用内置表。文件不可用时降级到内置表并告警，不阻断启动 |
| 导入 | — | `npm run lexicon:import --workspace=apps/game-server -- --dir <词库目录> --out lexicon.json`；开源词库来源与许可证见文档 |
| 自检 | — | `npm run lexicon:check --workspace=apps/game-server -- <lexicon.json>` |

政治类词条**不随仓库发布**：内置表只有中性占位条目，真实词条必须由合规清单提供，写成外置文件。
不配置 `GAME_MODERATION_LEXICON` 时，政治类实际不会拦截任何内容。格式与上线流程见
[`docs/moderation/lexicon.md`](docs/moderation/lexicon.md)。

## 多园区

园区不是分片，是**并列的独立世界**：一座园区 = 一个 game-server 进程，之间没有任何连接。
这条能成立是因为每座园区只写自己的本地快照（ADR-0081），园区之间没有共享状态，
也就没有分片协议、路由表或一致性窗口（ADR-0043）。

- **列表**由服务端 `GAME_PARKS` 下发（JSON 数组：`id` / `name` / `ws` / `health`），
  客户端只持有 `parkId`，端点一律由白名单翻译。存档被改成 `?park=wss://evil` 只会回落到第一座园区。
- **入场**在 `/enter` 选，选完写 `niuma:park:v1`；之后打开域名直达那一座，园内右上角可随时切换。
  只配一座园区时 `/enter` 直接 307 到 `/play`，单机部署看不到这个页面。
- **兜底**：入场前探活一次。只配一座园区时不探活直接进；首选不可达就顶到可达的那一座并给出提示；
  全都不可达才如实显示「连接中断，正在重连」。
- **落点按园区隔离**：`niuma:session:v1` 带一个 `park` 字段，换园区时丢弃 resume，角色从新园区门口开始。
  不升 `v`——升版本会让所有老玩家的落点一起失效。
- **回滚**：`GAME_PARKS` 只留一项并重启 Web，选园页自动退化成单卡片直接进入，代码不动。

部署（主站机器与游戏服机器的角色分配、环境变量、nginx、扩容清单、探活与故障排查）见
[`docs/deploy-multi-park.md`](docs/deploy-multi-park.md)。

## 已知边界

不含多地图、好友私聊、跨园区同步、Redis 分片、完整反作弊、移动端虚拟摇杆；
地图只有一块手写矩形陆地，地形碰撞是静态几何，不含可破坏物与游泳；园区同事在**整块陆地**上均匀采点随机漫游，
不走全图寻路（A* / 导航网格），卡住靠换落点与原地休息；美术是脚本生成的像素画，
替换 `apps/web/public/sprites/` 下的图集与 `manifest.json`（`version: 7`：64×64 帧、34 列、`origin`、
20×20 配件与 clips 结构）即可接入正式美术。
