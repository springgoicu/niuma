# ADR-0081：服务端时钟为唯一时间源，园区共享运行态写本地快照

- 状态：已采纳，**取代 [ADR-0004](0004-no-persistence.md) 第 1 条的「不写磁盘」边界**；
  ADR-0004 的身份与会话部分（无账号、断开即回收）继续有效
- 日期：2026-11-15
- 关联：[ADR-0034](0034-client-session-snapshot.md)（浏览器会话快照，仍然只有浏览器存本人数据）、
  [ADR-0043](0043-multi-park-deployment.md)（多园区）、[ADR-0052](0052-badge-career-summary.md)（考勤摘要）、
  [ADR-0054](0054-leaderboard-board.md)（牛马榜）、[ADR-0057](0057-badge-likes.md)（工牌点赞）、
  ADR-0061（上香日）

## 背景

三件事各自独立、合起来互相放大：

1. **时间口径散在两端。** 擂台倒计时、老板跨日回满、考勤的「今日/本周」、上香日、节日与季节判断，
   有的用服务端 `Date.now()`，有的用浏览器本地日历。玩家电脑慢 10 分钟、系统时区在 UTC-5，
   就会看到「擂台还剩 130 秒」「今天工时 0」——与邻座完全对不上。
2. **共享状态全在进程内存。** 一次发版重启，老板血量凭空回满、点赞全归零、擂台局号从 1 重新数，
   而这三样恰恰是玩家会记住的「园区发生过的事」。
3. **ADR-0004 的零持久化是针对「玩家身份与聊天」立的**，不是针对「园区公共设施」。
   把老板血量当成 PII 一样不落盘，收益是零，代价是每次重启都重置世界。

## 决策

### 1. 服务端只有一个时钟源

`apps/game-server/src/clock.ts` 在启动时把时区偏移解析一次（`GAME_TZ_OFFSET_MIN` 优先，缺省取宿主机），
之后 `now()` / `serverSec()` / `nextMidnight()` 全从它取；`now` 可注入，测试不用等真实时间。

- **固定偏移，不进夏令时**：园区不是跨洲业务，一个偏移足以让「今天」在所有人眼里一致；
  引入时区库只会换来 DST 边界上的偶发错位与一份新的运行时依赖。
- 老板回满、擂台阶段截止、限频窗口、会话续算、落盘时间戳，全部用这个时钟。
  `Date.now()` 在服务端只保留在纯日志与测试里。

### 2. 时间随心跳下行，不新增 opcode

`S2C_PONG` 尾部追加 `[serverSec u32][tzOffsetMin i16]`（6 字节），旧客户端 `decodePong` 只读前 5 字节，
尾段天然被忽略；心跳本就 1Hz，等于免费拿到 1Hz 的对时样本。秒级 epoch 而不是毫秒：
u32 秒到 2106 年才溢出，毫秒会在 49 天后回绕。

客户端（`lib/game/server-clock.ts`）不存「偏移」，只存「某次对时那一刻的服务器时刻 + 当时的单调时钟读数」，
之后用 `performance.now()` 自增，系统时间被改也不会跳。样本按 `serverSec*1000 + 500 + rtt/2` 换算，
偏差超过 1s 直接对齐，1s 以内按 EMA(α=0.2) 收敛。

### 3. 客户端只负责显示

`serverNow()` / `serverDateKey()` / `startOfServerDay()` 等纯函数是唯一入口；考勤、行为统计日桶、
上香日、木鱼账本、告示板倒计时与跑马灯、擂台 HUD、聊天气泡时间、季节与冬景判断全部改用它。
`local-date.ts` 只保留给纯本机交互（面板返回键守卫、重连退避、日志）。

擂台**不回传 `endsAt` 字段**：客户端收到快照时记「收包时的服务器时刻 + 剩余毫秒」，
HUD 用两者之差显示，误差是半个 RTT——120 秒倒计时可以忽略，
而给 `decodeRing` 追加字段会让未刷新客户端整包丢弃（它对尾字节直接抛错）。

时钟跳变超过 5s 时通过 `subscribeClockJump` 通知：按绝对时刻区间记账的模块（考勤）必须重设游标，
否则一次 2 小时的纠偏会被记成一整段在岗。

### 4. 落盘范围只有「园区共享运行态」

| 落盘 | 不落盘 |
|---|---|
| 老板血量 + 下一次回满时刻 | 玩家昵称、外观、状态、坐标 |
| 擂台局号 + 上一局名次摘要 | 聊天、在线时长、考勤、行为累计 |
| 匿名设备档案：赞数与擂台名次 | 会话、令牌、排队状态 |

判据是**它是不是园区公共设施**：老板和擂台是所有人共享的一个东西，重启清零就是世界重启；
昵称与考勤是本人的，属于 ADR-0034 的浏览器快照。

点赞的身份键是**客户端生成的匿名设备号**（16 位小写 hex，存 `localStorage`，随 `C2S_HELLO` 尾部
`[0xf8][8B]` 上报）：改名不丢、换浏览器重来、不做账号、不提供找回。宁可错合并同一台浏览器的数据，
也不引入登录。

### 5. 介质是单文件 JSON + 原子写

`GAME_STATE_PATH` 默认 `data/world-state.json`，v1 带 `version` / `savedAt` / `tzOffsetMin`。
写盘串行化：临时文件 → `rename`，读到的永远是完整 JSON；先写 tmp 再改名，避免半截文件被当成有效档。

- 变更只 `markDirty()`，1s 防抖合并；绝不在 Tick（50ms 预算）里同步写盘。
- 退出、SIGINT、SIGTERM 走 `flushSync()`，关服不丢最后一帧。
- 读档失败只 `console.warn`（路径 + 错误码，不打完整 JSON），坏档改名 `.bad-<时间戳>` 后空档开服。
- **`GAME_STATE_PATH` 留空 = 完全关闭持久化**，回到「纯内存」行为，供排查与灰度。

### 6. 重启恢复的语义

- **老板**：`resetAt` 未过期就沿用血量；已过期按当前服务器日重算并满血。不会「重启送一条新血」。
- **擂台**：只恢复 `matchId` / `nextMatchId` / `lastMatch` 摘要，阶段强制 `idle` 并清空名单。
  停机时参赛者的连接全断了，复活「幽灵比赛」只会让下一个人空等 120 秒。恢复摘要每进程一行日志。
- **档案**：设备号 → `{likes, gold, silver, bronze, name, lastSeenAt}`，上限 `GAME_STATE_MAX_PROFILES`（默认 512），
  超出按「最久未见」淘汰，另有 90 天过期；查找 O(1)。

### 7. 回合不重复写盘

`RingRuntime` 暴露 `revision`（只在真正改变名单/阶段时 +1），`server.ts` 对比指纹后才 `markDirty()`：
1Hz 心跳刷新快照不会变成 1Hz 写盘。

## 后果

- 正面：
  - 电脑时钟不准或人在别的时区的玩家，看到的倒计时、「今天」的工时、老板刷新点与园区一致；
  - 发版重启后老板血量、擂台局号、自己收到的赞延续，「一夜回到解放前」消失；
  - 协议全部尾部追加，旧客户端混部不炸；`decodePong()` 签名不变，旧调用点零改动；
  - 零新增第三方依赖，落盘成本只有一次 `rename`。
- 负面：
  - 磁盘上多了一份匿名数据（设备号是随机的，不含任何 PII），需要随部署机器一起备份/迁移；
  - 固定时区偏移意味着园区跨时区部署时只能挑一个「园区时间」，两端都按它算；
  - Worker 与主线程各持一份时钟实例，靠 `WorkerToMain { t:'clock' }` 低频同步（5s 节流），
    精度上限是半个 RTT + 转发间隔；
  - 重启期间的擂台被收尾为 idle，不保留「打到一半」的局。
- 回滚成本：低。`GAME_STATE_PATH` 留空即关闭持久化；时间下行段留着只用于显示，
  客户端退回 `localDateKey` 也能跑（`decodePongClock` 读不到尾段时返回 `undefined`）。

## 复核信号

- [ ] 出现「跨园区共享老板血量 / 跨园区排行榜」→ 单文件快照不够，要重新评估共享存储与 ADR-0043。
- [ ] 玩家要求「换设备继续自己的赞」→ 需要账号或可迁移凭据，推翻本文「不做账号」的前提。
- [ ] 快照文件超过几十 MB，或写盘把 Tick p95 推过水位 → 需要分表、分文件或改增量写。
- [ ] 出现「园区要跨时区」的需求（例如海外园区）→ 重新评估固定偏移与 DST。
- [ ] 时钟对时被玩家利用来刷考勤（跳变重设游标）→ 需要把在岗结算也搬到服务端。
