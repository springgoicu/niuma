# ADR-0110：骰桌台账——公开结算单、按设备归户的战绩与排行榜

- 状态：已采纳
- 日期：2026-11-16
- 关联：骰子馆玩法与座位门禁 ADR-0087 / ADR-0093 / ADR-0104；园区共享运行态落盘 ADR-0081；
  玩家可见文案去赌化 ADR-0111；协议追加规则见 `README.md`「线协议」

## 背景

改之前，一局结束时只有玩家自己的余额变化：中奖者看到钱包变大，落败者什么也看不到，
同一桌谁猜中、谁亏了多少全靠猜。骰桌没有任何跨局记录，服务重启即清零；
想比较「谁手气好」只能现场围观。产品要求把这件事变成可回看、可比较的公开数据。

约束：

- 服务端权威（ADR-0104），客户端不许自行推算金额；净盈亏必须等于真实入账减本金。
- 匿名设备号是唯一稳定身份（ADR-0081），但它不能出网，也不能出现在任何包或名单里。
- `S2C_DICE_STATE (0x47)` 是 1Hz 心跳的一部分，结构定长（2 + 17n 字节），不能变长。
- 榜单查询要扫全量账本，不能进 Tick 热路径。

非目标：不做实时赔率、不做跨服榜、不做玩家间转账、不做战绩清零/重置入口。

## 决策

### 1. 结算是「持久化的事实」，不是一次性的副作用

`dice-hall.settle()` 的三条路径（无人投入 / 命中档没人投入退款 / 正常分池）都构造同一条
`DiceRoundRecord` 写进 `DiceLedger`：局号、三颗骰、命中档、查岗标记、结束时刻，
以及逐人的 `bet / payout / net / refunded`。

`net` 一律取 `EconomyPorts.payout()` 的真实入账减去本金，绝不用 `splitPool()` 的理论分配值：
查岗 5% 服务费、`payoutFromPool` 内部先扣本金再分配的顺序，都会让理论值与真实入账不一致。

### 2. 亮牌期公开逐人明细，身份只到昵称

`S2C_DICE_RESULT (0x5b)` 在亮牌时**逐人**下发同一张结算单，服务端在每个人的包里标好
`self`（flags bit1）。不广播同一包的原因：昵称允许重名，客户端无法可靠自识别，
而「哪一行是我」只有服务端知道设备号与玩家对象的映射。

包内字段只有昵称、档位、投入额、到手与净额；`deviceId` 既不出网，也不写进落盘快照。

### 3. 战绩按设备号归户，容量与淘汰自管

`DiceLedger` 以 `deviceId` 为 key，累计 `rounds / wins / losses / refunds / totalBet /
totalPayout / net / bestWin`，并按桌各记一份；逐局环形缓冲每人 20 条、最新在前。

- 还款/退款局计入局数但不计胜负，不进胜率分母。
- 上限 200 人，超过按 `lastSeenAt` 淘汰最久未见者（榜单本来就是「最近在玩的人」）。
- 落盘时剥掉会话期字段（`playerId`），读档后不会把某个新会话误标成「我」。

### 4. 协议只追加：0x5b / 0x5c / 0x5d，`0x47` 零改动

`0x5b` 结算单、`0x5c` 拉榜请求、`0x5d` 榜单快照。`0x4d`–`0x50` 与其它留空编号不回收，
未升级客户端对未知 opcode 走既有忽略分支。

「我的战绩」与排行榜共用一次拉取：`0x5d` 在榜单行之后追加 `[hasSelf u8]` + 三份累计口径
（总榜 / 翡翠桌 / 鎏金桌）+ 最近 20 局历史行。原因是本人面板与榜单页签在同一弹窗内，
分两个包就要两次冷却、两次扫账本，而 self 段只有 80 + 20×20 字节量级。

### 5. 榜单按需拉取 + 每玩家 2s 冷却

不进 Tick、不进心跳：玩家打开页签才发 `0x5c`，服务端按玩家做 2s 令牌桶（独立于互动上行闸门），
命中冷却回 `S2C_INTERACT_REJECT (0x5a)`，客户端把 `pending` 复位并提示手动刷新。

排序口径：

- 净收益榜按 `net` 降序，同额按局数降序、再按最近活跃；
- 胜率榜按 `wins / (rounds - refunds)` 降序，分母为 0 的玩家置底并显示「—」；
- 本人不在前 20 名时补一行，保留真实名次，列表尾部用虚线标注「本人补行」。

### 6. `world-state.json` 升到 v4

新增 `dice` 段（`players[]` + `lastRounds[]`），由 runtime 直接转出 `DiceLedgerSaveState`，
persist 层不重复定义类型。读档接受 v3：缺 `dice` 按空账本接管；坏行只丢自己，不隔离整个档案。

## 备选方案

| 方案 | 为什么没选 |
|---|---|
| 把结算直接塞进 1Hz 的 `0x47` | 心跳每包都要带逐人明细，体积随在线人数涨；旧客户端还会解码错位 |
| 榜单广播给全桌，靠昵称判断「我」 | 重名即标错；且每次结算都要给所有人重算排序 |
| 战绩只存浏览器 `localStorage` | 换设备就清零，做不出「全员同一份榜」；与产品要求的跨重启保留冲突 |
| 单独开一个 `0x5e` 拉「我的战绩」 | 面板要多一次请求与冷却，服务端多扫一遍账本，收益只是包更小 |

## 证据基线

```
APIBASELINE | S2C_DICE_STATE 0x47 | expected: 定长 2+17n、1Hz 不变 | observed: 未改动 | fit: align
DATABASELINE | world-state.json | expected: 版本化 + 缺段容错 | observed: v4 新增 dice，v3 可读 | fit: align
QUALITYBASELINE | 1Hz Tick | expected: 结算写账本 O(参与者)，不扫全量 | observed: settle 只追加本轮；榜单独立路径 | fit: align
SECBASELINE | 身份 | expected: deviceId 不出网 | observed: 结算包/榜单包无该字段，落盘剥 playerId | fit: align
```

## 后果

- 玩家侧：亮牌即出结算单，落败者也能看到谁赢了多少；面板可查累计战绩与逐局记录；榜单跨重启保留。
- 服务端：多一份 200 人上限的账本与一个查询入口；每局多一次 O(参与者) 写入，与既有分池同阶。
- 成本：包体积增加（结算单最多 12 行，榜单 20 行 + 本人段），仍在单帧预算内。
- 已知取舍：设备号归户意味着换浏览器不继承战绩；这是匿名身份的既有边界，不在本 ADR 解决。

## 回滚路径（30 天内）

1. 客户端隐藏排行榜/战绩页签（只保留结算），不发 `0x5c`；服务端保留 `0x5b` 与账本写入。
2. 若账本写入出问题：`collect` 输出空 `dice` 段即可让 v4 文件退化成「有段无数据」，无需降版本号。
3. 若需彻底回到 v3：把 `WORLD_STATE_VERSION` 改回 3 时，读档分支要同时接受 4 并忽略 `dice` 段；
   现有的 `normalize` 已按版本号分支，回退时删掉 v4 分支会让老档案被判成坏档，必须一起改。
