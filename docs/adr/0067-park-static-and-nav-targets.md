# ADR-0067：游乐园转静态观赏区、导览目标扩到 11 处、滑梯协议号永久留空

- 状态：已采纳
- 日期：2026-11-13
- 关联：沿用 ADR-0036（HUD 园区导览与指路牌）、ADR-0040（自动寻路与可站立到达点）、
  ADR-0047（中央广场与三湖）、ADR-0049（中央四向指路牌）、ADR-0064（矩形边界）；
  废止此前未立 ADR 的滑梯互动链路（`C2S_SLIDE` / `S2C_SLIDE` / `sim/ride`）

## 背景

同一次需求里有三件事互相咬合：

1. 导览只认四角房，玩家想去游乐园、摸鱼亭或三处景观湖时没有「去这里」入口；
2. 用户希望**删掉互动逻辑**，但明确限定只删游乐园滑梯——售货机、饮水机、咖啡机、
   公告栏、财神、茶台与入座 / 躺平全部保留；
3. 游乐园被要求「加新器械 + 装饰」，从一片只有滑梯与三个小器械的空地变成能逛的观赏区。

关键约束：滑梯造型（精灵与碰撞底座）要保留，只摘掉点击 / F 键与滑行结算。
这意味着「删互动」不是删美术，而是删掉一条**跨服务端的状态机**。

## 决策

### 1. 滑梯只留造型与碰撞，互动入口整体下线

- 共享契约里 `SlideSpec` 收窄为 `SlideArt`（`hit` / `top` / `landing` / `chute`），
  不再有 `id`、时长、交互半径与插值函数；`PARK_SLIDE.chute` 只用于画折线；
- 删除 `SLIDES` / `slideById` / `slidePointInto` / `SLIDE_RUNS` / `chuteLengths` /
  `directionOf` / `SLIDE_INTERACT_RANGE` / `SLIDE_COOLDOWN_MS`；
- 服务端删除 `sim/ride.ts` 与玩家上的 `rideSlide` / `rideEndsAt` / `lastSlideAt`，
  移动包不再丢弃滑行输入，`vent` 不再给滑梯位置开免伤与免出招后门；
- 客户端删除 `isSlideHit` / `isNearSlide`、`HINT.slide`、`ride` 事件变体、
  滑行音效与 `session` 里五个滑行方法与全部状态门。

### 2. 0x2a / 0x2b 永久留空，不复用编号

`C2S_SLIDE = 0x2a` 与 `S2C_SLIDE = 0x2b` 直接删除，同时在 `OpCode` 里留注释：
两个号段此后不再分配给任何新报文。理由是本仓库客户端是唯一消费者且服务端零持久化，
复用号段只会在旧标签页与新服务端之间造出「解码到错误语义」的窗口；
留空 2 个号段的成本是零，排障成本却是无穷。

### 3. 导览目标从 4 处扩到 11 处，HUD 按 `area` 分组

- `NavTargetId` 增至 11 项：四角房（`workroom` / `meeting` / `restroom` / `lounge`）
  + 游乐园 / 研发园 / 家庭影音室 / 摸鱼亭 + 三湖（摸鱼湖 / 沉思浅塘 / 涟漪湖）；
- `NavTarget` 新增 `area: 'indoor' | 'grounds'`：`x` / `y` 仍是区域几何中心，
  只供方位角与步行秒数；`arrive` 才是 A* 的真正终点；
- `NAV_ARRIVALS` 从 `campus.ts` 迁进 `layout.ts`，与 `NAV_SOURCES` 同文件相邻，
  避免「目标加了、到达点忘了」；7 个户外到达点全部落在陆地、避开器械底座与门洞；
- 导览卡列表按 `area` 分两组，列表 `max-h` 内滚动、组标题 `sticky` 吸顶：
  11 行平铺会把竖屏画面挤掉，滚动只吃指针不吃 WASD。

### 4. 指路牌仍只列 5 个园区级目的地

牌面尺寸锁在 96×92（ADR-0049 的画布），11 个目标塞不进去。取舍：

- 指路牌（世界内、需走近读）只列游乐园 / 研发园 / 家庭影音室 / 摸鱼亭 / 摸鱼湖 五块，
  行距 13px、字号 8px，方位按 id 现算；
- 细分的三湖与四间房交给 HUD 卡（屏幕内、随时可读、可点击导航）。

指路牌是「告诉你这片园区有什么」，不是完整目录；完整目录只存在于 HUD。

### 5. 游乐园补 4 件静态大件与装饰

- `PARK_ATTRACTIONS`（摩天轮 / 小火车 / 沙池 / 喷泉）以「中心 + 宽高」写在共享布局，
  渲染层不写第二份尺寸；大件底座进 `WORLD_LAYOUT.solids`，只压最下面一条，
  玩家仍能从正面走到跟前；
- 装饰（彩旗、气球、彩灯串）全部走 `bake` 烘焙纹理，不进碰撞、不进 y 排序
  （灯串贴地面层），无逐帧计算；
- 坐标手排并用测试兜住：四件器械在园区内、两两留 20px 通道、不挡两处门洞与滑梯落点；
- 摩天轮辐条与吊舱用手写查表偏移，不引入三角函数（沿用布局层「禁止 sin/cos」纪律）。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 保留滑梯互动，只删其他 | 少动协议与模拟层 | 与「删互动」诉求相反，且滑行状态机是服务端唯一的多帧位移状态 | 否决 |
| B. 删滑梯美术，只留空地 | 改动最少 | 东门地标消失，园区辨识度下降 | 否决 |
| C. 滑梯降级为纯装饰 + 删 0x2a/0x2b + 新增 4 件静态器械（采纳） | 契约变薄、无跨帧状态、观赏区成形 | 一次性跨 4 个包（shared-types / game-server / web / 测试） | 采纳 |
| D. 导览牌直接列 11 个目标 | 世界上也能看全 | 92px 牌面放不下，缩字到 6px 不可读 | 否决 |

## 后果

- 协议层少 2 个 OpCode、2 对编解码、4 个常量；模拟层少一整个 `sim/ride`，
  `advanceRides()` 从主循环消失；
- `NAV_TARGETS` 是导览卡、指路牌、A* 与测试的唯一真相，加目标只需改
  `NavTargetId` + `NAV_ARRIVALS` + `NAV_SOURCES` 三处（同文件相邻）；
- 游乐园从「一处互动设施 + 三个小器械」变成「一条可逛的静态动线」，
  后续再加设施只需追加 `PARK_ATTRACTIONS` 条目与对应 `draw*`；
- 回归口径：`nav-arrival.test.ts` 断言 11 个到达点可站立、不撞墙、不落水；
  `theater-park-layout.test.ts` 断言四件器械在园区内、两两留 20px、底座不挡门；
  `pathfinding.test.ts` 断言 11 个目标从出生点与广场中心皆可达；
- 回滚：滑梯侧从 git 历史恢复 `sim/ride.ts`、`C2S_SLIDE` / `S2C_SLIDE` 与
  `session` 的滑行分支即可（协议号未被复用，回滚不会撞号）；导览侧把
  `NavTargetId` 收窄回 4 项并删掉 `NAV_ARRIVALS` 的户外条目，HUD 分组自然退化为单组。
