# ADR-0042：纯客户端园区小动物与蝴蝶

- 状态：已采纳
- 日期：2026-11-11
- 关联：沿用 ADR-0005（像素网格与 nearest）、ADR-0013（构造期烘焙）、
  ADR-0017（草地才是地面）、ADR-0021（整纹素吸附）、ADR-0024（分桶深度排序）；
  不改 ADR-0003（AOI）、ADR-0012（海岸即墙）与任何协议条目

## 背景

园区有 214 棵树、四片花海、七片林地与大片空草地，但除了玩家之外没有任何活动的东西。
用户要求「地图上创建一些随机跑的小动物，小兔子、小猫小狗等，增加丰富度，还有蝴蝶」，
并明确要求**最佳性能**。

约束：

- 世界是服务端权威的静态布局，客户端只负责呈现；
- 已有一条二进制协议与 20Hz Tick 预算，任何新增同步都会挤占广播带宽与 Tick 时间；
- 美术全部是脚本生成的像素画，没有外部素材管线可挂；
- 帧循环纪律是「运行期零分配、零纹理生成」（ADR-0005 / ADR-0024）。

## 问题

### 1. 同步 or 不同步

小动物如果进协议，需要新的 OpCode、服务端游走模拟、AOI 订阅与广播。
按 200 人最坏情况估算，每只动物每 Tick 7 字节 × 90 只 × 20Hz ≈ 126 KB/s 的单客户端下行，
而当前容量预算是 320 KB/s。收益只是「不同玩家看到同一只兔子」，
对氛围类内容没有可感知价值。

### 2. 走角色图集管线 or 自建小图集

`packages/pixel-assets` 是 64×64 帧、34 列、九层灰度 tint 的换色管线，
为玩家角色而生。小动物只需要「认得出物种 + 三套配色」，
走那套管线意味着扩 `layout.ts` 的列预算、重跑 `pnpm assets`、升 manifest 版本，
并且要双端一起发版——成本远大于收益。

### 3. 全量模拟 or 视口内模拟

72 只动物每帧跑状态机 + 碰撞查询，在低端机上是白白烧掉的 CPU：
玩家一屏最多看到 3–8 只，其余 90% 的模拟结果永远不可见。

## 决策

### 1. 纯客户端氛围，零协议改动

小动物与蝴蝶只存在于本地渲染层：每局用 `Date.now()` 当种子生成，
不写存档、不进 AOI、不占 Tick。不同玩家看到的个体与位置不同，这是**接受**的取舍。

### 2. 自建 32px 单图集，一次烘焙

`critter-art.ts` 用一个 `Graphics` 画满 12×10 个 32px 格，只调用一次 `generateTexture`：

- 地面：3 物种（兔 / 猫 / 狗）× 3 配色 × 3 视图（正 / 侧 / 背）× 4 帧（站立 / 吃草 / 走 A / 走 B）= 108 格；
- 蝴蝶：3 配色 × 2 帧（翅开 / 翅合）= 6 格；
- 脚底线固定在 y=29，精灵锚点 `(0.5, 29/32)`，接触阴影直接烘进帧里；
- 侧面永远朝右，朝左用 `scale.x = -1` 镜像，省下一半帧预算；
- 帧动画只是换纹理引用，不做缩放 / 旋转 / 补间。

所有帧共用同一个 `TextureSource`，绘制时天然合批。

### 3. 视口内才模拟

`CritterField.update` 每帧只做一次矩形判断：屏外（含 96px 余量）的动物
`visible = false` 并**跳过状态机**，回到视野内再从原状态继续。
同屏通常 2–4 只，实际参与模拟的就是这几只。

### 4. 软避障而不是寻路

`critter-motion.ts` 是纯函数状态机：`idle`（站立 / 吃草）→ `wander` → `idle`，
玩家进入 88–104px 时切 `flee`，逃跑后 1.8s 冷却。
移动每 100ms 探一次身前 10–16px 的点（`!isBlocked(p,4) && !isWadingAt(p)`），
被挡就右转 / 左转 / 掉头，全挡就停下吃草。
不做 A*：氛围内容不需要绕整座岛，只需要「看起来在躲人和不会进水」。

### 5. 深度与图层

地面动物按脚底 y 进 `SortLayer`，与树、桌椅、角色共用同一套遮挡；
蝴蝶飞在空中，单独一层插在 `sortLayer` 与 `labels` 之间。
**不把动物喂给 `syncOccluders`**：让树冠为一只兔子变透明会干扰玩家判断，
而且收益为零——动物本来就应该被树挡住。

### 6. 撒点有界

`critter-spawn.ts` 把岛按 320px 切格，每格最多一只、最小间距 80px、每格最多 12 次尝试；
落点必须通过 `isOutdoorGround`（与草地贴花同一份判定）与 `isBlocked`。
生境权重只影响「落在这个格子里的是谁」：兔靠花海与林地、猫靠园路与广场、狗留在开阔草地。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| 服务端同步 | 全服一致 | 新协议 + Tick 模拟 + 带宽，约 126 KB/s | 否决 |
| 复用角色图集换色 | 零新增美术代码 | 扩列预算、重跑图集、升 manifest、双端发版 | 否决 |
| 每只动物一个独立纹理 | 实现简单 | 破坏合批，90 个 `TextureSource` | 否决 |
| 全量模拟 + 全量绘制 | 状态永远连续 | 72 只每帧碰撞查询与绘制 | 否决 |
| 本方案 | 零协议、零服务端、+2 批次 | 玩家之间看到的动物不同 | 采纳 |

## 后果

**性能预算（验收口径）**

| 项 | 预算 | 实测手段 |
|---|---|---|
| 纹理 | 1 张 384×320，1 次 `generateTexture` | `?critters=debug` 打印构造耗时 |
| 精灵 | 90（地面 72 + 蝴蝶 18），屏内 2–8 | 同上 |
| 每帧 CPU | ≤ 90 次包围盒判断 + 可见者状态机 | 关闭开关对比 FPS |
| 绘制批次 | +1（地面动物）、+1（蝴蝶） | 共用同一 `TextureSource` |
| 初始化 | ≤ 8ms | `?critters=debug` |

**代价**

- 不同玩家看到的动物不同，无法「一起摸同一只兔子」；
- 屏外动物状态冻结，回到视野时从原状态继续（不可见，无观感损失）；
- 动物不具备玩家那种配件 / 换色能力，只换三套调色板。

**回退**

`?critters=0` 时整层不构造：烘焙、撒点、精灵、纹理全部不发生，与 `?flat=1` / `?light=0` / `?bands=0`
是同一套灰度开关惯例。`?critters=debug` 额外打印人口、图集尺寸与构造耗时。

## 测试

- `__tests__/critter-spawn.test.ts`：同种子可复现、人口达标、落点合法、间距 ≥ 80px、蝴蝶轨道在预算内；
- `__tests__/critter-motion.test.ts`：待机→游走、受惊方向背离玩家、冷却不重复触发、
  被挡换向 / 停住、离巢回拉、视图随位移方向切换、蝴蝶始终在椭圆轨道上；
- `__tests__/critter-art.test.ts`：用记录型 `Graphics` 断言每一笔都落在自己的 32px 格内、
  114 个帧号全覆盖、地面与蝴蝶帧号不重叠。
