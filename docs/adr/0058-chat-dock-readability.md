# ADR-0058：聊天面板的可读性优先于透视感

- 状态：已采纳
- 日期：2026-11-12
- 关联：部分取代 ADR-0041 第 4 节「半透明毛玻璃」；保留 ADR-0041 的常驻、贴底与展开态持久化，
  保留 ADR-0033 的移动端发送后收键盘与高度互斥，ADR-0056 的发送侧设置（颜色 / 模式 / 快捷词条）不变

## 背景

线上反馈原话：「左下角发送弹幕的框太马赛克，显示的不清楚，放大些或者怎么优化」。

ADR-0041 把面板底定成 `bg-ink-900/65` + `backdrop-blur-md`，目的是让左下角透出游戏画面。
但面板内的字是 9–11px 等宽字：像素风画面本身就是高对比小色块，12px 模糊把噪点抹成斑块，
再透过 35% 的透明度叠到字后面，观感就是「马赛克」。同时 JetBrains Mono 没有中文字形，
中文会落到浏览器的等宽回退字体，中英混排在小字号下发虚。

## 问题

1. **字号过小**：输入框 11px，工具栏、时间戳、分隔线 9px。1x 屏与 Windows 125% 缩放下都会糊。
2. **背景透字**：65% 墨底 + 12px 模糊，像素噪点与文字抢对比度。
3. **字体错配**：中文散文套在等宽字体上，回退字形与拉丁字母不同源，行内高低不齐。
4. **命中区域小**：输入框约 29px 高，发送键 36px，低于触屏与鼠标都舒服的 44px。

## 决策

### 1. 桌面档字号整体上调一档，窄版完全不动

| 位置 | 现状 | 目标 |
|---|---|---|
| 输入框 | `text-[11px] px-2.5 py-1.5 font-mono` | `text-[14px] leading-6 px-3 py-2 font-sans` |
| 发送键 / 图标 | `h-9 w-9` / `h-3.5` | `h-11 w-11` / `h-4` |
| 面板宽 | 340px | `340px`，`lg` 起 380px |
| 标题 / 计数 / 未读 | 10 / 9 / 9px | 11 / 10 / 10px |
| 色块按钮 / 色块 | `h-5` / `h-4` | `h-6` / `h-5` |
| 模式键、快捷词条 | 9px | 10px |
| 消息正文 / 昵称 / 时间 | 12 / 10 / 9px | 13 / 11 / 10px |
| 系统消息 / 分隔线 / 加载 | 10 / 9 / 9px | 11 / 10 / 10px |
| 列表高度上限 | `min(46dvh, 340px)` | `min(48dvh, 360px)` |
| 齿轮 / 设置浮层 | `h-7` / 220px | `h-9` / 248px |

所有新尺寸都写在 `compact === false` 分支：`ChatInput` 与 `DanmakuHUD` 新增可选 `compact`，
由 `ChatDock` 已有的 `compact` prop 统一下传。移动端 250px 面板输出的类名与改动前逐字一致。

### 2. 面板底压实到 88%，模糊降到 4px

`bg-ink-900/65 backdrop-blur-md` → `bg-ink-900/88 backdrop-blur-sm`（仅桌面档）。
画面仍能感知（12% 透光），但不再是一层噪点；顺带降低 `backdrop-filter` 的采样成本。

### 3. 中文散文去掉 `font-mono`，数字保留

输入框、消息正文、系统消息、空态、分隔线、加载提示在桌面档改用 `--font-sans`；
时间戳、计数、昵称、模式标签继续等宽，列对齐与数字观感不变。

### 4. 输入行统一到 44px

14px 正文 + `leading-6`（24px）+ `py-2`（16px）+ `border-2`（4px）= 44px；
发送键 `h-11 w-11` 同为 44px，两者在 `items-center` 下等高。

### 5. 面板宽度只在 `lg` 以上加宽

桌面底栏是「聊天 + 居中动作条 + 小地图」的 `justify-between`，小地图只在 `lg` 出现，
所以加宽也只在 `lg` 生效；md 区间保持 340px，避免把动作条挤成多行。

## 备选方案与反向成本

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 只放大输入框一行 | 改动最小 | 消息列表仍是 12px/9px，读记录照样累，「整块面板看不清」只解一半 | 低 |
| B. 整块提档 + 底色压实（采纳） | 一次收口字号、字体、透字三件事 | 面板透光降低，左下角画面感知变弱；桌面宽 40px | 低 |
| C. 加「界面字号 小/中/大」设置 | 用户可自选 | 多一个存储键与三套尺寸分支长期维护，且默认值 9px 依然是坏的 | 中 |
| D. 面板改全实底 | 最清楚 | 回到 ADR-0041 之前那块实心墨块，左下角画面被整块盖住 | 低 |

选 B。默认值必须自己站得住，把「看不清」转成设置项只是把问题交给玩家。

## 后果

- 正面：左下角一眼能读；输入框与发送键达到 44px；中文不再落到等宽回退字形；
  弹幕设置浮层与齿轮同步放大，设置入口不再难点的。
- 负面：面板透光从 35% 降到 12%，左下角游戏画面的存在感变弱；
  1024–1279px 区间仍是 340px，只有 `lg` 以上才吃到加宽；
  桌面面板一屏能看到的对话轮数变化不大（字号变大 + 高度上限提高 20px 大体抵消）。
- 回滚：`ChatDock` 根节点改回 `bg-ink-900/65 backdrop-blur-md` 与 `w-[340px]`；
  四个组件里的 `*Skin` 常量各自改成单一字符串即可。不涉及存储、协议与状态，30 天内可随时回退。

## 复核信号

- 「面板又看不清了」：查 `ChatDock.shellSkin` 桌面分支是否被改回 65% / `blur-md`，
  或 `ChatInput.inputSkin` 桌面分支是否又加回 `font-mono`、字号小于 14px。
- 「手机上聊天框变大、把操作区挤爆」：查新尺寸是否漏进了 `compact` 分支。
- 「中文又糊了」：查桌面档的散文是否还挂着 `font-mono`。
- 「面板挡住动作条」：查 `lg:w-[380px]` 是否被下放到 md 区间。
