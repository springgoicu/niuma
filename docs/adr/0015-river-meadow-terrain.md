# ADR-0015：中心线河道、草地叠层与孤树 / 花海

- 状态：已采纳
- 日期：2026-11-02
- 关联：细化 ADR-0008（地形碰撞）、ADR-0010（尺度与栅格）、ADR-0012（海岛边界）、ADR-0013（暖色地形渲染）

## 背景

线上地图有三个结构性问题，都不是「贴图好不好看」这一层：

1. **河流是 5 段轴对齐矩形拼的**。中心线在 2712 → 2601 → 2488 → 2601 → 2712 之间做 90° 折返，
   段与段右边缘还有 2px 错位；南北两端分别停在 y=476 / y=7051，**断在草地中央**。
   玩家看到的是一条凭空出现、又凭空消失、中间拐了四个直角的蓝色条。
2. **河流没有河岸**。湖有 22px 沙滩，河只有硬切的水面，水面与草地之间没有任何过渡。
3. **草地被切成几块**。林下地面是不透明深绿矩形，看起来像「另一种地面」，
   而不是长在草地上的树荫；草地本身除了稀疏贴花之外没有树、没有花。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 保留阶梯矩形，只修 2px 与断头 | 改动最小 | 90° 折返仍在；矩形无法做河岸沙带；「错位」的根因没解决 | 低 |
| B. 中心线 + 河宽生成带状多边形（采纳） | 河道连续、河宽恒定；左右岸线可直接描沙；碰撞 / 渲染 / 小地图共用一份多边形 | 新增一个几何模块；斜接点在急弯处要限幅 | 低 |
| C. 手写左右岸顶点 | 不需要几何算法 | 两份顶点迟早漂移；改河宽要同步改 48 个点 | 中 |

选 B。河流的问题本质是「数据模型只能表达矩形」，而不是「矩形没摆放整齐」；
把数据模型换成中心线之后，桥、碰撞、渲染、小地图都退化成对同一个多边形的消费。

## 决策

1. **新增 `world/river.ts`**：`buildRiver(stations, halfWidth)` 在每个站点取相邻两段法线的
   角平分线（miter），按 `halfWidth / dot` 放大后取整。只使用 `+ - * /` 与 `Math.sqrt`
   （IEEE-754 正确舍入，JSC / V8 逐位一致），不引入任何三角函数或随机数，
   继续满足 ADR-0008 的双端确定性纪律。`RiverShape` 同时给出
   `polygon / leftBank / rightBank / centerline / rect`。
2. **河道贯通南北海**：中心线北端 `(2500, 40)`、南端 `(2490, 7990)`，两端各探进海里 60–110px；
   中段摆动 ≤ 60px（小于半个河宽），河口因此不再断在草地上。
3. **桥段用直行约束解耦**：`y 3920–4300` 中心线固定 `x=2488`、半河宽 112，
   水面恒为 `x 2376–2600`；现有木桥 `x 2336–2640` 两侧各余 40px，
   `isOnBridge` 与 `blocker.water` 的放行逻辑一行未改。
4. **渲染改成「沙带 + 多边形遮罩水面」**：两条岸线各描 48px 沙色 + 4px 浅沙，
   **只画岛内的一段**（河口不封口，不会在海面上横一条沙坝）；水面是 1 个
   `TilingSprite` + 多边形遮罩，`tilePosition` 按世界相位对齐、按 `axis:'y'` 顺流滚动。
   原来的 5 个矩形水面精灵降到 1 个。
5. **草地是唯一基底**：林下地面改为 `forestFloor @0.55` 的半透明草色层，
   花田是 `meadowTint @0.4` 的草甸色层；广场、土路、水面仍是叠在草地之上的元素。
   任何新地面都不得使用不透明实色矩形。
6. **孤树进入布局**：`WorldLayout.wildTrees`，240px 栅格 + 0.42 命中 + ±100 抖动，
   再做 170px 最小间距收敛。过滤条件复用 `isPlantable`，另加海岸 90px 留白、
   林地 40px、花田 40px、出生圈 520px。孤树与森林里的树一样注册 `circle` 碰撞体，
   并走同一套树冠遮挡。
7. **花海进入布局**：`FlowerPatch { rect, palette }`，三片草甸（白雏菊 / 金盏 / 暖粉），
   纯装饰、不参与碰撞。贴花图集从 4 帧扩到 7 帧（64×16 → 112×16），
   基础草地层仍只用前 4 帧（种子与命中率不变），野花层 `0.025` 混撒三种花，
   花海层 `0.4` 只撒该花田的配色——三色混撒会糊成噪点。
8. **水面判定收敛到一处**：新增 `isWaterAt` / `distanceSqToWater`（湖多边形 + 河多边形），
   `isPlantable`、草地贴花、测试全部改用它，不再对河流包围盒做矩形判断。
9. **小地图同源**：河道改画多边形，花田画草甸色块 + 三粒配色点，孤树与森林树共用 1px 点。

## 后果

- 正面：河流是一条连续、宽窄稳定、两端入海的缎带；河岸有沙带与芦苇；桥仍是唯一渡口。
  地图回到「一片草地 + 叠层元素」的读法，孤树提供地标，花海提供小面积色彩高潮。
- 负面：
  - `shared-types` 多了一个几何模块；`RiverShape` 的岸线是渲染专用数据，需与多边形同步维护。
  - 碰撞多边形从 5 个矩形（20 顶点）变成 1 个 48 顶点多边形，单次 `pointInPolygon`
    多约 28 次边判断；仍在 128px 网格索引内，压测 p95 未见变化。
  - 贴花精灵从约 1300 增到约 2000，孤树约 89 棵（+178 个精灵），全部走 `renderable` 裁剪。
  - 花海是三块矩形包围盒 + 有机轮廓，形状不规则但仍是「一块一块」的分布。
- 回滚成本：低。恢复阶梯矩形只需把 `RIVERS` 换回矩形数据并删掉 `addRivers` 的岸线分支；
  `wildTrees` / `flowerFields` 置空即可退回「只有三片森林 + 稀疏贴花」的旧观感
  （碰撞与遮挡会自动跟随数组长度）。

## 复核信号

- 出现「河口被沙坝堵住」：检查 `clipBankToLand` 是否漏掉了岸线末端，或沙带宽度是否超过
  `RIVER_SHORE * 2`。
- 出现「桥头卡人」：先看桥段三个站点的 `x` 是否仍为 2488，再看桥矩形是否仍比水面宽 40px 以上。
- 出现「树长进水里 / 花海里」：检查 `isPlantable` 的水面留白（95px）与花田 40px 留白是否同步。
- 出现「花海糊成噪点」：把 `FLOWER_FIELD_CHANCE` 从 0.4 降到 0.3，不要混入其它配色的帧。
- 出现「孤树太密 / 太稀」：只调 `WILD_TREE_CHANCE`，不要动 170px 最小间距——
  它同时负责「两棵树冠不叠成一坨」的观感下限。
- 200 人同屏贴花层批处理耗时上升：先降 `WILDFLOWER_CHANCE`，再降 `FLOWER_FIELD_CHANCE`，
  最后才考虑 `DECAL_CELL`（64px 与 32px 采样格是整数倍关系，改它要连带重算草缘）。
