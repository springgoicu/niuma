# ADR-0022：大厅倍率降到 1.5，地图向内收一圈

- 状态：已采纳
- 日期：2026-11-10
- 关联：修订 ADR-0010（尺度总则）、ADR-0012（海岛边界）、ADR-0015（地形加密参数）

## 背景

线上反馈集中在三条，都是「画面比例」而不是「画得好不好看」：

1. **人物太大**：大厅每纹素 3 CSS px，角色站立 48 纹素 = 144 CSS px，在 1080p 屏上占屏高 13%，
   走近一点就只剩一个背影；
2. **地图太空**：一屏只看到 426×266 世界像素，岛却有 6900×7780，广场到研发园之间、
   北湾以南、东岸与湖之间都是整片纯草地，走一段路看不到任何东西；
3. **物品太散、太大**：花箱 34×44 几乎与角色等高，长椅、售货机同样偏大，
   同类道具彼此隔着几百像素，摆出来像仓库而不是广场。

## 问题

这三条互相牵制：把角色缩小一半，一屏就能看到四倍面积，**空旷感只会更强**。
所以缩放必须与「地图收紧 + 内容加密」一起做，否则改完比改前更空。

真正的约束是 ADR-0005 的「每纹素占整数设备像素」：
`cssScale = devicePxPerTexel / DPR`，因此 CSS 倍率只能取 `round(base × DPR) / DPR`，
1.5 在 DPR 2 上正好整数（3），在 DPR 1 上只有 2（= 96px），在 DPR 1.5 上只有 1.333（= 64px）。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 只把倍率降到 1.5 | 一行改动，人物立刻变小 | 一屏面积 ×4，空旷感反而加重 | 低 |
| B. 只收紧地图与加密内容，倍率不动 | 通行感变密，不碰渲染 | 人物仍然 144px，反馈的「大」没解决 | 低 |
| C. 倍率 1.5 + 收岛 + 加密 + 缩小道具（采纳） | 三条反馈一次解决 | 世界坐标改动需双端同版本发布；道具要按纹素重画 | 中 |

选 C。单做任何一条都会把另一条放大：缩放加剧空旷，加密加剧拥挤，只有三者同向调整才收敛。

## 决策

1. **大厅倍率 3 → 1.5**（`renderer.ts` 的 `DEFAULT_CSS_PER_TEXEL`）。
   `pixelMetrics` 增加第三个可选参数 `minDevicePx`，大厅传 2；
   **不直接把 `MIN_DEVICE_PX` 改成 2**——`fitMetrics` 也读这个常量，会让角色创建预览台在窄容器下多降一档，
   而本次明确不动预览台。各屏实际高度：

   | DPR | 设备像素/纹素 | 角色高度 |
   |---|---|---|
   | 1 | 2 | 96px |
   | 1.25 | 2 | 76.8px |
   | 1.5 | 2 | 64px |
   | 1.75 | 3 | 82px |
   | 2 | 3 | 72px |
   | 3 | 5 | 80px |

   只有 DPR 2 精确落在 72px。不追求全平台统一，是因为非整数设备像素会让 1px 描边
   在相邻纹素之间轮流占 1/2 像素，那正是 ADR-0005 要消灭的「糊」。
2. **`?zoom=` 灰度开关**：`?zoom=3` 一键退回旧倍率，与 `?flat=1` / `?light=0` 同一写法。
   线上出现「角色太小看不清」的反馈时先切开关验证，再决定是否回滚发布。
3. **道具按纹素重画，禁用 `sprite.scale`**：花箱 34×44 → 26×34、售货机 42×60 → 34×48、
   告示牌 32×42 → 24×32、公告板 46×30 → 34×24、长椅 46×22 → 40×18、单车 46×24 → 38×20、
   野餐桌 48×40 → 40×34、路灯 16×46 → 14×40、垃圾桶 / 绿植 / 水槽同比微收。
   连带三处必须同改：`PLANTER_RADIUS` 16 → 12、`PLAZA_SOLIDS` 售货机 40×28 → 32×24、
   `PROP_SHADOW.planter` 30×12 → 22×10。**树不动**：108 texel = 角色 2.25 倍是 ADR-0010 的基准。
4. **地图向内收一圈**：内容包围盒本来就贴着海岸，所以顺序是「先移内容，再画海岸」——
   三片林地向内平移（西林只下移，东北林左移 500，东南林左上各 300 并卡在南中湾东壁）、
   湖整体左移 350、河道两端跟着新海岸缩短（北 40 → 400，南 7990 → 7690）、
   北与东两条尽头无目标的支路分别 540 → 400 / 640 → 480。
   岛从 6900×7780 收到 6470×7164（面积 −12%），四个海湾的开口全部保留。
   **聚簇内部尺寸一律不动**：门洞 120、广场 1120×936、研发园 2100×800、工位 88×40、房间 440×280。
   压这些会压坏通行宽度与工位排布，不是「紧凑」而是「挤」。
5. **空地加密**（真正解决空旷的那一半）：新增 4 片小林地（北门两侧、东湾与湖之间、办公区与研发园之间）、
   2 口小水塘（西岸、南中湾西侧，走 `lakes` 数组，自动接入碰撞 / 撒树留白 / 芦苇碎石 / 小地图）、
   2 片花海、1 个沿路休息角（两长椅 + 路灯 + 告示牌 + 垃圾桶 + 花箱）、
   广场花箱 4 → 8、研发园庭院 +2 野餐桌 +4 绿植。
   密度参数：`TREE_CHANCE` 0.6 → 0.7、`WILD_TREE_CELL` 240 → 160 与 `WILD_TREE_CHANCE` 0.42 → 0.72、
   `DECAL_CHANCE` 0.12 → 0.24。`DECAL_CELL` 保持 64——它是 32px 采样格的整数倍，改格要连带重算草缘。
6. **`VIEW_RADIUS` 900 → 1000**：倍率 1.5 时 2560 宽的屏横跨 1707 世界像素，
   半对角线约 979，900 会让屏幕四角的角色不进入视野。小地图的 168px 画布同步跟随。
7. **道具贴图按类型缓存**（`PropsView.propTextures`）：加密后同类道具会有几十个，
   逐个烘焙等于几十张同内容纹理，显存与初始化时间都会被放大。

## 后果

- 正面：一屏能看到「树 + 花 + 水 + 长椅 + 路灯」同框，走一圈不再有大段纯草地；
  角色约占屏高 1/10，与 Stardew 一类的俯视像素游戏同档；道具缩小后成组摆放读起来像生活痕迹。
- 负面：
  - **世界坐标是服务端权威碰撞与客户端预测共用的常量**，本次必须双端同版本发布，
    旧客户端连新服务端会被持续拉回（与 ADR-0010 同一条纪律）；
  - 一屏对象数 ×4，贴花从约 2000 增到约 4000、孤树约 90、林地 7 片，
    帧循环成本仍是 O(可见数)，但初始化期烘焙时间上升；
  - 昵称与气泡随 world 一起缩放，现在是约 13.5 / 12 CSS px：描边比例不变、清晰度不变，
    但确实更小，是否回调字号属于后续观感问题，不是本次的缩放取舍。
- 回滚成本：中。倍率有 `?zoom=3` 开关；布局没有运行时开关，回滚 = 恢复 `layout.ts` / `campus.ts`
  的常量并与服务端同时回退。

## 复核信号

- 出现「角色太小、看不清朝向」：先确认用户的 DPR。DPR 1 的屏上是 96px（−33%），
  DPR 1.5 只有 64px（−56%）——差异来自整数纹素纪律，不是 bug；真要统一只能放弃整数设备像素，
  那是另一个决策（ADR-0005）。
- 出现「屏幕四角的角色突然冒出来」：说明 `VIEW_RADIUS` 仍不够，按 2560@1.5 重算半对角线再加余量。
- 出现「帧率掉到 45 以下」：按 ADR-0015 的顺序降密度——先 `WILDFLOWER_CHANCE`，
  再 `WILD_TREE_CHANCE`，最后才动 `DECAL_CELL`（会连带重算草缘）。
- 出现「树长进水里 / 花海压到路」：检查新增林地矩形是否越过了海湾内壁，
  以及 `isPlantable` 的 95px 水面留白是否仍覆盖新水塘。
- 出现「人物贴着花箱穿模」：`PLANTER_RADIUS` 与 26×34 的视觉尺寸是一对，改贴图必须同步改半径。
