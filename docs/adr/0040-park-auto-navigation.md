# ADR-0040：园区导览自动寻路

- 状态：已采纳
- 日期：2026-11-11

## 背景

ADR-0036 把园区导览做成了「方位 + 步行秒数」：新玩家知道工作区、卫生间、休息室、会议室在哪个方向，
但仍然要自己贴着墙找门洞。四个房间的几何中心分别是会议桌、马桶隔断、床铺与工位桌——
就算把方向走对，走到房间中心也会撞在桌子上。

需求是「点击园区自动走到对应的位置」：导览卡里的四行要能直接触发移动，并且必须能绕过墙体、
穿过 60px 门洞、停在房间内的空地上。

## 决策

### 1. 到达点与房间中心分开

`shared-types/world/campus.ts` 新增 `NAV_ARRIVALS`，按「房间原点 + 偏移」手写四个室内落点；
`NavTarget` 增加只读 `arrive`，由 `layout.ts` 的 `NAV_SOURCES` 合并。

- `x / y` 仍是房间几何中心：方位箭头、直线距离与步行秒数语义完全不变。
- `arrive` 只服务寻路与到达判定，不参与 HUD 的方位计算。
- `nav-arrival` 测试断言四个落点都在对应房间矩形内、`isBlocked === false`，
  且从门洞外侧能直线走到落点——落点写错会直接红，不会等到手动试。

### 2. 寻路是客户端纯函数，不进协议

新增 `apps/web/lib/game/pathfinding.ts`：

- 16px 网格覆盖 `ISLAND.bounds`（约 238×264 格），可通行性惰性缓存：
  `0 未算 / 1 陆地 / 2 水面 / 3 阻挡`，只对 A* 真正访问到的格子调 `isBlocked`，
  首次点击不预计算整座岛。
- 8 向 A*，octile 启发；对角必须两个正交邻格都可走（禁止切角），否则会贴着墙角卡住。
- 水面可涉但代价 ×3；桥与码头按陆地计（`isOnBridge`），优先走桥与土路。
- 二叉堆 + stamp 数组复用；单次展开上限 24000，超限按不可达处理。
- 返回世界坐标点列；末点用 `arrive` 精确坐标，避免停在格子中心。

服务端不参与寻路：移动本来就是客户端确定性预测（ADR-0021），服务端只按原限速校验位置。
不新增协议包、不改 `sendMove` 的 20Hz 节拍、不产生瞬移。

### 3. Navigator 只做路点推进

`apps/web/lib/game/navigator.ts`：10px 内切下一个路点，12px 内判定到达；
卡死判定看「实际位移」——连续 700ms 位置几乎不动才返回 `stuck`，
不用「到终点距离」判断，否则 A* 正常绕路会被误杀。方向写入调用方的复用槽位，帧循环零分配。

### 4. 手动输入永远优先

`GameSession.stepLocal` 先读手动输入：键盘或摇杆非零就立刻 `cancelNavigation()`，
只在没有手动输入时才消费 Navigator 的方向，之后仍走 `resolveMotionInto` 与 `MOVE_SPEED`。

取消矩阵（全部幂等）：

- 手动方向键 / 摇杆；
- 任何动作（坐、躺、跳、叫唤、挥手、互动）；
- 打开聊天（`clearMovement`）；
- 断线重连 / 换世界（`clearWorld`）、会话销毁。

`SessionCallbacks.onNav` 只传 `{ id, name } | null`，由 `GameViewport` 写入 zustand；
到达时提示「已到达工作区」，卡死时提示「去卫生间的路上被挡住了，试试手动走过去」。

### 5. HUD 入口

`NavCard` 四行改为独立 `<button>`（不嵌套）：「去这里」常显，导航中变「取消」，
`aria-pressed` 与 `aria-label` 跟随状态；触控热区 36px。
收起后的胶囊优先显示「前往 工作区」与目标方位；竖屏与聊天 / 公告浮层的让位关系不变。

## 后果

- 正面：导览从「看方向」变成「点一下就走」；四个房间都能真正走到室内空地；
  目标数据仍只有 `NAV_TARGETS` 一份，改地图不会出现第二份坐标；协议与服务端零改动。
- 负面：客户端多一个约 200 行的寻路模块与 62KB 可通行缓存；
  首次寻路含惰性求值，实测约 5–20ms，低端机上会有一次点击延迟；
  16px 网格的分辨率意味着落点精度约半格（8px），对 60px 门洞仍有余量。
- 回滚成本：低。删掉 `NavCard` 的两个回调与 `session.navigateTo` 调用即回到纯展示导览；
  `pathfinding.ts` / `navigator.ts` 无外部调用者，整体闲置即可。

## 复核信号

- 角色停在墙外进不去房间：先查 `arrive` 是否仍在房间矩形内，再查网格是否被降到 12px；
  不要手写门口航点绕过测试。
- 角色贴着墙角抖动：检查对角通行是否仍要求两个正交邻格可走；不要放宽切角。
- 手动按键后角色还在自己走：检查 `stepLocal` 是否先读手动输入并取消导航。
- 到达后还在原地小幅抖动：检查 12px 到达半径与 `finishNavigation` 是否在同帧清掉方向。
- 点击「去这里」掉帧：确认 A* 只在点击时跑一次，没有进 `tick` 或 React render。
- 竖屏导览卡挡住动作盘：调 `NavCard` 的 `compact` 定位与 `LEASH`，不要改摇杆热区。
