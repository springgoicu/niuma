# ADR-0002：调色板替换落在图层 tint，而不是逐角色滤镜

- 状态：已采纳
- 日期：2026-10-28

## 背景

需求希望用 WGSL/GLSL 片元着色器做 GPU 级调色板替换。直观做法是给每个角色挂一个 Filter，
按调色板纹理重映射颜色。

## 问题

PixiJS v8 的滤镜需要把目标渲染到中间 RenderTexture。每个角色一个滤镜 = 每个角色一次离屏 pass，
200 个可见实体时会直接把合批打断、把填充率打满。这与「最高性能」的核心指标冲突。
另外内置滤镜的 WebGPU 支持在不同版本间存在差异，把主渲染路径焊死在滤镜上不可接受。

## 决策

图集在生成阶段就按语义槽位拆成 6 个灰度图层（body / pattern / hoof / eyes / extra / snout），
运行时每层只设置 `Sprite.tint`：

- 灰度图层 × tint 在数学上等价于「按部位替换调色板」；
- 六个 Sprite 共享同一图集纹理，Pixi 仍然可以合批，每帧零额外成本；
- 颜色变化只改 `tint`，不重建纹理，捏人页拖动 HSV 时不会触发重建。

保留了 `PaletteStrategy` 的可能性：需要单角色实时重映射（如高亮、夜班滤镜）时，
可以对单实例使用带 GLSL + WGSL 双源的滤镜；能力探测失败即回退到 tint。

## 后果

- 正面：地图内实体数量与渲染成本线性、可合批；WebGPU 与 WebGL2 视觉一致。
- 负面：图集必须按部位预分层，正式美术接入时要遵守 `manifest.json` 的图层约定。
- 回滚成本：中。若将来换成单张打包图集，需要补一条真正的调色板 shader 路径。

## 复核信号

出现「同一角色需要逐帧改变整套调色板」的需求（例如渐变染色、动态皮肤）时，再引入 shader 烘焙缓存。
