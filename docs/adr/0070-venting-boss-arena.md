# ADR-0070：发泄区——一只 10000 血的胖老板，跨日回满

- 状态：已采纳
- 日期：2026-11-13
- 关联：复用 ADR-0051 的发泄动作与扇形判定；协议走 ADR-0038 的系统广播通道；
  与 ADR-0004「服务端零持久化」一致

## 背景

园区里已经有财神供案、紫砂茶台、牛马榜，缺一个「纯粹的坏情绪出口」。
需求是一只明显打不过、但每踢一脚都有反馈的老板：站在南侧空地上，比角色大得多，
全园区共享一条很长的血条，当天打完就躺平，第二天零点回满。

约束：

- 不新增持久化：服务端不落盘、不引入 Redis，进程重启即回满；
- 老板是静态地标，没有 AOI、没有实体 id，不该被当成玩家同步；
- 客户端帧预算已经被草地、贴花和名牌占满，血条与名牌不能每帧重建；
- 手机端也能踹，动作盘已有「发泄」，不新增按键。

## 决策

### 1. 坐标只有一个真相，放在 shared-types

`BOSS_ARENA`（420×320 的垫子）、`BOSS`（200×256，`x` 是横向中心、`y` 是脚底南沿）、
`BOSS_SOLID`（脚底 160×44 的碰撞）、`BOSS_HIT_RECT`（脚底以上 150×110 的受击区）
与服务端、客户端、布局测试共用。发泄区落在南侧主路以东、四角院落以南、
南侧庭院铺装以北的空地，与两侧设施留足草缘。

碰撞只挡脚底，不挡整只：玩家可以贴到肚子正下方出招，而不是被 200×256 的
包围盒推在三百里外。

### 2. 血量活在进程内存里，跨本地零点回满

`BossRuntime` 只保留 `currentHp` 与 `resetAt`。`resetAt` 用
`setHours(24, 0, 0, 0)` 求下一个本地零点，夏令时切换日也落在当地真正的午夜。
`hit()` 先 `syncDay()` 再扣点，所以 Tick 因休眠或时钟跳变错过零点时，
跨日后的第一脚仍会先回满再扣，不会把昨日的尸体继续打。

每次真实命中扣 1 点，下限 0；已倒下返回 `null`，不广播、不重复扣。
归零那一次 `justDied = true`，客户端据此只弹一次战报。

### 3. 一条广播包覆盖三种变化

`S2C_BOSS = { hp, attackerId, died, reset }`：

- 入场快照：`hp` 当前值、`attackerId = 0`；
- 每次真实命中：带着攻击者 id 广播给全园区，哪怕在摸鱼湖最远端也看到同一个数；
- 跨日重置：`hp = BOSS_MAX_HP`、`reset = true`。

不走 AOI：血量是园区共享状态，按区域裁剪会出现「广场上打空了、湖边还是满的」。

### 4. 渲染：1:1 texel 烘焙，只写标量

老板与垫子按 1:1 texel 手绘后烘焙成 nearest 纹理（200×256 / 420×320），
不做矢量缩放，1px 描边在任何缩放下都不糊。

- 垫子进地面装饰层，不参与 y 排序；老板本体按脚底 y 进排序层，玩家能绕到身后被肚子挡住；
- 血条槽与满血条各烘焙一次，之后每帧只写 `scale.x`；血量数字 8Hz 节流，避免 Text 每帧重建；
- 待机 3.4s 一次的 1px 上浮、受击 140ms 的整数像素抖动、倒地 300ms 的 2px 下沉，全部只改位置，不改纹理；
- 全血转 0 只做一次状态切换：整只换去饱和灰纹理、名牌换纸板「老板倒下」，血条仍显示 0 / 10000。

### 5. 交互复用发泄动作，提示量到受击矩形

按 E 出招，服务端沿用 `withinVentCone` 的扇形判定，目标点取
`bossHitPoint(玩家坐标)`——即受击矩形上离玩家最近的一点。这样「站远一点斜着踢」
与「贴脸踢」用的是同一个折算点，判定和提示不会一个够得着、一个够不着。

感应提示同样量到受击矩形最近点，半径 72：老板 200×256，按中心点距离算的话
玩家站到脚边时离中心还有一百多像素，提示永远不会出现。

命中音效走已有的 `vent(hit: true)`，声源取老板脚底坐标；本地玩家踢中才在结算包回来时
补这一声「砰」，空挥只有破空音。

### 6. 主线程只留一行常驻战报

`onBossDown(local)` 在归零与入场快照（`hp = 0`）两种情况下都会触发，
`onBossReset` 在跨日回满时收起。战报不自动消失：它表达的是「今天已经打完了」，
不是一次性提示，8 秒后消失反而会让后进来的玩家以为血条空了是故障。

## 代价与取舍

- 10000 点血、每脚 1 点，单人要踢很久，设计上就是「人多才打得完」；
- 血量只在内存里，部署或进程重启会回满，属于可接受的重置语义；
- 客户端不做本地扣血预测，命中反馈要等半个 RTT，换取「没判中就不抖」的诚实反馈；
- 倒下状态没有独立动画与音效，只有换纹理和纸板牌，成本低但表现力有限。

## 备选方案（未采纳）

- 血量持久化到数据库或 Redis：违反零持久化约束，还要处理多实例一致性；
- 每脚扣百分比或按人数缩放：血条数字失去意义，玩家无法核对「还差多少脚」；
- 把老板做成有 id 的实体走 AOI：静态地标不需要同步位置与朝向，只会浪费带宽；
- 客户端先扣血再等服务端校正：会出现「踢了没掉血又弹回去」的抖动。
