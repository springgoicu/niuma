# ADR-0044：北门四角院落、上下铺宿舍与区域 logo

- 状态：已采纳
- 日期：2026-11-11
- 关联：修订 ADR-0026（工作区 / 休息室）、ADR-0028（开放式办公区与树篱软分区）、ADR-0036（北门出生点与导览）、ADR-0040（园区自动寻路）

## 背景

北门出生点上线后，玩家从门口看到的是一圈沿四边铺开的工位：办公区 1760×1384，
北、南两排横桌加东、西两列竖桌共 51 张桌子，房间却散落在岛北、岛东与岛南三处。
反馈集中在三点：

1. 进门后没有「四个方向都能去」的读感，工位环把人挡在中间，房间要走很远；
2. 工位太散，坐下来要绕半圈，忙时还会和别人的椅子挤在一起；
3. 卫生间只有一排马桶加四个洗手池，男女不分；休息室只有三张单人床，躺满了就没地方去。

需求是：收窄园区、删掉散落的工位，按北门进入的方位重排四个区域——
左上工作区、右上会议室、左下宿舍区、右下卫生间；卫生间男女分区、洗手池居中；
每个区域门口加 logo 标识；除工作区外都加墙，工作区保持开放并用横向工位。

## 问题

四条约束互相牵制：

- **方位是硬需求**：四间房各占一角，中庭就必须同时承担四条通道；
  房间再大一点，十字通道就会窄到推不开椅子。
- **工作区不能加墙**：没有墙体做边界，工位必须自己成组，否则「开放」会读成「散落」。
- **上下铺要睡两人**：`SeatKind` 目前把「家具种类」和「入座姿态」绑在一起，
  新增 `bunk` 会让服务端 `sit/lie`、客户端 `actions/session/interactions/badge` 里
  所有 `kind === 'bed'` 的判断一起改；改漏一处就是「上床按 X 被弹起来」。
- **南侧研发园**：会议室与卫生间搬走后，原 2100×800 的铺装庭院会变成空广场；
  直接删除又会掉 0.83M 像素的「有内容」面积，撞上 ADR-0028 的空地密度阈值。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 保留四边工位环，只挪房间 | 改动面最小，座位与碰撞不动 | 没有解决「删除分散工位」，房间里外仍是 51 张桌 | 低 |
| B. 工作区单排 6 张 | 最字面的「横向排列」 | 房间要加宽到约 560，破坏四间房 460×360 的对称与十字通道 | 低 |
| C. 新增 `SeatKind.bunk` | 语义最干净，一张床一条记录 | `seatPose`、服务端 sit/lie、客户端四处 `kind === 'bed'` 与全部相关测试连锁修改 | 中 |
| D. 四个独立 logo `PropKind` | `PropInstance` 不用改 | union 与 switch 各多四个成员，未来扩展更碎 | 低 |
| E. 四角院落 + 两张 bed 座位表示上下铺 + 单 `logo` 多 variant（采纳） | 方位、无墙、两人上下铺、logo 一次收口；座位语义零改动 | 布局常量整体重排，双端必须同版本发布 | 中 |

选 E。A 没解决需求，B 会压坏中庭，C 把一个纯家具表现升级成跨端状态机改动，
D 只是把 variant 换成四个名字。

## 决策

### 1. 四角院落是唯一几何源头

`campus.ts` 只写一行院落矩形与两行房间尺寸，四间房由它推出：

```text
CAMPUS_RECT = { 3336, 3476, 1520, 1240 }   // 中心仍是 (4096,4096)
ROOM_W = 460, ROOM_H = 360
1520 = 460 + 600 + 460                     // 中庭宽 600
1240 = 360 + 520 + 360                     // 中庭高 520
```

| 区域 | 矩形 | 门 | 地面 |
|---|---|---|---|
| 工作区（西北） | 3336, 3476, 460, 360 | 无墙无门 | 木地板 |
| 会议室（东北） | 4396, 3476, 460, 360 | 南墙 4726–4786 | 木地板 |
| 宿舍区（西南） | 3336, 4356, 460, 360 | 北墙 3536–3596 | 地毯 |
| 卫生间（东南） | 4396, 4356, 460, 360 | 北墙 4596–4656 | 瓷砖 |

中庭 600×520 就是 `PLAZA`（由院落减两间房推出，不另写坐标），
四条土路全部止于院落外缘，不再切进草地。

### 2. 删除散落工位，工作区横向成排

- 删除 `officeWorkstations()`、`PLAZA_DESKS`、`GATE_LANE_X/Y`、北岸横路与 45 张广场桌；
- 工作区只保留 8 张桌：两排背靠背、每排 4 张，北排 `DIRECTION.Up`、南排 `DIRECTION.Down`，
  列距 104、排距 124，两排椅子在中间背靠背相距 44px；
- 工作区不调用 `roomWalls()`，`CAMPUS_SOLIDS` 里没有任何属于它的碰撞矩形；
  边界只由木地板、桌子和四角的绿植/咖啡机/饮水机表达。
- 座位从 51 降到 25：工作区 8 + 会议椅 6 + 马桶 4 + 宿舍 7。

### 3. 卫生间三区：男 / 洗手池 / 女

自西向东 140 + 10 + 140 + 10 + 140：

- 两道 10px 内隔墙各在 `y+200–y+260` 留 60px 门洞，中央区从北门直进；
- 两侧各 2 个马桶，仍朝南、背靠水箱贴房间北墙，中间各一道 6px 隔间；
- 中央区南墙放 2 个 `sink`（沿用「底座贴南墙」的旧画法，不新增翻转贴图）；
- 男/女不引入新的房间类型，只是同一条 `roomWalls` + 两段手写内隔墙。

### 4. 上下铺：两张 `bed` 座位 + 一架爬梯，不新增 SeatKind

每个铺位写成一张普通 `bed` 座位，同 x 上下两层相距 44px：

- 上层（y 更小）先画，下层在更近的前景，两床精灵边缘只差 2px，读作上下铺；
- 44 而不是 30：既让两层床垫不完全重叠，也满足「座位两两间距 > 40」的既有断言；
- 新增 `PropKind.ladder`（14×34 小道具，不参与碰撞）贴在每个铺位侧面，
  用最低成本把「两张床」读成「一组上下铺」；
- `seatPose`、服务端 `sit/lie` 的 `kind === 'bed'`、打呼判定、`findNearestSeat` 全部不动，
  上床仍然按 X、坐下仍然不能占床。
- 宿舍区陈设精简：2 组上下铺（4 铺）+ 1 沙发 + 2 凳 + 床头几 + 绿植 + 垃圾桶，共 2 张新贴图以内。

### 5. 区域 logo：一个 PropKind，四个 variant

- `PropKind` 增加 `logo`，`PropInstance` 增加可选 `variant`（0 工作区 / 1 会议室 / 2 宿舍区 / 3 卫生间）；
- `PROP_SIZE.logo = 28×38`，`drawProp(kind, g, variant)` 在同一个木牌上画显示器、会议桌、上下铺、男卫浴四个图标；
- `PropsView` 的贴图缓存键从 `kind` 改成 `kind:variant`，四个变体各烘焙一次；
- 立牌不产生碰撞（不在 `PROP_FOOTPRINT` 里），放在每区入口外侧，工作区无门则放在东南角外侧。

### 6. 南园收窄为休息庭院

- 原 `CAMPUS_RECT`（2100×800）改名 `SOUTH_YARD` 并收为 1520×560，铺装 1440×520；
- 删除两栋房、会议桌、马桶、隔断、洗手池及对应座位/碰撞；
- 保留灯柱、绿植、长椅、野餐桌、单车、垃圾桶与指路牌并重排；
- 树篱环从办公区四边移到南园边界，北侧留 210px 入口，保住「树篱 > 40 段」的视觉密度；
- 删除北岸横路与办公区西侧的空档后，西北角与西岸水塘北侧各补一片草甸，把空地密度窗口压回 45% 以内。

### 7. 文案与导览

- `REGIONS` / `NAV_SOURCES` / `CAMPUS_BUILDINGS` 的「休息室」改为「宿舍区」，其余沿用现名；
- 四间房在「办公区」内部，`REGIONS` 里必须先于办公区命中；
- `NavTargetId` 的 `'lounge'` 保留，HUD、指路牌与测试只改显示名；
- 入场成功后在本地播一条系统公告「园区重装修完成」，`SYSTEM_NOTICE_KIND` 新增 `Renovation`，
  只走客户端 `pushSystemNotice`，不新增协议、不广播给其他人；
  「园区公告」面板顶部同时固定一行同一文案。

## 后果

- 正面：
  - 从北门一眼能读出「左上工作区、右上会议室、左下宿舍区、右下卫生间」，四扇门都朝中庭；
  - 工位从 51 张降到 8 张，桌面碰撞体、渲染精灵、裁剪条目同步减少，初始化更轻；
  - 卫生间有了男女分区与中央洗手池，宿舍区四个铺位可以同时躺下；
  - 座位语义、协议、服务端模拟逻辑零改动，改动集中在共享常量、渲染贴图与测试。
- 负面：
  - **世界坐标是双端共用的常量**，本次必须客户端与服务端同版本发布，旧客户端连新服务端会被持续拉回；
  - 上下铺靠「两张床 + 爬梯」表达，不是真正的双层家具；若以后要做 `bunk` 家具，
    需要按方案 C 抽一个共享的「躺卧座位」谓词再改；
  - 工作区没有墙，边界完全依赖家具与地板，遇到大风天（未来天气系统）没有可依附的碰撞；
  - 南园缩掉约 0.83M 像素铺装，靠两片新草甸补密度，装饰密度比上一版更依赖草甸与孤树。
- 回滚成本：中。布局常量与 `campus.ts` 回退即可，但必须与 `game-server` 同时回退；
  logo / ladder 贴图与公告可以单独保留（不依赖坐标）。

## 复核信号

- 出现「从北门看不到某个房间」：先查四角矩形是否仍贴院落四角，再看中庭是否被道具占住，不要改相机；
- 出现「工作区走不进去」：工作区本来就没有墙，卡住只可能是桌子或花箱；
- 出现「上床按 X 被弹起来」：检查 `SeatKind` 是否被改成 `bunk` 而漏改服务端 `kind === 'bed'`；
- 出现「上下铺看起来像两张单人床」：先调 `LOUNGE_SEATS` 的 44px 间距与 ladder 位置，不要给椅子加碰撞；
- 出现「南园又变成空广场」：先补草甸 / 孤树，不要放宽 `layout-density` 的阈值；
- 出现「logo 立牌挡住门口」：立牌不在 `PROP_FOOTPRINT` 里，挡住人的只可能是门洞两侧的墙。
