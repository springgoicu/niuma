# ADR-0029：工位桌随朝向转置，家具朝向与占地回归物理直觉

- 状态：已采纳
- 日期：2026-11-11
- 关联：细化 ADR-0020（工位、座位与园区设施）与 ADR-0027（座位朝向与工位桌四向贴图）；
  沿用 ADR-0005（禁负缩放 / 整数纹素）、ADR-0013（构造期烘焙）、ADR-0028（紧凑开放海岛）

## 背景

反馈原话：「当工位在侧面时，桌子也应该侧面放；检查地图中所有的物品，要符合现实物理规律逻辑。」

ADR-0027 把显示器做成了四向，但桌子本体没有跟着转：东西两列工位仍是 88×40 的横桌，
椅子落在 40 宽短边的**端头**，显示器压在近侧（`FACING_LEFT_ART.monitor.x = 74..86`，
椅子在东侧 x+64），读起来像「人趴在桌角看屏幕」。顺着「所有物品符合物理」再扫一遍地图，
还发现七处同类问题。

## 问题

1. **侧向工位桌子没转**：`DESK_SOLIDS` 恒为 88×40，`chairOffset(Left/Right) = 44 + 20 = 64`，
   人坐在短边端头；侧视显示器落在近侧长边，屏幕与桌面之间的空间无法使用。
2. **椅子背靠恒在北侧**：`drawChair` 只有一种画法（靠背在画面上方），等于「人朝南」；
   北排、东西两列、工作区与会议室南排的空椅看起来都背对着桌子。
3. **马桶正对水箱**：`drawToilet` 的水箱画在精灵北端，注释写「坐上去时后背靠水箱」，
   但 `TOILET_SEATS.facing = Up`——人面朝水箱。
4. **会议室白板穿墙**：34×24 的白板底边贴在 `y + 92`，主体一半越过北墙（墙内缘 `y + 90`）。
5. **洗手台背对南墙**：台面在 `y + 320`，离南墙（内缘 `y + 350`）还差 30px；贴图的水龙头画在上方，
   是「挂北墙」的画法，与它在卫生间南侧的位置相反。
6. **实体道具的碰撞盒整体偏南 14px**：碰撞盒以精灵底座为中心画 24 深（`y - 10 .. y + 14`），
   于是机器正面有一条看不见的墙，贴不上去；碰撞数据还是手写坐标，改精灵位置就会漂。
7. **会议室门正对椅子**：南墙门洞 `x + 370 .. x + 430` 正对中排会议椅（`x + 400`），进门先撞座。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 只把显示器移到远侧，桌子不转 | 改动最小 | 人仍坐在短边端头，桌面可用面积与朝向都没修好 | 低 |
| B. 桌子随朝向转置 + 全图物理审计（采纳） | 桌椅、显示器、马桶、白板、洗手台、门位、碰撞盒一次收口 | 东西两列椅位内收 24px，多 3 张椅子贴图、4 张工位贴图尺寸变化 | 低 |
| C. 布局统一改成「人一律朝北」 | 贴图不用转 | 丢掉四面环绕的构图（ADR-0027 已否掉） | 中 |

选 B：朝向是布局数据，几何应当从朝向派生；靠「贴图旋转」绕过只会把问题推到下一轮。

## 决策

1. **朝向即占地**：`deskFootprint(facing)` 是唯一真相——南北朝向 88×40，东西朝向整张桌子转 90° 为 40×88。
   `DESK_SOLIDS`、门洞留白判定、渲染锚点全部读它。
2. **椅子永远坐长边外侧**：`chairOffset(facing) = min(w, h) / 2 + CHAIR_GAP`，恒为 40；
   东西两列的椅子由 ±64 收到 ±40。南北两排与工作区六工位坐标零变化。
3. **贴图按朝向新画几何，不旋转精灵**（ADR-0005）：`desk-art.ts` 给出每朝向的
   `frame / top / front / handle / legs / monitor / details` 盒子；横桌 96×66，侧放桌 48×92
   （桌面 40×72 + 南端前挡板 14，正好覆盖 40×88 占地）。`props.ts` 只按盒子绘制，不再写四套分支。
4. **显示器永远在背对椅子的远端长边**：Left → 西端 `x 5..17`、屏幕朝东；Right → 东端 `x 31..43`、
   屏幕朝西。屏幕面到椅子的距离恒小于机背到椅子的距离，由单测锁定。
5. **椅子四向化**：新增 `chair-art.ts`，四个朝向共用 26×30 帧，靠背永远在入座朝向的反侧
   （Up → 靠背在南，Left → 靠背在东……）；`props.ts` 按 `seat.facing` 取图。
6. **马桶背靠水箱**：`TOILET_SEATS.facing` 改 `Down`，人面朝房间、水箱在背后，与 `drawToilet` 的注释一致。
7. **白板 / 洗手台贴墙**：白板底边 = 会议室北墙内缘 + 白板高度；洗手台底边贴卫生间南墙内缘，
   贴图上下翻转（龙头朝墙、台盆朝北），人从房间一侧使用。
8. **会议室门让开桌椅**：南墙门洞移到桌子东侧走道 `x + 530 .. x + 590`。
9. **道具占地单一来源**：`PROP_FOOTPRINT` 只登记大件（售货机、饮水机、咖啡机、长椅、野餐桌、单车），
   `propSolid(prop)` 按「底边 = 精灵底座、中心 x = 精灵 x」派生碰撞；`isSelfSolidProp` 改为查表。
   手写的售货机 / 饮水机碰撞删除，`WORLD_LAYOUT.solids` 由 props 派生。
   绿植、垃圾桶、标识、灯、床头几、树篱保持可穿过（`kind: 'prop'` 已被 `fillSolidFlat` 跳过，
   地面层不会重复画矩形）。
10. **回归测试**：`desk-art.test.ts`（四向帧、屏幕面朝向椅子、桌体覆盖占地、陈设不压显示器）、
    `chair-art.test.ts`（靠背反侧、共用帧、盒子不越界）、`seats.test.ts`
    （桌子长边垂直于朝向、椅子在长边外侧、碰撞盒底边贴底座、大件有碰撞 / 小件可穿过、南门可通行）。

## 后果

- 正面：
  - 四面工位都是「人正对桌子长边的显示器」，东西两列的桌面、抽屉板、桌腿、绿植与马克杯一起转了过来；
  - 空椅的靠背永远在座面背后，不再出现「背对桌子」的错觉；
  - 家具的朝向与贴墙关系可以直接从数据读出来，位图里看不出的「贴错边 / 穿墙」由几何单测挡住；
  - 道具碰撞与精灵同源，移动一件家具不会再留下一条隐形墙。
- 负面：
  - 侧放桌的帧更高（48×92），东西两列桌子的 y 向占地翻倍，150 的列距下相邻桌子只剩 62px 缝；
  - 椅子多 3 张贴图（26×30 级小图），一次性烘焙成本可忽略；
  - 东西两列椅位内收 24px，桌面到椅背的距离比上一版紧，属于「坐长边」的正常距离；
  - `PROP_FOOTPRINT` 是新的人工表：新增可碰撞道具必须同时登记尺寸，否则仍然可穿过。
- 回滚：低。回滚 `desk-art.ts` / `chair-art.ts` / `props.ts` 与校园布局的坐标改动即可；
  `deskFootprint`、`propSolid` 是纯函数，可单独保留。

## 复核信号

- 出现「侧向工位的人坐在桌角」：查 `deskFootprint(seat.facing)` 是否为 40×88、`chairOffset` 是否为 40；
- 出现「显示器背对人 / 压在近侧」：查 `deskArtFor(facing).screen` 是否等于入座朝向的反侧，
  以及屏幕面到椅子的距离是否仍小于机背到椅子的距离（单测已锁）；
- 出现「桌子陷进地面 / 浮空」：查 `PropsView.build()` 的 `bottom = desk.y + footprint.h / 2`，
  不要靠改贴图高度解决；
- 出现「空椅背对桌子」：查 `chairArtFor(seat.facing).back` 是否在朝向反侧；
- 出现「机器正面贴不上去」：查 `propSolid()` 的底边是否等于 `prop.y`；
- 出现「长椅 / 野餐桌可以穿过」：查 `PROP_FOOTPRINT` 是否登记了该 `PropKind`；
- 出现「进门撞椅子」：先看门洞区间是否与座位 / 桌子的包围盒相交，再动房间坐标。
