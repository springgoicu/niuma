# ADR-0105：共享交互的反馈对旁观者可见，私密反馈保持本机

- 状态：已采纳
- 日期：2026-11-16
- 关联：ADR-0051（发泄击倒）、ADR-0057（工牌点赞）、ADR-0061（上香只在本机）、ADR-0070（发泄区老板）、ADR-0072（小黑屋处置）

## 背景

玩家反馈「发泄区看不到其他玩家的交互」：别人踢老板时，老板不抖、不泛红、也没有钝击声，
只有头顶血条的数字在变。排查确认服务端已经把 `attackerId` 广播给全园区（ADR-0070），
问题在客户端：`handleBoss` 用 `attackerId === localId` 同时决定了抖动与音效，
旁观者拿到的包被当成「什么都没发生」。

顺着这个口径做了一次全局检查，同类「服务端已广播、客户端没画」的还有两处：

- 工牌点赞：`sim/like.ts` 把包发给目标与目标视野内所有人，客户端只更新计数与面板，
  世界里没有任何表现，被点赞者自己也不知道刚被点了；
- 保安派单：`sim/detention.ts` 把 `Dispatch` 阶段发给被处置者视野内所有人，
  客户端只处理 `Escort`，旁人完全看不到保安出动。

同时确认了两类**不是**漏洞的既有行为，避免后人误改：

- `handleVent` 开头的 `targetId === 0` 早退：空放的冲撞动作、破空音与台词由 state 位上升沿覆盖
  （远端 `stepRemote`、本人按键即时），在这里补反馈会造成双重音效；
- 上香 / 作揖 / 光晕、弱交互场所（会议室 / 影音室 / 游乐园 / 摸鱼亭）台词、设施互动气泡、
  钱包与打赏：按 ADR-0061 等既有决定就是本机私有，不随这次改动外扩。

## 决策

### 1. 反馈是否共享，只看「服务端有没有广播」

一条反馈若来自服务端广播的共享事件（老板血量、点赞、押送阶段），就必须对所有收包者渲染；
「是不是本人」只允许影响叙事文案与音效节流档位，不允许作为「要不要画」的开关。
本人特殊的东西（钱包、光晕、私人台词）继续留在客户端本地，不为了对称去发新包。

### 2. 老板受击：任何出招者都触发，入场与重置不触发

`bossHitFeedback(packet, localId, previousHp)` 是唯一归因点：

- `attackerId !== 0` 且不是跨日重置 → 抖动、钝击音、伤害数字；
- 入场补发（`attackerId = 0`）与 `reset` → 只更新血条；
- 伤害按前后血量差算；还没收到过快照时按 1 点兜底，绝不把整条血算成一次伤害。

抖动与「老板倒下」横幅仍挂在服务端归因上（本地不做乐观预测），
音效复用 `vent(hit: true)` 的 800px 距离衰减，远处玩家天然听不到。

### 3. 伤害数字按窗口合并，不复用每条命中

多人同时踢时命中频率可达每秒十几次。伤害数字走会话层 600ms 合并窗口，
窗口内累加成一个 `-N` 再交给 `RitualFx`（3 槽、金色描边）飘在老板胸腹；
字号比默认飘字放大一档，否则 256 纹素高的老板身上只剩一个零头。

### 4. 点赞与保安派单补齐世界内表现

- 点赞：收到 `S2C_LIKE` 时在目标头顶飘「赞 +1」，目标与旁观者都能看见；目标不在视野内静默跳过。
- 派单：`Dispatch` 阶段若保安已在视野内，气泡挂在保安头顶；否则挂给被处置者，
  等保安走进视野再自然接上。`Escort` 阶段的抗议气泡保持原样。

## 备选方案（未采纳）

- **旁观者只播声音、不加数字**：远处玩家看不到老板本体，血条变化又太抽象，仍然读不出「有人在打」；
- **伤害数字逐条飘**：`RitualFx` 只有三个槽位，高频连击会互相覆盖并把上香 / 擂台飘字挤掉；
- **为点赞 / 派单新增广播包**：服务端已经在发，重复造协议只增加状态面；
- **把作揖、影厅频道也一并同步**：前者需要挤占已满的 state 字节，后者是各客户端独立的观感选择，
  都要改协议或服务端，与本次「纯客户端补齐已广播的反馈」不是一件事。

## 后果

- 同一个园区里，别人的交互结果能在自己的屏幕上看见：老板被打会抖会红、头顶冒伤害，
  被点赞的人头顶冒「赞 +1」，保安出动时附近能看到提醒；
- 不新增协议字节、不改服务端、旧客户端行为不变；跨日重置与入场快照不会误触发反馈；
- 高频连击的飘字被合并到最多约每秒两次，帧循环里只增加几次标量写入；
- 仍保持本机私有的反馈没有被顺手扩大：上香光晕、私人台词、钱包与打赏依旧只有本人可见，
  要做「看见别人上香」需要另开一条协议并重新评估带宽。
