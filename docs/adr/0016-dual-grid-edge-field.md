# ADR-0016：位掩码驱动的双网格边缘与三层地表

- 状态：已采纳
- 日期：2026-11-02
- 关联：细化 ADR-0013（暖色 pastel 地形）、ADR-0005（整数栅格与 nearest 采样）、ADR-0010（64 网格）

## 背景

地图的方块感集中在边界：土路、广场、湖岸、海岸各自内联描边，草地一侧只有「2px 草色 stroke + 每 6px 一个 1×1 点」，
近看是一圈整齐的梳齿；树木、花箱、石头完全没有落地投影，整棵树像贴纸浮在草地上。

需求要求四件事：位掩码驱动的自适应边缘、三层叠加、像素参数矫正、全屏柔光与大物件底座投影。
其中贴花层（位置哈希 + 12% 命中 + 四类）与柔光层在 ADR-0013 已落地，本次不动算法，只补参数与层序。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 47 态边缘图集逐格拼贴 | 教科书式 dual-grid，任意拓扑可拼 | 拼贴块材质相位无法与外层 TilingSprite 对齐，接缝必露半块砖；边界被量化到 32px 格点，土路末端与 120px 门洞最多错位 16px | 中 |
| B. 位掩码驱动 + 解析轮廓（采纳） | 相邻状态由 8 邻掩码真实计算；几何仍是解析圆角/多边形，零格点误差、零接缝 | 每个材质区域多一次边缘采样（构造期一次） | 低 |
| C. 离屏 Canvas2D 烘焙成纹理 | 能严格照搬 `ctx.imageSmoothingEnabled` 那套参数 | 8192²×4B ≈ 268MB 显存与同量级 CPU 光栅化；分块重烘会在转视角时卡帧 | 高 |

选 B。A 的两个代价恰好是本次要消灭的「拼贴感」本身；C 的首屏成本与用户「加载最快」的要求直接冲突。
`imageSmoothingEnabled` 是 Canvas2D 上下文属性，WebGL/WebGPU 下不存在——本项目用
`bake()` 的 `antialias:false` + `scaleMode:'nearest'`、`loadAtlas()` 统一 nearest、
`app.init()` 的 `roundPixels:true` 与 `pixelMetrics()` 的整数设备像素缩放作为等价保证，本次保持不动。

## 决策

1. **渲染器仍是 `TerrainView`，不新增 `MapRenderer` 包装类**。
   它本来就拥有「整张地图怎么拼」的职责，再套一层只会是 pass-through；
   与场景层 `GameRenderer` 的命名也不会混淆。类注释里已写明这一点。

2. **材质判定收敛到 `terrain-edge.ts` 的 `materialAt`**，优先级：桥 > 水 > 土路 > 广场 > 岸沙带 > 草地 > 浅滩 > 海。
   渲染层不许再写第二份 `if`；单测直接锁优先级（桥压水、水压土、广场压草、岛外为海）。

3. **8 邻掩码 + 47 态归一化**。
   `edgeMaskAt` 按 32px 网格取 N/E/S/W + 四角共 8 位；`canonical47` 先清掉「孤立斜角」
   （斜角为异类但两侧正交邻居都是同类，这类状态在标准 47 态里不存在），再按 D4 群（4 旋转 × 2 镜像）
   折叠成不超过 47 个等价类。**它只做状态归类，不查图集**——图集才会切断材质相位。

4. **几何仍是解析的，不做 marching squares 提轮廓**。
   这是对原方案的一处收紧：32px 采样格提轮廓会把土路端点、120px 门洞、河口全部量化到格点，
   正是 ADR-0013 否决 A 的理由。改为「位掩码负责状态，解析轮廓负责几何」：
   矩形走 `roundedRectContour`，湖/河/岛走新增的 `polygonContour`（只切凸角，凹角保持尖，避免自交），
   岸沙带的两条边用 `offsetContour` 从原始多边形偏移 ±26/±22/±24 得到。
   偏移必须基于未倒角的多边形：半径小于偏移量时，先倒角会让圆弧上每个点各走各的法线，在角上收成一个结。

5. **三层结构**：`base`（材质底色与轮廓遮罩）→ `edge`（内缘暗边 + 连续草缘 + 草尖/圆弧）→ `decals`。
   边缘任务在底色阶段只登记，等**所有**底色落盘后由 `flushEdges` 统一出图——草缘必须压在所有材质的暗边之上，
   这才是「草自然覆盖泥地」的层序；如果跟着各自区域画，后画的土路会把先画的草缘盖掉。

6. **边缘图元全部是整数 `rect`**（1×1、1×N），不用 `Graphics.arc / ellipse`。
   内缘暗边仍用一次 `stroke`（`alignment` 内侧）：它是单条路径，逐像素拆成 rect 会让图元数量翻十倍；
   而 `stroke` 的顶点也落在整数轮廓上，配合 `antialias:false` 不会糊。

7. **生长方向规则只有一条**：草往对面的材质里长。
   - 对面是草（土路、广场、湖岸外缘）：齿朝轮廓内侧长，草盖住泥/石/沙；
   - 其余配对（沙↔浅滩、水↔沙）：齿朝外长，用自己材质的色。
   两个反例用 `grow` 显式覆盖：海岸带陆地侧（沙在轮廓外、草在内，齿朝外）、
   湖/河沙带外缘（草在轮廓外、沙在内，齿朝内）。方向不靠推断，避免朝向一改就整条边翻面。

8. **每 6~8px 一个齿，每 46~52px 一个外凸圆弧**；齿长 2~4px、三七开外突/内缩，颜色在 `tooth` / `toothDeep` 之间按位置哈希二选一，
   偶尔补一撮两像素宽的草。图元上限 4096/段，超出即停——宁可少画，也不让病态轮廓把构造期拖爆。

9. **底座投影**：`fx.fillEllipse` 扩成可传画布尺寸并导出，`makePropShadowTexture` 烘焙
   `0x1E2846 @0.2` 外圈 + `@0.06` 内芯的硬像素椭圆（树 46×18、花箱 30×12、石头 18×8）。
   `zIndex = y - 0.5`：永远压在同位置物体之下，又不会掉到更靠上的物件后面；全部进 `cullables` 复用现有裁剪。
   角色三档阴影走默认参数，逐像素不变。

10. **相机只在源头取整**：`updateCamera` 对 `cameraAxis` 的结果取 `Math.floor`。
    `snapTexel` 保持 `Math.round`——实体位置是逻辑坐标，改成 floor 会让所有角色整体偏半个纹素。

11. **柔光与调色**：`ANCHORS` 的 dawn 改 `0xFFE6B4 @0.08`（其余锚点不动，保留 multiply 与 `?light=0`）；
    `dirtBase` 改需求指定的 `0xC8A27A`，`dirtAlt` 同比抬一档，`MINIMAP_COLORS.dirt` 自动跟随。

12. **三个独立回滚开关**：`?flat=1` 退回矩形平铺并跳过边缘层，`?edge=0` 只关边缘层，`?light=0` 关柔光。
    三者互不依赖，线上定位观感回归时可按层剥离。

13. **不铺全局泥土底**。需求里的 Base/Dirt 指「泥土是承托草的那一层」，但本世界草占七成，
    再铺一层 8192² 的泥土只会被完全遮住，还多一次全屏填充；`#C8A27A` 落在土路本体
    与草缘内侧的露底上，视觉等价、零额外填充。

## 后果

- 正面：草土/草石/草沙/沙水/桥水五类边界共用一张 `EDGE_STYLE` 表与一套方向规则；
  边界由真实的相邻状态驱动，不再是等距撒点；树木与花箱落地，画面不再「浮」。
- 负面：
  - 构造期多一次 66k 格材质扫描与约 7k 采样点的边缘生成，实测在桌面浏览器为数十毫秒级，
    且只在 `TerrainView` 构造时发生一次；材质网格按需构建，`?edge=0` 时完全不算。
  - 边缘图元约 6k~10k 个 1px 四边形，每个材质区域合成一个静态 `Graphics`，帧循环零成本；
    若低端机首屏出现明显停顿，优先把 `scallopRadius` 降到 3、再考虑把齿步长提到 8，不改 32px 采样格。
  - 海岸带的两条边缘是基于原始海岸线偏移的，海湾凹角处齿会稀疏一些（探针判定为异类即跳过），
    属于「草不该长在河口正中央」的正确行为。
- 回滚成本：低。三个 URL 开关覆盖边缘、平铺、柔光；配色集中在 `terrain-palette.ts`，几何集中在 `autotile.ts`。

## 复核信号

- 出现「土路边缘的齿忽密忽疏」：先查 `edgeGlyphs` 的双侧探针是否在凹角两侧都命中 `other`，再查 `offsetContour` 的偏移量。
- 出现「广场边缘的草戳在石板上」：确认 `paintRegion` 的 `edgeOutset` 仍等于路缘石宽度 10。
- 出现「湖岸沙带外缘有折角」：说明偏移用到了倒角后的轮廓，必须换回原始多边形。
- 出现「角色整体偏半像素」：检查是否有人把 `snapTexel` 从 round 改成了 floor。
- 贴花层在 200 人同屏时绘制耗时上升：先降 `DECAL_CHANCE` 到 0.08，不要动 64px 栅格（与草缘采样格成整数倍）。
