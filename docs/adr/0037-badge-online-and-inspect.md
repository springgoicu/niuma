# ADR-0036：工牌显示在线时长与所在地，点击角色查看他人工牌

- 状态：已采纳
- 日期：2026-11-11
- 关联：ADR-0004（服务端零持久化）、ADR-0025（远端插值）、ADR-0033（移动摇杆与聊天层）、ADR-0035（常驻状态与工牌）
- 后续：完整档案与考勤摘要由 [ADR-0052](0052-badge-career-summary.md) 接续；本 ADR 的会话级工牌与 0xfe 在线时长段仍有效。

## 背景

工牌目前只回答「你是谁」：昵称、物种，以及一行硬编码的 `floor 03 · corridor b`。
园区里真正被频繁询问的是「你在线多久了」「你现在在哪」「你在干嘛」，而这些信息
服务端其实都已经知道——位置、入座、姿态、会话起点——却没有任何一条路径把它们送到
别人的工牌上。

需求有三条：

1. 自己的工牌显示**所在地**（园区区域名）与**本次在线时长**；
2. 点击 / 轻点园区里的其他角色，打开对方工牌；
3. 他人工牌要包含在线时长与所在地，并附带当前姿态与是否入座。

## 决策

### 1. 在线时长走服务端会话口径，随 SPAWN 尾部追加 5 字节

纯客户端只能从「第一次看到这个人」开始计时，入服前就已经在线的人会显示成刚上线，
口径不准确。因此由服务端记录入场时刻，并在入场包里带上**发送那一刻的已在线秒数**：

```
S2C_ENTITY_SPAWN (0x05) v3
[op u8][id u16][x u16][y u16][state u8][nameLen u8][name nB][appearance 32B]
[statusLen u8][status nB]?          ← ADR-0035，空状态不写
[0xfe][onlineSec u32 小端]?         ← 本次新增，旧服务端不带
```

- `0xfe` 大于 `MAX_STATUS_BYTES`（48），不可能是合法状态长度，因此可以按首字节窥视。
- 旧解码器读到 `0xfe` 会当成状态长度 254；此时剩余只有 4 字节，按既有「长度超出负载
  就回退空串」的规则丢弃状态并返回，不会越界，也不会拒收整包。
- 新解码器遇到旧服务端（没有这 5 字节）时 `onlineSec` 为 `undefined`，客户端退化为
  「首次看到起算」，保证新客户端可以接旧服务端。
- 逐字节只追加在尾部，既有字段偏移不变，30 天内回滚只需撤掉双端的读写分支，无数据迁移。

### 2. 服务端只多一个内存字段，仍不落盘

- `Player.joinedAt`（毫秒）在 `World.create` 时写入，`reset()` 清零；`admit` 复用同一次
  `Date.now()`，与座位占用共享同一个 `now`。
- `spawnPacketOf` 每次发入场包时现算 `floor((Date.now() - joinedAt) / 1000)`，
  **不写进 `spawnBody` / `spawnWriter` 缓存**：秒数每秒变化，缓存会让后进入视野的人
  看到旧值。
- 这段逻辑只发生在视野重算，不在 20Hz Tick 热路径；断线重连会创建新的 `Player`，
  时长从重新入场开始，符合「会话时长」而不是「账号年龄」。

### 3. 客户端用「收到时的秒数 + 本地时钟增量」计时

- 远端：收到 spawn 时记下 `onlineSec` 与本地 `performance.now()`，展示时加上本地增量。
- 本地：从 `WELCOME` 时刻起算，不依赖服务端时钟。
- 不使用服务端绝对时间戳：客户端时钟可能与服务端差几分钟，而 `performance.now()` 单调、
  不跳变，足以覆盖显示精度（秒）。
- 姿态与入座状态直接复用会话已有数据：`Motion.pose` 决定「站立 / 走动 / 坐 / 躺」，
  `entitySeat` 决定是否入座以及座位种类（椅子 / 凳子 / 马桶 / 床）。

### 4. 拾取放在渲染层做几何判定，不进帧循环

- `renderer.pickEntityAt(stageX, stageY)` 把舞台局部 CSS 坐标反变换到世界坐标：
  `worldX = (stageX - world.x) / cssScale`。
- 命中盒以角色脚底锚点为中心：横向半宽 20 世界像素，纵向从脚底 -74 到 +6；
  只遍历 `isShown` 的实体，取中心距离最近的一个。点击频率极低，允许一次小数组分配。
- 会话层 `inspectAt` 调用拾取并排除本地玩家（自己的工牌常显，不需要再点开一份）；
  点击空白返回 `null` 并关闭详情。

### 5. 手机端区分轻点与拖动，不让选中抢走移动

- 左半屏摇杆继续铺满热区，但按下后先记录起点与时刻：
  - 位移超过 10px 或按住超过 320ms → 按拖动处理，摇杆照常移动；
  - 抬起时仍在小阈值内且时间短 → 视为轻点，转发屏幕坐标做拾取，**不产生位移**。
- 右半屏没有摇杆遮挡，直接走宿主的 `pointerup`。
- 旋转舞台沿用既有 `offsetX / offsetY` 约定，不再多一套坐标换算。

### 6. 工牌是同一套信息的两个副本

- 自身工牌：姓名下方常显「所在地 · 在线 HH:MM:SS」，手机折叠条展开后同样可见。
- 他人工牌：桌面放在右上角控件列下方，手机浮在动作盘上方；结构为
  头部 / 姓名与物种 / 所在地 / 在线时长 / 常驻状态（有则显示）/ 当前姿态 / 入座状态。
- 关闭路径三条：点击空白、关闭按钮、被查看者离开 AOI（`despawn` 后 `badgeOf` 返回 null）。
- 视觉沿用现有工牌的 ink 底、2px 硬边、mint 强调与 mono 小字，不新增色系、不引入弹窗动画。

## 备选方案与反向成本

| 方案 | 形态 | 收益 | 代价 / 不做的理由 |
|---|---|---|---|
| A（采用）SPAWN 尾部追加 | 入场包多 5 字节 | 一包拿全、零额外往返、旧解码器天然忽略 | 双端需同版本发布；每包 +5 字节 |
| B 客户端首次看到起算 | 零协议改动 | 改动最小 | 入服前已在线的人时长明显偏短，口径不可信 |
| C 新增查询 opcode | 点选后向服务端要详情 | 协议语义独立 | 多一次往返，要处理迟到、丢失、重连与伪造请求 |

反向成本（不做 / 晚做）：工牌只能继续显示硬编码楼层，玩家想了解对方只能靠聊天问，
而聊天会被刷掉；位置与在线时长这些服务端已经持有的信息白白浪费。

## 后果

- 正面：他人时长与本人完全同源；首页与工牌不必新增轮询；服务端仍零持久化，
  进程重启只丢失「在线多久」这一展示字段。
- 负面：
  - SPAWN 包增加 5 字节，200 人同屏刷新视野时多约 1KB 下行，可忽略但确实存在。
  - 拾取是一次 O(可见角色数) 的线性扫描；角色密度继续上升时再考虑复用空间索引。
  - 手机轻点与摇杆共用左半屏热区，阈值以内的「手抖拖动」会变成选中而不是走位。
- 回滚成本：低。协议为纯追加，撤掉 `encodeSpawnInto` / `decodeSpawn` 的新分支即可；
  UI 侧移除详情卡不会影响既有工牌与移动。

## 复核信号

- 在线时长需要跨重连累计或跨会话保留（此时要引入服务端身份与持久化，重新评估 ADR-0004）；
- 同屏角色密度大到线性拾取出现可感知延迟（改用空间索引拾取）；
- 工牌详情需要展示外观/背包等完整资料（此时应抽独立的玩家资料查询接口，而不是继续扩 SPAWN）。
