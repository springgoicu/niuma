# ADR-0056 全屏像素弹幕与聊天包元数据

- 状态：已采纳
- 日期：2026-11-12
- 关联：ADR-0028（内容审核）、ADR-0033（移动端聊天层级）、ADR-0039（聊天历史）、ADR-0046（屏幕空间雪层）、ADR-0049（Worker 渲染）、ADR-0050（构建版本强制刷新）

## 背景

园区频道原本用角色头顶的局部气泡显示聊天。这个方案在人数少时直观，但有两个硬伤：

1. **空间上限**：气泡挂在一个角色身上，同屏 4~5 条就会互相遮挡；头顶还要让位给昵称、状态与眩晕星星。
2. **信息带不走**：镜头外的消息完全不可见，频道缺少「全园在说话」的氛围。

产品要求把聊天升级成**全屏像素弹幕**，并且支持发送者自选颜色与飞行模式（滚动 / 顶端 / 底端），
同时保留防打扰设置（总开关、不透明度、覆盖区域）。

## 决策

### 1. 弹幕是屏幕空间层，挂在 `app.stage` 顶层

`DanmakuField` 持有独立 `Container`，在 `GameRenderer.init()` 里于 `lightmap` 之后 `stage.addChild`，
**不进 `world`**。因此相机平移、缩放、抖动都不影响弹幕位置；DOM 面板天然在画布之上，不需要额外排序。

之所以不用 DOM 覆盖层：仓库的渲染循环整体在 Worker（ADR-0049），DOM 方案意味着主线程每帧改上百个节点，
且拿不到与画布同一帧的合成时序；Pixi 内部的 `Text` 已经带纹理缓存与批处理。

### 2. 聊天包前置 2 字节元数据（有意破坏兼容）

```text
C2S_CHAT           = [op u8][colorIndex u8][danmakuMode u8][len u16][utf8]
S2C_CHAT_BROADCAST = [op u8][entityId u16][msgId u16][colorIndex u8][danmakuMode u8][len u16][utf8]
```

- `colorIndex` 是调色板索引（今天 0~7，字段按 0~15 预留）；
- `danmakuMode`：0 滚动 / 1 顶端 / 2 底端。

这是对 ADR-0028「协议只增不改」的一次**有意识例外**：把元数据放到包尾虽然对旧端友好，但会让
「文本长度」与「文本内容」之间出现可选段，解码要按包长猜语义——与 ADR-0034 / ADR-0039 反复避开的
「用长度猜格式」是同类错误。发布保障是 ADR-0050 的构建版本强制刷新：部署后旧标签页会被要求刷新，
不存在长期双格式并存。

### 3. 服务端是颜色的唯一权威

`normalizeDanmakuColor` / `normalizeDanmakuMode` 在共享层实现，解码、广播编码与 `handleChat` 三处调用：

- 颜色超出调色板（≥8 或 >15）→ 回落 0（默认白）；
- 模式未知 → 回落 0（滚动）。

**不新增拒绝原因**：外观越界是伪造包或客户端版本差异的痕迹，静默钳制后照常广播，比让正常玩家
发不出话更合理；`S2C_CHAT_REJECTED` 仍然只表达政治拦截与限速。

审核链路完全不变：截断 → 空串 → 限速窗口 → 政治拒绝 / 脏话打码 → 广播。打码只改正文，元数据保留。
历史环形缓冲（ADR-0039）不新增字段：历史只负责「谁说了什么」，回放不重播弹幕。

### 4. 轨道算法：固定速度、复用判定、固定弹幕独占

- 轨道高度 28px，数量按可用高度落在 **8~12** 之间，顶边 88px（让开左上角工牌）、底部安全区 104px；
- **滚动弹幕用固定速度**而不是固定单条时长：`speed = (屏宽 + 360) / 7200ms`。全部同速才不会出现
  「后发的短句追上先发的长句」；实际飞行时长随文本宽度在 6~7.2 秒之间，符合产品口径；
- 轨道可用判定是「上一条的**右边缘**已完全进入屏幕（留 48px 间隙）」，而不是「上一条已离场」，
  这正是同轨能同时容纳多条文本的原因；
- 全部轨道繁忙时按游标轮替，宁可短暂交叠也不吞消息；
- 顶 / 底固定弹幕独占轨道，停留 4 秒后 0.5 秒淡出；轨道全忙时选最早空出来的那条（立刻可见优先）；
- 覆盖区域：`full` 全轨、`half` 上半屏、`compact` 前 3 轨。非全屏时底端弹幕收进覆盖带内，
  避免「精简模式」仍然压住脚边操作。

### 5. 对象池与帧循环纪律

`Text` 是纹理级对象，每次改 `text` 都会重建纹理，所以：

- 池上限 120，活跃上限 100，溢出队列 100（满则丢最旧）；离开左缘当帧回收；
- 只在**激活时**写一次 `text` 与 `style`；帧内只改 `x` / `alpha`；
- 8 种颜色各一份共享 `TextStyle`，换色只换引用；
- 昵称 12 显示宽、正文 40 显示宽截断，避免一条弹幕横跨三条轨道。

### 6. 偏好分两层，键名唯一

- `lib/game/danmaku-prefs.ts`：纯契约与清洗函数，Worker 可安全导入；
- `lib/danmaku-prefs.ts`：`localStorage` 读写，只允许主线程；
- 键：`niuma:danmaku_pref:v1`，同时存接收侧（开关 / 不透明度 / 覆盖区域）与发送侧（颜色 / 模式）。

读盘逐字段回落：坏字段只回默认，不连带清掉其他还记得的偏好。渲染线程的初始值随 `init` 消息带入，
运行期变更走一条低频 `danmaku` 消息——设置是事件，不进每帧控制块。

### 7. 聊天表现收口

`GameSession.handleChat` 不再调用 `renderer.showBubble`，改调 `showDanmaku`；Zzz、发泄、互动、
咀嚼这些**非聊天**台词仍走原有头顶气泡。弹幕昵称取 `names`（含本人），物种取 `speciesById` 决定 🐮/🐴 前缀。

## 备选方案

| 方案 | 描述 | 优点 | 代价 | 结论 |
|---|---|---|---|---|
| A（采用）屏幕空间 Pixi + 前置字节 | 本文方案 | 与现有 Worker 渲染同帧、帧预算可控、层级天然正确 | 双端需同版本发布；文本纹理是主要成本 | 采用 |
| B DOM 覆盖层 | 主线程渲染弹幕 | 样式自由、实现直观 | 主线程每帧动上百节点，与画布合成错拍；跨线程数据仍需通道 | 否 |
| C world 内图层 | 弹幕跟随世界坐标 | 复用现有层 | 相机移动会让弹幕跟着漂，语义错误 | 否 |
| D 尾部可选扩展 | 元数据放包尾 | 旧端可解析 | 需要按长度猜格式，重蹈 ADR-0039 明确拒绝的覆辙 | 否 |
| E BitmapText | 位图字体渲染 | 纹理成本更低 | 中文位图字体资产与生成管线超出本次范围 | 暂缓（列为后续优化） |

## 反向成本（不做 / 晚做）

- 不做：多人聊天始终挤在头顶，超过 5 人就无法阅读；频道没有「全园在场感」，新玩家判断不了园区活不活跃。
- 做：协议硬切要求客户端与服务端同时上线；发布窗口内旧标签页会解析失败（由强制刷新兜底）。
- 做：每条弹幕一次文本纹理重建。对象池与上限把峰值锁在 100 条，但低端设备仍需用 `?danmaku=0` 兜底。

## 回滚路径（30 天内）

1. **先关表现**：线上加 `?danmaku=0` 或让设置面板默认关闭，聊天列表不受影响；
2. **回退协议**：还原 `encodeChatSend` / `encodeChatBroadcast` 与 `handleChat` 签名（三处），旧客户端即可继续工作；
3. **保留 UI**：工具栏与设置面板可以独立隐藏，不动偏好存储，避免用户设置丢失。

回滚成本低：协议是唯一不可逆点，其余都是渲染层与 UI 层。

## 复核信号

- **掉帧**：先看活跃数与纹理重建次数（`?danmaku=stress` 复现），再看是否有人绕过池直接 new Text。
- **轨道重叠**：检查 `pickScrollLane` 的间隙是否被改小，或有人把固定速度改回「每条固定时长」。
- **内存上涨**：池上限或回收条件被改动；回收必须发生在 `x + width < 0`，不能提前。
- **同一句话颜色不一致**：服务端钳制被移除，或客户端按本地偏好重算了别人的颜色。
- **中文输入法误发**：`compositionstart/end`、`isComposing`、`keyCode 229` 三重守卫缺一。
- **关掉总开关仍有弹幕**：`setPrefs(false)` 必须 `clear()`，不能只隐藏容器。
