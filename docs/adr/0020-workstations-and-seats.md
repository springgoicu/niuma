# ADR-0020：工位、座位与园区设施

- 状态：已采纳
- 日期：2026-11-06
- 关联：ADR-0008（地形碰撞）、ADR-0017（草地地面）、ADR-0018（叠加动作与 state 位）

## 背景

办公广场只有花箱与围栏，玩家按 Z 只会切换坐姿，不存在「坐在哪」。
产品需要：园区里有工位，靠近空闲工位按 Z 能坐上去，一个工位同一时间只能坐一人；
同时补上卫生间、会议室等设施，让地图更像一座办公园区。

## 决策

### 1. 座位是布局数据，双端共用

- `packages/shared-types/src/world/campus.ts` 与 `layout.ts` 描述座位（`SeatInstance`）、工位桌、装饰与碰撞矩形。
- 座位 id 从 1 开始，0 保留为「无座位」；座位表顺序决定 id，协议与服务端只传 id。
- 工位椅引用所属桌子的下标（`desk`），用于占座时点亮显示器；马桶 `desk = -1`。
- 座位锚点即入座后角色的世界坐标；入座判定半径 `SIT_RANGE = 90`，由 `findNearestSeat` 统一计算。

### 2. 占用权威在服务端

- `apps/game-server/src/sim/seats.ts` 的 `SeatRegistry` 持有 `seatId → 占用者` 表。
- 入座：附近有空闲座位则吸附到锚点并面朝座位；没有则就地坐（保持原有行为）。
- 起身 / 断线 / 移动起身：释放座位，广播 `S2C_SEAT_STATE`。
- 入场时下发一次全量占用快照，之后只发变化条目。

### 3. 座位上的移动规则

- 入座后服务端锁定位置：上报坐姿的移动包只接受原地叫唤 / 挥手，位置不变。
- 上报非坐姿（移动、跳跃）即视为起身，先释放座位再按正常移动处理。
- 座位上不能躺（X 无效）；Z 在已入座时无效。

### 4. 客户端：预测 + 服务端校正

- Z 时若本地镜像显示附近有空闲座位，先本地吸附（即时反馈），再发 `ACTION.Sit`。
- 服务端的座位广播是最终结果：本人被分到别的座位则吸附过去；座位被别人先占则退回地面坐。
- `sitIntent` 标记「已发入座且尚未起身」，避免起身后迟到的入座结果把角色拽回椅子。
- 座位附近的提示（`按 Z 坐到工位` / `按 Z 使用马桶`）每 150ms 计算一次，只在文案变化时更新 UI。

### 5. 协议变更（向后兼容）

- `ACTION.Stand = 2`（新增，旧客户端不会发）。
- `OpCode.S2C_SEAT_STATE = 0x19`，格式：`op(1) + count(u16) + [seatId(u16) + occupant(u16)] * count`。
- 旧客户端收到未知 opcode 会忽略，不会错位。

### 6. 渲染与性能

- `apps/web/lib/game/props.ts`：地板、瓷砖、铺装、墙体压成一张 Graphics（base 层），桌椅与装饰是按 y 排序的精灵。
- 所有贴图构造期一次性烘焙（沿用 `bake`），帧循环只做视口裁剪与显示器贴图切换。
- 地面贴花排除铺装与室内空间，草不会长进会议室。

## 后果

- 占座规则完全在服务端，客户端无法伪造占用；多开客户端的抢座有单测覆盖。
- 座位与碰撞共用 `WORLD_LAYOUT`，布局改动需要跑 `shared-types` 的座位测试（座位在陆地、不压墙、两两不重叠、门前通道不被挡）。
- 桌子的碰撞矩形与椅子锚点保持 20px 间距，改桌子尺寸时要同步 `CHAIR_GAP`。

## 回滚

单独回滚 `campus.ts` 与 `props.ts` 即可去掉新增地图；座位逻辑依赖布局数据，回滚需同时还原 `ACTION.Stand` 与 `S2C_SEAT_STATE`（旧客户端忽略未知 opcode，可单向保留）。
