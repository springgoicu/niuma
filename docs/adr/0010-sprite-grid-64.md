# ADR-0010：角色网格升到 64×64——硬朗卡通画法与地形尺度校准

- 状态：已采纳
- 日期：2026-10-30
- 取代：ADR-0006 中「差距不在分辨率（48×48 已经够用）」的判断；ADR-0005 中「DOM 侧只允许 48 的整数倍」的措辞

## 背景

48×48 的图集在 ADR-0006 里被判定为「已经够用」，问题都归给了剪影、体积、节奏与场景。
上线后的实际反馈是另一组：

1. **画不清楚**：远看角色是一坨带描边的色块，走近才认得出是牛还是马；
2. **画面杂**：斑纹、背线高光、右缘压暗叠在一起，在深色主体上糊成噪点；
3. **牛马比例不和谐**：两者剪影尺寸几乎一致，只靠颜色与吻部长短区分，
   马看起来就是「方身子的棕牛」；
4. **人与地图比例失调**：树只有角色 1.7 倍高，地砖比角色还窄，广场像一张格纸。

## 问题

这四条里有三条是同一处约束的结果：**48 格里放不下四段结构**。

按当时的解剖参数，角色约 41 texel 高，其中头 13.6、躯干 11.2、腿 12。
要把「头 + 颈 + 躯干 + 前后各两条腿」画进 41 texel，只剩一个办法：
把前腿和后腿各错开 2px 合成一根带明暗的粗柱（`quadruped.ts` 里当时就写着这条注释）。
一旦腿合并，剪影里就没有「关节」这个结构，牛与马也就只剩躯干形状的差别。

第二个问题是**明度阶梯与 tint 的冲突**。旧表 255 / 176 / 112 是为浅色牛设计的；
马身取 `0xA96C3C`，乘 0.44（BodyDeep）后是 `0x4A2F1A`——近黑，看不出色相。
也就是说同一张明度表在浅色主体上正常、在深色主体上全是噪点。

第三，地形件从来没随角色一起校准过：树 68px、地砖 32px 都是 8 帧时代留下的数。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 保持 48×48，只重画画法 | 改动最小，图集与锚点零风险 | 四段腿依然画不下；「牛马同构」无法根治 | 低 |
| B. 升到 64×64（采纳） | 面积 +78%，头/颈/躯干/四条腿各有位置；牛马可以按部位分配身高 | 图集 1024×256；锚点与客户端帧几何全部要重推 | 中 |
| C. 升到 96×96 | 细节最充足 | 风格从复古像素滑向高清像素；重画量翻倍；显存 ×4 | 高 |

选 B。理由是「头/躯干/腿能不能分开」是二元的：64 之后站立总高 48 texel，
头部 18、躯干 15、腿 17.5，四段腿各占 4px 宽、间隔 1.2px，结构终于是画出来的而不是暗示出来的。

## 决策

1. **网格 48 → 64**，`FRAME_SIZE = 64`、`ORIGIN = (32, 59)`。列数、`CLIPS` 与逐帧时长一字不动——
   16 列帧预算是动画契约，改它要同时动播放器、相位错开与落地页 CSS mask，风险与收益不成比例。
2. **画法改为硬朗卡通**：每个形体只有「本体 + 一档阴影」，阴影靠 `solid()` 整块偏移得到，
   不再逐列扫描（删除 `topLight` / `rightShade` / `bottomShadeAbove`）。描边统一 1px 深色并补对角针孔。
3. **明度阶梯重写为 255 / 206 / 158 / 44**。阴影档从 0.69 抬到 0.81，
   深色主体上仍留得住色相；这是「一坨近黑」的直接解法。
4. **牛马按部位分配身高**，而不是按颜色区分：
   牛 躯干 23×15.2、腿 17.5、颈 8.2、头 18.4、吻 10；马 躯干 19×13.2、腿 20、颈 10.5、头 15.2、吻 6.8。
   站立总高 48.6 / 49.8（差 1.3 texel），并排齐高但剪影不同。
5. **配件 16×16 → 20×20**：头径 13.6 → 17 是 1.25 倍，`16 × 1.25 = 20`，
   帽子相对头宽的比例与旧版完全一致，锚点不需要手调。
6. **地形件 ×1.25**：树 68 → 108（= 角色 ×2.25）、地砖 32 → 64×32 大板错缝、围栏柱距 56 → 84、
   花箱 24×32 → 34×44、水面 32 → 48、接触阴影 16×7 → 22×9。
   广场取消每块砖的亮边：地面越「有图案」，角色越出不来。
7. **世界坐标 ×1.25**（`shared-types/world/layout.ts`）：广场、围栏、门洞 80 → 120、道路 96 → 128、
   湖泊 20 顶点按中心等比放大、河流 5 段阶梯、木桥、花箱间距、`SPAWN_RADIUS` 240 → 300、
   `TREE_CELL` 96 → 120、`PLAYER_RADIUS` 7 → 9，`isPlantable` 的六处留白同步重算。
   `MOVE_SPEED` 132 → 165，走完整张地图的秒数不变。
8. **`origin` 下沉到生成物**：`sprite-layout.generated.ts` 新增 `origin` 与 `cosmeticSize`，
   客户端锚点改读 `origin.y / frame.h`。此前 `character.ts` 写死 `45 / 48`，
   昵称 `-47`、气泡 `-54`、裁剪余量 `48 / 96` 各自手推，改一次网格要回来找五处。
9. **图集升 v4**，`atlas.ts` 的版本校验会直接拦下旧图集，而不是静默错帧。

## 后果

- 正面：角色有可读的四段腿、颈与吻；深色主体不再糊；牛与马并排第一眼就能分开；
  树高是角色的 2.25 倍、围栏齐胸，园区有了纵深；客户端不再持有任何帧几何魔法数。
- 负面：
  - 图集 768×192 → 1024×256，8 层 × 2 物种的常驻纹理从约 9.4 MiB 增至约 16.8 MiB；
  - 地形纹理单张面积 ×2.5（初始化期烘焙，一次性成本）；
  - **世界坐标是服务端权威碰撞与客户端预测共用的常量**，旧客户端连新服务端会被持续拉回——
    必须双端同版本发布，这是本次唯一一处高代价改动。
- 回滚成本：中。把 `FRAME_SIZE` 改回 48、`COSMETIC_SIZE` 改回 16、`world/layout.ts` 各常量退回旧值、
  `MOVE_SPEED` 回 132，再跑一次 `pnpm assets` 即可；但 `shared-types` 与客户端必须同步回退，
  否则碰撞与画面会各走一套坐标。

## 复核信号

- 若 1024×256 图集在中低端移动设备上出现首屏卡顿或纹理上传超时，
  优先砍 `body` 与 `bodyLight` 的 tail 变体（合回一张），不砍网格尺寸与行走帧数。
- 若出现「踩在路口被弹回」的反馈，检查 `PLAYER_RADIUS` 与门洞宽的比值——
  9 : 120 是本次的基准，门洞再窄就会被半径吃掉通行宽度。
- 若出现「新旧客户端互相看不见」或位置抖动，说明有一次发布没对齐 `shared-types`，
  按上面的发版纪律重新同版本发布，不要试图在服务端做兼容。
- 若地形件与角色再次出现比例失衡（例如新增建筑、NPC），先按「角色站立高 = 48 texel」折算，
  再决定新件的像素尺寸，不要凭观感调数。
