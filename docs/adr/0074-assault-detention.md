# ADR-0074：打人触发执法——擂台外单向累计、2 分钟窗口、先警告后押送

- 状态：已采纳
- 日期：2026-11-13
- 关联：小黑屋处置与押送沿用 ADR-0072；擂台独立战斗域沿用 ADR-0073；发泄命中结算沿用
  ADR-0051；零持久化沿用 ADR-0004；系统广播沿用 ADR-0038

## 背景

ADR-0072 只处理「贴着别人反复坐下站起」的骚扰，园区里的另一种行为没有出口：
玩家用发泄（E）单方面殴打同一个人，被打者除了倒地 1.5 秒没有别的手段。
需求是让这类行为也进入同一条执法链路，但必须与擂台里的正常对战区分开。

约束：

- 判定必须服务端权威：命中已经由 `sim/vent` 权威结算，客户端无法伪造；
- 擂台内互打是玩法（ADR-0073），不能触发执法；
- 不新增协议与客户端改动：小黑屋阶段包与系统提示都已存在；
- 不新增持久化：账本只活在进程内存，断线、重启即清（ADR-0004）；
- 不新增传送与禁足：处置仍走 ADR-0072 的步行押送、送到即放人。

## 决策

### 1. 判定口径：擂台外、真人之间、同一目标、2 分钟滑动窗口

常量集中在 `sim/detention.ts` 的 `ASSAULT`：

| 常量 | 值 | 含义 |
|---|---|---|
| `WINDOW_MS` | 120000 | 只看最近 2 分钟的命中 |
| `WARN_HITS` | 2 | 第 2 次只私下警告本人 |
| `CONFIRM_HITS` | 3 | 第 3 次确认并派单 |
| `PRUNE_MS` | 5000 | 账本清理节流 |

只统计「攻击者 → 受害者」的单向命中次数，按目标分别计数，不跨目标合并。
互殴时双方各自累计，谁先对同一目标打满 3 次谁被押走；不检查对方是否还手。

排除项：

- 擂台内命中：`sim/vent` 的 `ringHit` 为真时不上报，擂台是独立战斗域；
- 空放与入座免伤：`targetId = 0` 或目标 `seat !== 0` 时不会产生命中回调；
- NPC 与离线实体：任一方 `isNpc` 或 `wsId === 0` 直接返回；
- 已在押送流程中的攻击者：`cases.has` 挡住重复建案。

### 2. 命中上报走观察者端口，不让命中结算认识执法

`sim/vent` 导出 `VentHitObserver { onVentHit(attacker, target, now) }`，
`resolveVents` 增加可选第五参数；只有擂台外命中才回调。

依赖方向：`vent` 只定义端口，`detention` 实现端口，`server` 在组装层注入。
不新增模块、不引入事件总线：当前只有两种判定来源，第二套分发机制是投机抽象。

### 3. 三级响应：记录 → 私下警告 → 押送

- 第 1 次命中只写账本，玩家无感；
- 第 2 次命中发 `SYSTEM_NOTICE_KIND.AssaultWarn`，只发给攻击者本人，
  不经过 AOI 广播；
- 第 3 次命中建案：广播 `DetainedFight` 给看得见他的人，并就近派保安。
  建案后清空该攻击者的账本，押送途中与放出来之后都重新累计。

警告不走 `JAIL_PHASE.Warn`：那条阶段包的客户端文案固定为坐站骚扰，
换判定来源不该复用同一句话，也不该为了一个提示改 9 字节协议。

### 4. 复用小黑屋的全部处置与兜底

`confirm()` 的建案段抽成 `openCase(player, now, noticeKind)`，坐站骚扰与打人共用：
占反省点、写 `cases`、按 kind 套文案、`tryDispatch`。派单全忙时排队，
12 秒等不到保安按证据不足放人；拖行 15 秒、整案 40 秒仍是原有上限。
到达反省点即放人，没有禁足时长。

### 5. 清理

`update()` 按 5 秒节流调用 `pruneAttacks()`：删除断线 / 离场攻击者的整条记录，
裁掉窗口外的命中时刻。`dispose()` 清空账本。稳态下账本通常为空，遍历成本接近零。

## 代价与取舍

- 单向计数意味着互殴双方都可能被押走；这是可接受的，因为打架本身就该被管；
- 2 分钟窗口内的正常打闹（例如连续三次误伤同一个人）可能触发，但第 2 次已有私下警告；
- 警告走系统消息列表而不是黄条，提示位置与坐站警告不同；
- 账本按攻击者 + 受害者两级 Map，最坏情况是在线人数 × 平均目标数，实际只有极少数人打架。

## 备选方案（未采纳）

- 独立 `AssaultDetector` 模块 + 事件分发：职责更单一，但当前只有两种判定来源，属于投机抽象；
- 给 `Player` 增加命中历史字段：污染实体模型，且无法表达多次历史；
- 复用 `JAIL_PHASE.Warn` 或改 9 字节阶段包：为了一个提示改协议，旧客户端兼容成本不成比例；
- 只统计「对方没还手」：互殴无人被处罚，与「打架也招保安」的目标相反。

## 回滚

`GAME_JAIL_ENABLED=false` 或 `npc.count.guard = 0` 时不创建 `Detention`，
`resolveVents` 拿不到观察者，攻击不计数、不警告、不派单，行为回到本 ADR 之前。
账本只在内存，没有迁移成本。
