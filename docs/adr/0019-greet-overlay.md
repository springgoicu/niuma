# ADR-0019：打招呼——第三个叠加动作位（bit4）与图集扩到 34 列

- 状态：已采纳
- 日期：2026-11-03
- 关联：ADR-0018（叫唤与跳的叠加位）、ADR-0006 / ADR-0010（帧预算与 64 网格）

## 背景

园区里的牛马原本只会走、坐、躺、叫唤、跳。玩家靠近同事时缺一个「抬手示意」的动作，
而现成的叫唤只动嘴、跳是全身位移，两者都读不出「跟人打招呼」。

ADR-0018 的结论里写过：后续再加表情（挥手、鼓掌）「只需加列 + 复用同一对标志位的模式」。
真正动手时发现那句话有个前提没兑现——`state` 字节的 8 个位已经全部分配完：

```
bit0-1  direction
bit2-4  pose（3 bit，但 POSE 只有 0-3 四个值，最高位恒为 0）
bit5    moving
bit6    emote
bit7    jump
```

## 问题

- 没有空闲位可用，第三个一次性动作没有上行通道；
- 图集 25 列，站姿也没有挥手帧，更别说坐姿与躺姿；
- 服务端的准入规则是按位写的（行走中丢叫唤、放行跳），新增位必须决定自己站哪边。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. state 扩成 2 字节 | 位随便加 | move 包 14→15、sync entry 7→8，双端所有解析器、限速校验、压测脚本全要改；每个实体每 Tick 多 1 字节广播，只为放 1 个布尔位 | 中（协议版本分叉，回滚要双端同批） |
| B. 复用 pose 字段的最高位 bit4（采纳） | 包长、opcode、sync entry 全部不变；改动只落在位打包与选帧 | 旧客户端会把 bit4 读成 pose=4 而回落 idle，旧服务端会把姿态归 Idle 并丢位 | 低（同一份代码两端同批发布） |
| C. 把打招呼塞进 `POSE` 枚举 | 不动位布局 | 重演 ADR-0018 已否定的错误：姿态同时承担「身体形态」与「正在播什么」，坐着挥手播完会站起来，服务端还得记住并回滚上一个姿态 | 中 |
| D. 只改客户端 | 改动最小 | 别人看不到你打招呼，多人场景直接失真 | 低（但功能残缺） |

选 B。pose 的 3 bit 字段里第 3 位从来没有被用到过（`POSE` 只有 0-3），
把它当成「空闲位」用，比为一个布尔值给全网多付 1 字节/Tick 便宜得多；
C 的问题 ADR-0018 已经付过一次学费，不再讨论。

## 决策

### 1. state 字节：bit4 = 打招呼

```
bit0-1  direction
bit2-3  pose（Idle/Walk/Sit/Lie）
bit4    wave      一次性打招呼
bit5    moving
bit6    emote     一次性叫唤
bit7    jump      一次性跳跃
```

- `packState(direction, pose, moving, emote = false, jump = false, wave = false)`；
  新增参数放在末尾，既有调用点不用改。
- `unpackState` 的 pose 掩码从 `0b111` 收紧到 `0b11`，并返回 `wave`。
- 包长仍是 1 字节状态位：move 14B、sync entry 7B、opcode 都不动。

**混布降级**：旧客户端把 bit4 读进 pose 得到 4，`baseTracks[4]` 为空、回落到 idle——
看到的是「站着不动的人」；旧服务端 `sanitizePose` 把 pose 归 `Idle` 并丢掉 wave 位——
远端看不到挥手。项目本来就要求双端同批发布（地形同源、图集带版本校验），这属于可接受降级。

### 2. 服务端：与叫唤同一条准入线

`applyMove` 里把「站定」判据抽成一处：

```ts
const stationary = pose !== POSE.Walk && !state.moving;
player.applyState(dir, pose, state.moving, stationary && state.emote, state.jump, stationary && state.wave);
```

- 行走中丢弃叫唤与打招呼（图集没有行走张嘴帧，也没有行走挥手帧）；
- 跳跃继续放行（位移动作）；
- 仍然不做到期计时：起止以客户端 20Hz 包里的位为准，服务端只重新打包回传（ADR-0018 §3）；
- 切坐 / 躺时 `applyState(..., false, false, false)` 一并清掉三个位。

### 3. 图集：25 → 34 列

```
idle       0-2    不变
walk       3-8    不变
sit        9-10   不变
lie       11-12   不变
jump      13-15   不变
emote     16-18   不变
sitEmote  19-21   不变
lieEmote  22-24   不变
wave      25-27   站姿：抬前蹄 → 挥出 → 收回
sitWave   28-30   坐姿：同一套手势，坐下时用
lieWave   31-33   躺姿：贴地那截前蹄抬起来挥
```

- 每段 `frameMs: [220, 220, 220]`、`loop: false`，合计 660ms。叫唤与跳的 440ms 三帧
  压不出「抬起来 → 挥出去 → 收回」三个阶段，硬压会读成抽搐。
- 图集 1600×256 → 2176×256；每层切片 100 → 136，所有层仍共享同一批 `TextureSource`，显存不变。
- manifest 与 `sprite-layout.generated.ts` 的版本同时 6 → 7，`atlas.ts` 的版本校验会抓住漏改。

### 4. 选帧优先级：跳 > 打招呼 > 叫唤

`overlayTrackFor(overlays, pose, emoting, jumping, waving)` 仍是唯一入口：

- `Jump` 最优先，且不区分姿态（行走中起跳也走同一条轨）；
- `Walk` 直接返回 null，叫唤与打招呼都不接；
- 打招呼按姿态映射到 `wave / sitWave / lieWave`；
- 三个叠加动作在客户端置位时互斥（`startOverlay` 一次只置一个），这里只做兜底。

播放窗口 `waveMs = max(440, 图集实际长度) = 660`，与图集对齐，末拍「收回」不会被硬切。

### 5. 交互规则

| 输入 | 行为 |
|---|---|
| 站 / 坐 / 躺时按 E | 播对应姿态的挥手，姿态不变，播完仍保持原姿势 |
| 行走中按 E | 忽略，不置位，不打断行走 |
| 开始移动 | 立即清掉打招呼位（与叫唤同一条） |
| 切坐 / 躺 | 立即清掉叠加位 |
| 连按 E | 从第 0 帧重播 |
| 与叫唤 / 跳 | 互斥，后按的打断先按的 |

动作栏「打招呼 [E]」与键盘等价；键位选 E 是因为 Z/X/C/Space 已占用，E 贴着 WASD 且不在页面快捷键里。

### 6. 像素几何：只抬一条前腿

- 侧视：近侧前腿改用两段式 `drawRaisedLeg`（`drawLeg` 只能画到脚底线，蹄子必须落地，画不出「抬在空中」）；
  三拍的 `reach` 4 → 7 → 1、`lift` 2 → 4 → 1，蹄子停在胸口高度、探出躯干轮廓；
- 正视 / 背视：该侧前腿不画落地柱，改从肩点向外上方举；`reach` -8 → -10 → -5 让它甩出躯干剪影，
  只伸到胸口以内会与躯干同色叠在一起，读成「胸口多了一道浅色带」；
- 坐姿沿用坐姿基座（臀部下折、躯干不变），躺姿把贴地那截前蹄抬到躯干上方；
- 举腿会横过躯干，所以先在腿形外圈铺一道描边再落本体色——同色叠同色时，只靠外轮廓分不出「这是腿」；
- 三套都不参与呼吸、不张嘴，与「只动嘴」的叫唤在观感上不重叠。

## 后果

**收益**

- 打招呼与「身体形态」彻底解耦：坐着挥手播完还是坐着，不需要任何回滚状态；
- 协议零增量：字节数、opcode、发送频率都不变；
- 远端只多解析一个布尔位，丢包最多漏一次表现，不会永久抬手；
- 三套姿态共用同一份节奏表，加「鼓掌」之类的新动作只需再补枚举与列区间（但要先读下面的边界）。

**代价**

- 图集与 manifest 升到 v7，`public/sprites` 必须与 web 包同批发布；
- 新增两条回归线：`overlay-frames.test.ts`（挥手只抬一条前腿、不动头/嘴）、
  `clip.test.ts`（三条轨映射与优先级矩阵）；`layout.test.ts` 的一次性动作时长断言改成按动作取值；
- 像素校对仍要人眼看 `.proof/sheet-*.png`：自动化只能证明「差异落在前腿区域」，
  证不了「看起来像在打招呼」。

**边界（重要）**：`state` 字节至此 8 位用尽。再加动作有两条正路——
要么按「动作种类 3 bit + 独立 opcode 的旁路包」扩一条旁路通道，要么把 state 扩成 2 字节并接受包长变化；
**不要**再从 pose 里抠位，也不要继续往这个字节里塞语义。

## 回滚（30 天内）

- 协议位与资源在同一个提交里：`git revert` 即回到 v6（25 列）。
- 只想关掉表现而不动协议：让 `overlayTrackFor` 忽略 `waving` 入参——位、图集、
  服务端回传都还在，只是不播，属可逆降级。
- 反向操作（把 34 列图集留在仓库、只回退客户端）不可行：`atlas.ts` 的版本校验会直接报错。
