# ADR-0078：园区导览收窄到可互动设施（8 处）、指路牌改由 NAV_TARGETS 派生

- 状态：已采纳
- 日期：2026-11-13
- 关联：修订 ADR-0067（§3 目标清单、§4 指路牌五块牌）；沿用 ADR-0036（HUD 导览与世界指路牌）、
  ADR-0040（到达点与几何中心分离）、ADR-0049（96×92 牌面画布）、ADR-0070（发泄区）、
  ADR-0073（三人擂台）

## 背景

ADR-0067 把导览从 4 处扩到 13 处：四间房 + 游乐园 / 研发园 / 影音室 / 小黑屋 / 摸鱼亭 + 三湖 + 发泄区。
扩完之后玩家用起来有两类错位：

1. 导览是「去能动手的地方」，但清单里一半是静态观赏区——三湖、摸鱼亭、研发园、影音室走过去只能看，
   占了列表却帮不上忙；
2. 真正能按 F 报名的**擂台**反而没有入口，玩家得自己找。财神供案同理。

同一份清单还派生出了第二份真相：世界指路牌 `SIGN_PLATES` 手写 5 条 id，
用 `readings.find(...)?.octant ?? 0` 兜底。删掉一个目标时箭头不会报错，
只会静默指向正北——这是这次一起修掉的失败模式。

## 决策

### 1. 导览只认 8 处：四间房 + 可互动设施

| id | 名称 | area | 中心 | 到达点 |
|---|---|---|---|---|
| `workroom` | 工作区 | indoor | `WORKROOM` 中心 | 现状不变（`+230, +294`） |
| `meeting` | 会议室 | indoor | `MEETING_ROOM` 中心 | 现状不变 |
| `restroom` | 卫生间 | indoor | `RESTROOM` 中心 | 现状不变 |
| `lounge` | 宿舍区 | indoor | `LOUNGE` 中心 | 现状不变 |
| `shrine` | 财神供案 | indoor | `SHRINE_ALTAR` 案面 | 案前空地：案面底边外 18px |
| `park` | 游乐园 | grounds | `AMUSEMENT_PARK` 中心 | 现状不变（南门内侧） |
| `bossArena` | 发泄区 | grounds | `BOSS_ARENA` 中心 | 现状不变（垫内左下角） |
| `ring` | 擂台 | grounds | `RING_ARENA` 中心 | `RING_EXIT` 场边报名点 |

删除 7 项：`southYard` / `theater` / `jail` / `pavilion` / `lakeMoping` / `lakeChensi` / `lakeLianyi`。
售货机、咖啡机、饮水机、茶台、牛马榜、放假告示板与全部座位家具都不进导览：
它们要么成组重复（同类多台），要么靠走进房间自然发现，进列表只会稀释「去这里」的信噪比。

### 2. 擂台到达点取场边报名点，不取场地中心

`RING_ARENA` 对非参赛者是一块不能踏入的区域（移动被夹在围绳外，只能按 F 传送入场）。
A* 的终点若落在绳内，玩家会在围绳边上原地卡住；取 `RING_EXIT (3780, 5430)` 则天然闭环：
围绳外 40px、落在 `RING_NEAR_PX (96)` 报名半径内，落地就能按 F。

### 3. 财神供案归 `indoor`

供案在 `WORKROOM` 内，按真实空间分组，HUD 的「室内 / 园区」两段不需要加特例。
到达点取案面底边外 18px：比玩家半径 9px 多一倍余量，不压案腿也不贴香炉。

### 4. 世界指路牌从 `NAV_TARGETS` 派生，块数自适应

- 删除 `SIGN_PLATES` 与 `navReadings` 的 `find + ?? 0` 兜底；
- 新增 `apps/web/lib/game/signpost.ts`（纯计算、不引 Pixi）：`signPlates()` 过滤 `area === 'grounds'`，
  名称与顺序直接来自 `NAV_TARGETS`；`signPlateTop(index, count, height)` 给出每块牌的行位置，
  绘制与文字叠层共用同一份；
- 画布仍锁 96×92（ADR-0049，`layout-hub.test.ts` 断言几何），3 块牌在标题与「你在这里」之间垂直居中；
- 牌面从此只会「少一块」，不会「指错方向」——删目标不再需要回来改第二份清单。

### 5. 世界本身一个设施都不删

游乐园的四件器械、三湖、摸鱼亭、影音室、小黑屋、研发园全部保留：地形、碰撞、美术、区域命名不动，
玩家仍可步行抵达与观赏，只是没有一键前往入口。删导览与删世界是两件事，这次只做前者。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 保留 13 项，只补擂台与供案 | 改动最小 | 与「删掉不互动的」诉求相反，列表继续噪音化 | 否决 |
| B. 连世界设施一起删（游乐园器械、三湖、亭子） | 园区只剩互动内容 | 跨渲染 / 碰撞 / 寻路 / 地形测试；玩家仍想逛 | 否决 |
| C. 牌面仍固定 5 块，空位留白 | 绘制代码不改 | 牌面出现空白纸牌，且仍要维护第二份清单 | 否决 |
| D. 8 项 + 牌面按 grounds 派生、块数自适应（采纳） | 契约变薄、单一真相、静默指北消失 | 一次性动 shared-types 与 welcome 烘焙层 | 采纳 |

## 后果

- 契约层少 7 个 `NavTargetId`、7 个到达点；新增 `ring` / `shrine` 两项，`NAV_TARGETS` 仍是导览卡、
  指路牌、A* 与测试的唯一真相；
- HUD 导览卡分组计数变为室内 5 / 园区 3，8 行无需滚动，`NavCard` 与寻路链路零结构性改动；
- 指路牌从 5 块变 3 块（游乐场 / 发泄区 / 擂台），删掉一份手写清单；
- 回归口径：`nav-arrival.test.ts` 断言 8 个到达点可站立、不撞碰撞体、不落水，擂台到达点在 `RING_ARENA`
  外且在报名半径内，财神供案到达点在 `WORKROOM` 内；`pathfinding.test.ts` 断言 8 个目标从出生点与广场中心
  皆可达；`signpost.test.ts` 断言牌面恰为 grounds 目标且行位置单调、不压标题与底牌；
- 回滚：把 `NavTargetId` / `NAV_ARRIVALS` / `NAV_SOURCES` 恢复成 13 项，并在 `welcome.ts` 恢复
  `SIGN_PLATES` 与固定 5 块的行布局即可；`signpost.ts` 可以保留（回滚后牌面会变成 9 块，需同时收窄过滤条件）。
