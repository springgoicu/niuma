# ADR-0108：帧节拍上限与低帧自适应画质

- 状态：已采纳
- 日期：2026-11-16
- 关联：分带深度沿用 ADR-0024；渲染线程与主线程回退沿用 ADR-0049；WebGL2 默认后端沿用
  ADR-0071；共享运行态落盘范围不变（ADR-0081）

## 背景

玩家反馈「游玩感觉卡」。排查后确认不是单一原因，而是三层彼此独立的开销叠在一起：

1. `GameSession` 注册 ticker 时没有设 `maxFPS`，Pixi 默认 `0` 即跟随显示器刷新率。
   120/144Hz 设备上同一套玩法逻辑、排序与填充每秒被算两遍以上，纯属白烧。
2. `SortLayer.update` 无条件写 `zIndex`。带 `sortableChildren` 的 band 收到一次真实写入
   就会标脏并整块 `sortChildren`（O(n log n)）。站立 / 坐着 / 靠墙的角色 y 逐帧恒定，
   等于每帧为「什么都没变」重排一次。
3. 渲染线程崩过一次后会写入回退标记，此后整个标签页一律主线程渲染，而 HUD 从不显示
   当前宿主，玩家无法自证「为什么就我卡」，也没有自救入口。

另有两点属于**不该动**的：高 DPR 的 backing store 与设备像素 1:1 是像素画风的地基，
封顶会引入非整数重采样；光图分辨率降低会让夜景糊成色块。所以画质降档只允许发生在
非关键观感层。

## 决策

### 1. 帧节拍默认 60，显式可回退

`session.start()` 在挂 ticker 前设置 `maxFPS = resolveTargetFps(env.search)`：缺省 60，
`?fps=0` 表示不设上限（与改造前等价），`?fps=30|120|240` 按原值，空串 / 小数 / 超区间回落 60。

安全性来自既有约束，而不是新增假设：`tick` 内已有 `Math.min(deltaMS, 50)` 钳制，
远端插值按毫秒推进，网络同步是包驱动，节拍减半不改变任何位置或动画的时间语义。

### 2. 静止角色免深度重排

`SortLayer.update` 在换 band 前先判「同容器且深度值相等」并直接返回。band 顺序仍等价于
y 顺序（ADR-0024 只依赖 y 的单调性，与是否重复写同值无关），走动角色 y 每帧变化，
行为与改造前逐帧一致。

### 3. 低帧自适应只降非关键观感

`quality-tiers.ts` 的三档状态机按 2Hz 的既有 stats 窗口推进：连续 3 个窗口低于 45 降一档，
连续 12 秒高于 55 升一档，45–55 为滞回区，`fps <= 0`（尚未测出）不参与判定。

| 档位 | 光图 screen 层 | 飘雪 | 远景昵称 |
|---|---|---|---|
| high | 开 | 开 | 全量 |
| balanced | 关 | 开 | 全量 |
| low | 关 | 关 | 只保留玩家 420 纹素内（260 内回升） |

**刻意不动 DPR、光图分辨率、角色与地形**：那是画风与手感，不是「降一档画质」。
昵称预算用两段距离阈值做滞回，避免站在边界时名字闪烁。

### 4. DPR 封顶只作显式自救

`?dpr=1|2|3` 才会压 backing store，缺省 `0`（不封顶）与改造前一字不差。封顶在 `init` 与
`resize` 走同一个 `capDpr`，拖动窗口跨屏时口径一致。

### 5. 渲染宿主可见化与一次性重试

`EngineEnv.renderMode` 由两个宿主（worker / main）各自填值，经 `SessionStats` 到 HUD。
渲染线程崩溃回退后，状态段显示一枚琥珀色「主线程」角标，点击执行
`clearRenderFallback()` 并摘掉地址上的 `render` 参数后重载。

**不钉 `?render=worker`**：该参数会永远盖过回退标记，Worker 再次崩掉时用户会被困在
「刷新 → 又崩」的循环里。清标记 + 清参数让这次重试只发生一次，失败就再回退并重新记标记。

### 6. 搬砖面板倒计时直写 DOM

倒计时文本与进度条改走 ref，React 只在轮次切换与按键时重渲染。`toFixed(1)` 本身只有
10Hz 有效变化，进度条原有 `duration-100` 过渡保留，观感逐帧等价，但面板打开期间不再
以 30Hz 让带 `backdrop-blur` 的整块面板重新合成。

## 取舍与备选

- **不把 DPR 硬封顶**：能在高 DPR 手机上立刻砍掉约一半填充，但 backing store 与设备像素
  脱钩后像素块边界会出现 4/5 设备像素交替，属于全站画风降级。改为显式开关。
- **不把帧率压到 30**：30Hz 下走路与飘字的抖动肉眼可见，60 是观感与开销的平衡点。
- **不做静默降档**：降档会改观感，玩家必须能看见（角标 + 日志），否则「为什么我的雪没了」
  会变成新的困惑。
- **不引入新依赖、不新增计时器**：档位推进复用 2Hz stats 窗口，昵称预算复用既有的逐帧
  可见性循环。

## 后果

- 高刷屏设备回调与填充各减半；广场站立人群不再产生 band 重排；低帧机器自动退到可玩的
  观感档位，恢复后自动回升。
- 回退到主线程的玩家第一次能看见自己的状态，并有一次自助重试机会。
- 所有新行为默认值与改造前等价，可用 `?fps=0`、`?dpr=0` 在线上即时对照。
- 新增三条纯函数测试（帧节拍、画质档、DPR 上限）与深度早退判定，均不依赖 DOM 或 Pixi。
- 不涉及任何落盘状态；`world-state.json` 范围不变（ADR-0081）。
