# ADR-0100：弱交互场所的演出只做客户端，不改协议与碰撞

- 状态：已采纳
- 日期：2026-11-15
- 关联：沿用 ADR-0024（轻互动留在客户端）、ADR-0030（水域可涉水）、ADR-0045（河道小鱼）、
  ADR-0067（游乐园转静态观赏区，`0x2a` / `0x2b` 永久留空）、ADR-0081（落盘范围）、
  ADR-0093（入座类玩法「先坐下」口径）

## 背景

会议室（8 把会议椅 + 北墙投屏）、家庭影音室（15 张影厅座椅 + 大屏 + 4 只音箱）、
游乐园（摩天轮等静态器械）与摸鱼亭（4 张石鼓凳）四处已经建好，但除了「坐一下、抬起来」
之外没有任何反馈：投屏永远是同一张静态 OKR，大屏是一幅不动的夜空，摩天轮是一个静态精灵，
涉水涟漪只有 20×10 的 3 帧、小鱼完全不感知玩家。

想盘活它们，有三条路：

1. **加状态、加协议**：服务端记「谁在开会 / 在放什么片」，新增 opcode 广播；
2. **加共享热区**：把「按 F 发言」登记进 `WORLD_HOTSPOTS`，服务端一并校验；
3. **只做客户端演出**：读现成的 `S2C_SEAT_STATE`，画面、气泡、闪光全部本地生成。

前两条都会把「看片 / 开会」变成玩法：要落盘、要发版、要和服务端对齐距离门，
还要跟 90px 的座位感应圈抢同一次 F；而这四处的价值恰恰是**氛围**而不是规则。

## 决策

### 1. 屏幕演出 = 静态底图 + 1~2 个动件

投屏与大屏不再「每个频道烘 8 帧」：每块屏只烘一张底图，动件（列车车厢、老板头像两帧、
DVD 方块、小舟、激光笔）各是一张小贴图，按绝对时间落在**整数像素**上平移或换帧。

- 会议室 3 张幻灯片（甘特 / 折线 / 饼图）每 4s 换一张，无人入座时被一层待机遮罩压暗；
- 影厅 4 个频道，换台只换底图 + 动件 + 光晕 tint，纹理总数 ≈ 16 张、最大 256×60。

### 2. 摩天轮：静态轮盘 + 六只吊舱沿整数圆环步进

八根辐条按 45° 自对称，转 45° 后与自身重合——**旋转的视觉线索全部来自吊舱**。
因此把 `drawFerrisWheel` 拆成静态底（腿 / 轮圈 / 辐条 / 桅杆旗）与吊舱贴图，
构造期生成 72 步整数圆心 LUT（`Int8Array`），帧循环按 `(step + i × 12) % 72` 摆六只吊舱，
吊舱始终直立（真实摩天轮不翻转）。一圈 24s，每步约 5px。

好处：零新增帧烘焙、零浮点旋转（不糊边）、零每帧分配；彩灯是 12 个 3×3 精灵，
夜间增益 30s 采样一次，白天整圈不画，**不占 `MAX_LIGHTS` 预算**。

### 3. 影厅压暗放在 y 排序层之后

影院开场感由一层半透明暗色承担：覆盖「屏幕下沿 → 房间南墙」，本地坐在 `cinema` 座椅上时
alpha 平滑收敛到 0.22，起身回落。它挂在排序层之后、昵称之前，所以连角色一起暗下去，
而屏幕本身不进暗区——否则读起来是「停电」而不是「开场」。

### 4. F 交互的唯一真相是 `venue-spots.ts`

新增客户端模块 `venue-spots.ts`（纯函数、可 `bun:test`）集中四件事：

- 屏幕矩形（从 `MEETING_ROOM` / `THEATER_SCREEN` 派生，渲染与演出共用）；
- 座位归属（会议椅 / 影厅椅 / 石鼓凳 / 园内长椅，构造期建 id 表）；
- 本地点与台词（会议 / 禅意 / 拍照 / 怀旧），以及静置气泡节流阈值；
- 影厅 4 个频道的名称与主色。

**坐姿类 F 只在坐下后生效**（会议椅 / 影厅椅 / 石鼓凳），站立时提示仍然是「按 Z 坐下」——
这样既不会跟座位感应圈抢同一次按键，也不破坏既有的入座类玩法口径（ADR-0093）。
游乐园打卡点（秋千 / 跷跷板 / 旋转木马 / 沙池 / 喷泉）是站位类，半径 56，与长椅坐点保持
≥150px，同样不抢提示。

占用人数只读 `S2C_SEAT_STATE`：渲染层在 `setSeatOccupied` 的**变化沿**上加减会议室 / 影厅人数，
重复广播不会把人数越加越多；服务端零改动。

### 5. 涟漪与小鱼复用既有通路

- 涟漪池沿用 `WaterFx`：帧数 3 → 4（环半径 3/6/9/14，画布 28×14），池 24 → 36，
  新增 `spawnWake()` 作为「涉水扩散大圈」（380ms 最多一枚），入水大水花仍是 `spawn(x, y, true)`；
- 小鱼只在 `stepFish` 末尾加三个标量：`alarmMs` / `dodge` / `heading`，
  玩家进入 56px 才触发（`playerX/Y` 默认无穷远，无玩家场景与旧版逐帧一致）。

### 6. 灰度开关

- `?motion=0`：本次全部新动效冻结在第一帧（吊舱停在 0 步、彩灯不闪、屏幕停在上电画面、
  音符与闪光不生成），静态观感不变；
- `?venue=0`：投屏 / 大屏 / 压暗 / 闪光四层整层不构造（与 venue 装饰层同一条关法）；
- `?light=0` / `?festival=0` / `?flat=1` / `?bands=0` / `?season=winter` / `?fish=0` 均不冲突。

### 7. 发版边界

本次**不改 `packages/shared-types`**：没有新增或修改碰撞体、坐标、`WORLD_HOTSPOTS`、
`NAV_TARGETS`；没有新增 opcode，`0x20` / `0x2a` / `0x2b` / `0x3d` / `0x4d`–`0x50` 继续留空。
因此**无需双端同步发布**，只有客户端发版。

## 备选方案

- **每频道多帧烘焙**：4 频道 × 8 帧 = 32 张 256×56 纹理，换台还要管帧序列；
  末帧与首帧的接缝比一张底图 + 一个动件更难对齐。
- **Sprite 旋转摩天轮**：`rotation` 是浮点，1:1 整数纹素下必然糊边；改成 24 帧烘焙则是
  24 张 172×182，收益与「吊舱沿圆环走」完全相同但贵一个数量级。
- **服务端记放映状态**：会进入「共享运行态」的落盘范围（ADR-0081），却只影响几米内的观感，
  属于把氛围成本转嫁给所有人。
- **新增 `WORLD_HOTSPOTS`**：热区是服务端校验表，加四条要双端发版，
  还会让「开会 / 换台」变成需要服务端裁决的玩法，与本 ADR 的取舍相反。
