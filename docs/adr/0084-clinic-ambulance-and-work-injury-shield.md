# ADR-0084：护士急救站——救护车拖拽、床位治疗与工伤保护

- 状态：已采纳
- 日期：2026-11-15
- 关联：服务端 NPC 沿用 ADR-0061；护士角色字段沿用 ADR-0063；救护车直接写坐标沿用
  ADR-0003 的 AOI 与 ADR-0043 的 dirty 同步；零持久化沿用 ADR-0004；状态广播沿用
  ADR-0038；压缩状态包沿用 ADR-0035

> 编号说明：需求原写作 ADR-0077，但仓库里已有
> `0077-map-tighten-restroom-jail-and-park.md`，为避免改写历史 ADR，本决策顺延为 0084。

## 背景

发泄区的「创飞」是园区最常用的互动，但连续被打飞只带来位移与两秒硬直，没有可感知的
后果，也没有恢复路径。需求是让「被创飞 3 次」变成一次完整事件：昏迷 → 救护车出警 →
拖回急救站 → 病床治疗 → 带着工伤保护回到园区。

约束：

- 判定必须服务端权威，客户端只做表现；
- 救护车必须看得见地开过来、装人、开回去，不能把伤员直接传送；
- 急救状态只活在进程内存，断线、重连、重启即清除（ADR-0004）；
- 不为一次玩法新增持久化，也不把救护车坐标塞进 20Hz 的常规移动通道；
- 病床是座位而不是新实体系统：复用现有座位、姿态与座位同步，避免两套「躺着」的真相。

## 决策

### 1. 急救站只做地图数据与两个座位

`CLINIC_RECT = { x: 5000, y: 4260, w: 248, h: 210 }`、`CLINIC_COUNTER`、`CLINIC_BEDS`、
`CLINIC_AMBULANCE_SPOTS` 与 `CLINIC_DROP` 全部放进 `shared-types/world`。铺装并入
`paved`，导医柜台与两张病床的头尾边并入 `solids`（kind 用已有的 `desk` / `fixture`），
区域名并入 `REGIONS`，树木生成在站点外扩 60px 内避让。站点落在东侧主路尽端南侧，
刻意避开小黑屋、研发园东墙与家庭影音室，避免与 ADR-0077 的新地图几何重叠。

病床同时是 `SeatInstance`（`kind: 'bed'`），`CLINIC_BED_SEAT_IDS` 暴露给急救管理器直接
占用。床面中段不设碰撞，伤员才能被放到床心躺下；治疗结束从床尾外侧站起。

### 2. 受击计数：相邻两次命中不超过 15 秒，连续 3 次触发

`AmbulanceManager.observeHit()` 与执法共用 `resolveVents` 的命中回调，只统计：

- 非擂台、非座位、非昏迷、非工伤保护中的目标；
- 同一个攻击者反复命中同一目标同样计数；
- 距上一次命中超过 15 秒就从 1 重新计数，连续第 3 次命中 → `downPlayer()`：
  强制 `POSE.Lie`、`incapacitated = true`、清空座位、广播 `PATIENT_STATE.Incapacitated`，
  并按 id 顺序派第一辆空闲救护车；两辆都在任务时进入 FIFO 队列，先昏迷者先上车。

处于昏迷或工伤保护的目标在 `resolveVents` 里按空放处理：不击退、不硬直、不计数，
也不会被穿透打到身后的人。

### 3. 救护车四态 + 固定 Tick 步进

状态机 `Idle → Dispatched → Transporting → Returning → Idle`，两辆车各自独立：

| 阶段 | 行为 |
|---|---|
| `Dispatched` | 从车位出发，先走「东侧空地 → 南向主路」两段固定航点，再从路口追伤员当前坐标；距离 ≤ 48px 装人 |
| `Transporting` | 每 Tick 把伤员放在车头反方向 26px，沿「南向主路 → 东侧空地 → `CLINIC_DROP`」运回 |
| `Returning` | 空车回自己的车位，到达后 `Idle` |

没有寻路，但也不是一条直线：出警先沿 `(5200, 4755)` 的东侧空地航点，再沿
`(4096, 4755)` 的研发园南缘 / 南向主路航点，最后才追伤员；送回时反向走同一条
走廊，避开研发园与小黑屋的实心墙。每段航点最多磨 8 秒，超时直接贴到航点，
避免救护车卡在墙角。速度取基础移速的 1.6 倍，出警与返航同速。装人失败
（伤员断线、已被其它车接走、已不在昏迷）一律放空返航，不重试排队。

### 4. 治疗与工伤保护

到达落点后优先占用空病床：`seats.occupy()` 把伤员放上床心并 `POSE.Lie`，广播座位变化，
再广播 `PATIENT_STATE.Treating`（3 秒）。两张床都满时不占座，原地完成同样的 3 秒计时，
避免「没床就永远治疗中」。

计时结束：

1. `seats.stand()` 释放床位，把伤员移到床尾外侧站立；
2. `incapacitated = false`，清空受击计数；
3. `immunityUntilMs = now + 15s`，广播 `PATIENT_STATE.Shielded`。

护盾期间：免疫一切创飞（不位移、不硬直、不计数），主动出招仍然正常；再次被创飞不会
累计。断线立即清除车内挂载、床位计时与护盾。

### 5. 协议：8 字节救护车包 + 6 字节伤员包

`S2C_AMBULANCE = 0x31`：`[op][id u8][state u8][x u16][y u16][flags u8]`

- 坐标与 Tick 共用 1/8 像素量化；
- `flags bit0` 警灯鸣闪、`bit1` 车内有伤员；
- 停靠且状态未变的 Tick 不重发；新连接入场由 `sendSnapshot()` 单独补一次。

`S2C_PATIENT = 0x32`：`[op][entityId u16][state u8][seconds u16]`

- `state`：0 无 / 1 昏迷 / 2 治疗中 / 3 工伤保护；
- `seconds`：治疗倒计时或护盾剩余秒数，客户端只用于文案与倒计时，判定仍在服务端；
- 状态只在跃迁时广播，不跟 20Hz 心跳。

旧客户端不认识 `0x31` / `0x32`，走 default 静默忽略，不影响正常同步。

### 6. 客户端表现

- 站台、病床、车位、柜台与两辆救护车走像素图形；救护车警灯沿用 400ms 红蓝相位；
- 昏迷：伤员 `POSE.Lie` + 头顶转圈星星 + 气泡「等救护车」，本人输入被 `incapacitated` 冻结；
- 治疗：病床躺姿 + 护士头顶爱心气泡 + 本人提示「3 秒后原地复活」；
- 治愈：头顶绿色十字盾牌 + 浮动文字 + 轻量提示音；15 秒后由下一次状态包收起；
- 护士是服务端 NPC：白制服、护士帽、固定站桩，站位与 `CLINIC_NURSE_SPOTS` 一致。

### 7. 回滚

不新增开关。需要回滚时删掉 `AmbulanceManager` 的实例化与两个协议分支即可：

- 病床退化为普通座位，仍可坐下；
- 护士退化为普通 NPC，仍会巡逻与打招呼；
- 地图多出的铺装与人行道不阻塞任何既有路线。

## 代价与取舍

- 救护车用两个固定航点绕开研发园与小黑屋，不做逐帧寻路；代价是不在东侧空地附近的
  伤员都要先绕到主路口，路径比直线长，但不会穿墙；
- 治疗 3 秒是短事件而不是惩罚：让「被打飞」有恢复成本，但不把玩家长时间锁在病床；
- 15 秒护盾会让连击节奏断档，属刻意设计：给被创飞者一个明确的「别再打了」窗口；
- 伤员坐标每 Tick 直接写，客户端不做插值预测，拖拽中会有轻微台阶感，与被押送一致。

## 备选方案（未采纳）

- 客户端判定命中并上报：可伪造，跨端不一致；
- 伤员直接传送到病床：违反 ADR-0061 的可信度约束，看不到救护车过程；
- 为救护车新增全图 A*：矩形地块内直线可达，寻路只会增加 Tick 开销；
- 把急救状态写进 `world-state.json`：属于本人会话，不属于园区共享运行态（ADR-0081）；
- 复用 `stunUntil` 表达昏迷：床位治疗与拖拽需要独立状态，硬直时长无法表达「正在车上」。
