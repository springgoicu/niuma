# ADR-0114：NPC 伤员排队等车，开服清空站内闲人

- 状态：已采纳
- 日期：2026-11-16
- 关联：急救站与两车两床沿用 ADR-0069 / ADR-0092；NPC 一击即倒与排队兜底沿用 ADR-0106；
  站内门禁与「治好的伤员自己走出去」沿用 ADR-0107；护士值守与交接沿用 ADR-0109；
  押送员昏迷撤案沿用 ADR-0113；零持久化沿用 ADR-0004 / ADR-0081

## 背景

ADR-0106 给 NPC 定了一击即倒：任何真实命中都直接进救护链。送医频率因此显著高于真人，
而急救站只有两辆救护车、两张床，`sim/clinic.advanceQueue` 的兜底是「排队满 6 秒就地包扎」。
救护车往返要走两段固定绕行（ADR-0097），一轮出警 + 3 秒疗程通常 20~28 秒，所以实际表现是：

1. 玩家在押送 / 盯梢途中把保安或同事打倒，两辆车恰好都在任务里；
2. 伤员进内存队列，6 秒后 `healInPlace` → `restoreNpc` → **在倒地原地站起来**并进入 15 秒免疫；
3. 玩家看到的是「打倒了却没有任何车出发、人自己爬起来了」，而急救站其实一直在正常运转。

同一套兜底还有两个结构性问题：

- `tryDispatch` 只按「第一辆 Idle 车」派车，没有「同一名伤员最多一辆车」的不变量：
  一旦队列里出现重复条目（护士被打倒重入队等），两台车会一起追同一个人、一起在落点等交接，
  两辆车被一个伤员占死，后面的人只能排队到就地包扎；
- 队列只校验 `player.incapacitated`，不剔除已经挂上车或已经躺上床的人，留着就会派空车。

另外站内会残留站着的人：床尾康复的伤员、落点地面治疗的伤员都要自己走出站门（ADR-0107），
他们的位置在站体内部，开服时也可能出现站在站内的闲人。

## 决策

### 1. 排队兜底按实体类型分支

```ts
const HUMAN_QUEUE_TIMEOUT_MS = 6000;   // 真人：绝不让玩家卡在无限等待里
const NPC_QUEUE_TIMEOUT_MS = 45000;    // NPC：给足两轮救护车往返，真卡死才就地包扎
```

`advanceQueue` 按 `player.isNpc` 取不同上限。NPC 的 45 秒不是「更长的卡死容忍」，
而是让「排队等车」在观感上真的还是等车：空车一回来立刻出警，走完上车、交接、床位、
治疗后由 `NpcRestorePort.restore` 续接巡逻（押送案已按 ADR-0113 当帧作废）。

真人口径不变：6 秒没车就地包扎，ADR-0106 的防卡死保底保留。

### 2. 一名伤员只允许一辆车

`tryDispatch` 开头先查「是否已有车以该伤员为目标」，是则直接返回已接管（把队列条目清掉）；
`advanceQueue` 另外剔除 `carriedBy !== 0`、`beds.has(id)` 的条目。派车语义因此从
「有空车就派」收紧为「没人接才派」，两台车不会被同一个伤员占死。

### 3. 开服清场只在启动时做一次

`AmbulanceManager.evictIntruders(now)` 遍历在线实体，把 `isInClinicInterior` 为真、
且不属于急救链的实体移到西门外 60px（`CLINIC_REGION_RECT.x - 60`，仍在服务广场铺装），
清坐标状态、刷 AOI，NPC 额外走 `NpcRestorePort.restore` 重新锚定行为态，避免下一拍拿旧路径走回站里。

跳过对象：护士、`incapacitated`、`carriedBy !== 0`、`beds` 里的床位伤员、`tweens` 里的挪床过渡。
`server` 在 `npcs` 与 `clinic.setNpcRecovery` 装配完成后调用一次，并打印被清人数。

不做持续规则：治疗中的床位伤员、挂车途中的伤员与护士本来就该在站内，持续清扫会和急救链抢人；
落点也刻意放在区域矩形之外，只清出站体、还堵在门口铺装上的话，护士接人的走廊照样会被占。

### 4. 不落盘、不改协议

清场只改内存坐标（ADR-0084），不发新包：位置继续走既有 AOI 刷新，姿态继续走 `S2C_POSE`。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 维持 6 秒兜底，只加派第三辆车 | 出警更快 | 第三辆没有停车位，南侧通道口与站内床位几何不够（ADR-0092 / ADR-0107 预算） | 否决 |
| B. 取消所有实体的排队兜底 | 谁都不会自己站起来 | 真人两车都忙时会无限躺着，违反 ADR-0106 的防卡死口径 | 否决 |
| C. NPC 排队上限 45 秒 + 唯一派车 | 观感仍是等车，两车不被占死 | NPC 可能躺 20~30 秒等车 | 采纳 |
| D. 每 Tick 持续清场 | 站内永远只有护士 | 与床位、落点治疗、挂车尾抢人，会把伤员反复搬走 | 否决 |
| E. 每次康复后强制送出站 | 站内不留人 | 与 ADR-0107「自己走出去」口径冲突，且等于一次瞬移 | 否决 |
| F. 只加开发期 GM 清理命令 | 零玩法改动 | 用户要的是正式开服口径，正式服仍会残留 | 否决 |

## 后果

- 押送 / 盯梢中的 NPC 被打倒后一定有车接：空车立刻出警，两车都忙时排队等车，不再原地起身；
- 真人玩家两车都忙时仍在 6 秒后就地包扎，急救链不会把玩家卡在无限等待里；
- 重复入队的伤员不会再骗走第二辆车，`releaseNurse` 场景的出警时长可预期；
- 开服时站内只剩护士与急救链正在管的人，其余实体出现在西门外铺装；
- 站内闲人清理是**一次性**的，运行期新走进来的人仍由门禁（ADR-0107）挡；
- 单测：`sim/clinic.test.ts` 新增「排队出警与开服清场（ADR-0114）」四条（NPC 不 6 秒起身、
  真人仍 6 秒包扎、清场跳过护士、床位伤员不被清走）；
- 回滚：把 `NPC_QUEUE_TIMEOUT_MS` 改回 6000、删掉 `tryDispatch` 的已接管判断与
  `advanceQueue` 的 `carriedBy` / `beds` 剔除、删掉 `evictIntruders` 与 `server` 的调用；
  坐标与协议零影响。
