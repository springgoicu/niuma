# ADR-0068：设施感应提示改为可点按钮，键鼠共用同一条动作路径

- 状态：已采纳
- 日期：2026-11-13
- 关联：沿用 ADR-0054（牛马榜公告栏）、ADR-0059（放假告示板 64px 感应与面朝判定）、
  ADR-0061（财神供案与茶台）；ADR-0067 已下线滑梯互动，本次覆盖范围随之不含滑梯

## 背景

玩家靠近可互动设施时，HUD 只弹一条纯文本提示（「按 Z 坐下」「按 F 查看牛马榜」）。
键盘玩家可以直接按键，但鼠标与触屏玩家看到提示后没有可点的目标：动作条上的
「坐下 / 躺平 / 互动」是通用按钮，并不知道玩家此刻站在哪件设施旁。

需求是「靠近设施时自动显示的提示本身就是按钮，点击即可完成互动」，同时键盘
快捷键与出现时机完全不变。约束：

- 提示仍以字符串经 `onHint` 从 Worker 传到主线程，不改协议、不改 `session` 判定；
- 提示有三种落位（桌面 / 触屏 / 竖屏）与两种说法（键帽 / 触屏按钮名），只在视图层分叉；
- 纯状态与劝阻文案（「移动即可起身」「座位上不能躺」）不能被误渲染成按钮。

## 决策

### 1. 文案到动作用显式映射表，归 `hint-copy` 所有

`hint-copy.ts` 是提示文案唯一事实源，映射表也放在这里：

```ts
interface HintButton {
  action: ActionKey;
  label: string; // 按钮上的动作名
  key: string;   // Z / X / F，同时用于 aria-keyshortcuts
}
function hintButton(hint: string): HintButton | null;
```

映射表用 `Record<HintCopy, HintButton | null>` 而不是 `Partial`：新增提示却忘了
归类时编译期直接报错；劝阻文案显式写 `null`，让「不可点」成为被记录的决定，
而不是查找失败后的兜底。不从「按 Z 坐下」里正则抠键帽——文案改字不会破坏点击行为。

覆盖 8 条当前可执行的提示：座椅 / 马桶 → `sit`，床 → `lie`，牛马榜 / 告示板 /
通用互动 / 财神 / 茶台 → `interact`。滑梯已按 ADR-0067 下线，不在表内。

### 2. 点击复用键盘动作路径，不新增互动规则

`InteractionHint` 的 `onClick` 只调用 `GameViewport` 已有的
`handleAction(action)` → `client.perform(action)`，与 Z / X / F 走同一条
Worker 动作通道。视图层不判断距离、不判断姿态、不猜设施 id：距离与合法性仍由
`session` 权威裁决。

### 3. 落位沿用旧提示，按钮自己接管指针

- 告示板提示继续贴右下角（ADR-0059 的 64px + 面朝判定不变），其余提示底部居中，
  桌面 / 触屏 / 竖屏三套偏移照旧；
- HUD 覆盖层保持 `pointer-events-none`，只有按钮 `pointer-events-auto`；
  角色点选监听在同一层的兄弟节点上，点击不会穿透；
- 鼠标 `mousedown` 阻止默认焦点转移，点完按钮后方向键 / 空格仍归游戏键盘；
  键盘用户仍可 Tab 到按钮并用 Enter / Space 触发；
- 按钮带可见动作名、键帽、`aria-keyshortcuts` 与含动作名的 `aria-label`。

### 4. 双端说法与动效

桌面显示键帽 + 「点击」，触屏不显示键帽、显示「轻点」，点击后 8ms 震动；
入场动画只跑 transform / opacity 180ms，全站 `prefers-reduced-motion` 规则自动归零。
非互动提示保留 `role="status"` 的纯文本胶囊，不再套按钮样式。

### 5. 顺手修正告示板错字

`HINT.bulletin` 的「查解放假倒计时」改为「查看放假倒计时」，触屏投影同步；
仅改文案，不触碰 ADR-0059 的感应逻辑。

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 从桌面文案正则解析键帽与动作 | 不加映射表 | 文案改字即断点击；劝阻文案容易被误判 | 否决 |
| B. 世界里跟着设施飘的浮动按钮 | 指向更直观 | Worker 无投影能力，主线程无每帧设施坐标，需新增同步通道 | 否决 |
| C. 把提示升级成结构化协议（action + label） | 视图层无需映射 | 改协议与 session 输出，收益不抵一次跨线程契约升级 | 否决 |
| D. 在 `hint-copy` 加映射表 + 视图层双形态（采纳） | 协议零改动、键鼠同路径、映射可穷举测试 | 新增提示时要同步维护映射表（编译期会提醒） | 采纳 |

## 后果

- `hint-copy` 从「文案表」升级为「文案 + 动作映射」的唯一事实源；新增互动设施时
  需要同时补 `HINT`、`HINT_BUTTONS`、`TOUCH_HINTS`，漏掉映射会编译失败；
- 两组测试兜底：`hint-copy.test.ts` 穷举 8 条可互动提示与 3 条劝阻文案，
  `interaction-hint.test.tsx` 断言双端形态、键帽显隐与告示板落位；
- 视图层多一个无状态组件，`GameViewport` 的旧提示块被整体替换；提示出现 / 消失
  仍由 `session.updateSeatHint()` 的事件驱动，无每帧开销；
- 回滚：把 `GameViewport` 换回旧文本块并删除 `InteractionHint` 即可；
  映射表与文案修正可独立保留，不影响键盘行为。
