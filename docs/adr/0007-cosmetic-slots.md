# ADR-0007：配件迁到头顶 / 眼线 / 颈线，锚点按帧列推导

- 状态：已采纳（文中的 48×48 像素坐标与 16×16 图标已由 ADR-0010 改为 64×64 与 20×20；挂点仍由 landmarksOf 推导）
- 日期：2026-10-30

## 背景

角色是 48×48 的大头小身：正面朝下时头占 `x14..30 / y12..25`，口鼻占 `x18..26 / y20..25`，
躯干 `y22..33`，腿从 `y30.4` 起。扣除头与口鼻之后，**胸口只剩 `y25..30` 约 16×5 格**。

原来的三类配件（工牌 / 领带 / 嘴里叼着）全部压在这条窄带上：

- 工牌 7×8 卡片落在 `y21..28`，压住口鼻下缘；挂绳画在 `y18..21`，直接落在脸上。
- 领带从 `y26` 垂到 `y34`，穿出躯干底边；侧面画在 `x24..28` 的躯干内部，而颈前缘在 `x29..34`。
- 叼着的咖啡锚点 `x32`，嘴在 `x18..26`：杯子悬在脸右下 6px 外。
- 默认外观同时带工牌与领带，两者在胸口叠成一坨。

同时锚点表本身有两处结构性缺陷：

1. **不分物种**：马的头比牛高 2.2px（正面 headCY 16.6 vs 18.8），侧面高 3.2px。
2. **不随姿态**：坐姿头下移 9px、侧面躺姿下移 20px，而锚点是按朝向写死的常量。
   捏人页的坐/躺预览里配件会整块悬空——这是「视觉效果差」最直接的一环。

此外，朝上（背面）时三类配件仍然画在后脑与后背上，物理上不可见。

## 决策

1. **部位迁移，字节只换语义不换长度**：`cosmetics` 的 `badge / tie / mouthItem`
   改为 `headwear / eyewear / neckwear`，字节槽位仍是 `[15][16][17][18]`，`[19]` 继续保留，
   `APPEARANCE_BYTES` 仍为 20。`encodeSpawn / encodeHello / encodeSetAppearance` 与包体大小都不变。
   目录顺序与旧语义对齐（intern→grad、dev→cap、pm→beret、ops→helmet、boss→top），
   旧档的字节值会落到语义相近的帽子上。
2. **一处几何真相**：把 `quadruped.ts` 里 `drawSide / drawFacing` 的姿态计算抽成
   `sideOptions / facingOptions`，并导出 `landmarksOf(species, direction, column)`，
   返回头心、头顶、眼线、吻心、颈点、躯干心。绘制与锚点生成共用这一份，
   改美术不会再让锚点漂移。
3. **manifest 升 v3**：`cosmeticAnchors[species][direction][column][kind]`
   为 `[x, y]` 或 `null`（2×4×16×4 = 512 组，约 41KB JSON）。按帧列而不是按姿态，
   是因为呼吸、走路起伏、蹦跳与坐躺过渡帧都会让头/躯干移动 1–3px；
   按列只多 4 倍数据，客户端逻辑反而更简单（`frameIndex % columns`，O(1) 查表）。
   图标按朝向分文件（`cosmeticFiles[kind][id][direction]`），朝左由生成器镜像朝右。
4. **叠层顺序**：`back` → body → pattern → bodyLight → **headwear** → hoof → extra →
   eyes → eyeLight → **eyewear** → snout → **neckwear**。帽子排在 `extra` 之前，
   牛角与马鬃从帽子上方穿出，戴帽不会丢掉物种剪影。
5. **背面规则**：眼镜在朝上时锚点为 `null`，整层隐藏；头饰、颈饰、背包正常显示
   （颈饰在背面正好是后颈的打结处）。

## 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 保留三类配件，只重画 + 重定位 | 否 | 胸口 16×5 的预算摆不下「工牌 + 领带」两件胸饰；把叼着缩小到 3–4px 也只是从「悬空」变成「看不清」。 |
| B. 新增三个槽位、保留旧槽位 | 否 | 20 字节里只剩 `[19]` 一个保留位；扩包长会牵动所有编解码、同步包与前后端同时上线。 |
| C. 把配件烘进图集逐帧绘制 | 否 | 每个配件 × 每个组合都要出一套 64 帧图集，面积与显存是现在的两个数量级，ADR-0006 已经因为 16MiB 显存写过一次警。 |
| **D. 部位迁移 + 锚点按帧列推导（采纳）** | 是 | 大头比例下头顶、眼线、颈线是三块最稳的承载面；锚点由美术推导后，姿势与物种差异自然消失。 |

## 后果

- 正面：配件在站立、走动、坐下、躺平、叫唤与四个朝向下都贴住头/颈，不再悬空或跑到后脑勺；
  帽檐、镜片、围脖三处都有明确的读图语义。
- 负面：配件图标从 14 张涨到 43 张（合计约 4.8KB，仍可忽略）；manifest 从个位数 KB 涨到 41KB
  （gzip 后约 6KB）；`sessionStorage` 里的旧字段（`badge/tie/mouthItem`）在改名后
  会回落到默认外观，等于免费迁移而不是保留旧搭配；戴帽会遮住部分头顶/牛角根部。
- 协议兼容：字节长度不变，但**同一串字节在旧客户端里会被解成旧配件**。
  这是开发期项目，客户端与服务端同仓部署；若将来需要灰度，必须按 manifest 版本走双读。
- 回滚成本：低。把 `catalog.ts` 的三个目录与 `cosmetics.ts` 换回旧版、manifest 降回 v2 并重跑
  `pnpm assets` 即可；协议长度没变，服务端不需要回滚。

## 复核信号

- 新增配件时，先确认 `landmarksOf` 里有对应的挂点，不要在 `generate.ts` 里手写坐标。
- 如果某一类配件在四个朝向下仍然读不出来，优先怀疑「图标没有分朝向」，而不是继续调锚点。
- 如果 manifest 体积成为首屏瓶颈（> 100KB 未压缩），再考虑把锚点改成按姿态压缩或二进制定长表。
