# ADR-0028：内容审核沉到共享契约，政治类拒绝、脏话打码

- 状态：已采纳
- 日期：2026-11-11
- 关联：ADR-0004（零持久化）、ADR-0009（准入与排队，同样选择「服务端权威 + 客户端可解释」）

## 背景

园区里只有两处自由文本：

- **工牌名**：`JoinGate` 入场、`SaveBar` 捏人页、深链 `?name=`、`sessionStorage` 恢复，四条路径最后都进
  `truncateName` → `C2S_HELLO`；
- **园区频道**：`C2S_CHAT` → `handleChat`，截断到 160 码点、5s/3 条限速，广播给视野内所有人。

产品约束是**零持久化**（ADR-0004）：没有数据库、没有内容存储，词库只能来自代码或部署时挂载的文件。
合规要求这两处都不能出现政治敏感内容与污言秽语。

## 问题

1. **词库不能写死在代码里**。政治类词条必须来自合规清单，由运营/法务维护；仓库内置真实条目既不可审计，
   也会让「词库是什么版本」变成一次发版问题。
2. **同一份规则不能两端各写一遍**。项目已有硬约束：客户端与服务端共用 `packages/shared-types`。
   过滤规则一旦分叉，就会出现「本地放行、服务端拒绝」的静默吞消息。
3. **审核必须能扛住常见绕过**：夹空格/标点/零宽字符、全角半角混写、大小写混写、叠字（「敏敏感感」）、
   数字替字（`sh1t`）。
4. **打码要精确**。规范化会丢字符，不能拿规范化串的长度去截原文，否则打码位置会错、emoji 会被切半。
5. **服务端不可信任客户端**：伪造的 `HELLO` / `CHAT` 必须被权威拦下；但正常用户需要即时反馈，
   不能每次都等一个往返才知道被吞。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 只在服务端内置词库，命中静默丢弃 | 改动最小，词库不进前端 | 用户不知道为什么没发出去；改词必须发版；违背「词库由合规方维护」 | 低 |
| B. 客户端与服务端各实现一份匹配 | 各自演进互不影响 | 两份实现必然漂移；违反仓库既有契约；绕过手法要修两次 | 中 |
| C. 共享引擎 + 内置词库 + 服务端外置覆盖 + 拦截回执（采纳） | 规则单源；客户端即时提示；服务端权威；改词不必发版 | 词库进前端 bundle；需要一条新协议；两份词库可能不同步 | 低 |
| D. 接第三方内容安全 API | 变体、图片、语音能力更强 | 引入外网依赖与按次成本；单机 2C2G 的延迟预算；用户文本外传 | 中 |

选 C。A 把成本转嫁给用户，B 把成本转嫁给维护者，D 在一次协议层改动里引入了新的故障域与合规问题。

## 决策

1. **引擎落在 `packages/shared-types/src/moderation/`**，对外只有两个入口：
   - `inspectText(text)`：内置词库，客户端预校验用；
   - `createModerationFilter(lexicon)`：显式词表，服务端启动时建自己的实例。
   规范化、trie、区间合并、打码全部藏在接口后面。
2. **两趟规范化 + 原文码点映射**：第一趟 NFKC（全角→半角）+ 小写 + 去噪（`\p{P}\p{S}\p{Z}\p{C}`）+
   数字替字；第二趟按 run 折叠重复——中日韩从第 2 个起折，拉丁从第 3 个起折（`ass` 不会被折成 `as`）。
   折叠后的区间覆盖整段 run，避免「话话」只打码第一个字。
3. **分类裁决**：政治类命中立即 `reject`（整条不发），脏话命中 `mask`（合并区间后逐码点覆盖为 `*`）。
   同时命中两类按政治类处理。
4. **词库两层**：`BUILTIN_LEXICON` 随包发布（政治类只有中性占位条目），服务端用
   `GAME_MODERATION_LEXICON` 指向 JSON 文件：数组=整类替换，`{ mode: "append" | "replace", words }`=追加/替换。
   逐条校验（类型、空串、32 码点上限、控制字符），单类上限 20000；文件缺失或格式错误**降级到内置表并告警，
   不阻断启动**。
5. **协议只增不改**：`S2C_CHAT_REJECTED = 0x1a`，载荷 `[op][reason]` 共 2 字节，与 `S2C_QUEUE_REJECTED` 同构。
   旧客户端落到 `switch` 默认分支忽略。未知 reason 原样返回，由客户端给通用文案。
6. **拦截点位**：
   - 聊天：截断 → 非空 → 限速窗口计数 → 审核 → 广播。政治类回执且不广播；脏话广播打码后的文本；
     **被拦下的消息也计入限速窗口**，否则可以拿被拒请求刷回执。
   - 昵称：`JoinGate` / `SaveBar` 渲染期预检，政治类禁用「上岗」并就地提示，脏话打码后允许提交；
     服务端 `handleHello` 再判一次，政治类改写为「无名牛马」，脏话改写为打码文本。
7. **零持久化不变**：不落盘、不写库；日志只打类别与命中数，不打原文与词条。

## 后果

- 正面：规则单源，客户端与服务端行为一致；改词库不必重新构建前端；被拦下时有解释；
  伪造包也送不出违规内容；聊天广播的文本永远是打码后的版本。
- 负面：内置词库随客户端 bundle 下发，可被提取（词表本身不是秘密，代价可接受）；
  外置词库只在服务端生效，与客户端内置表可能不同步——这正是回执通道存在的理由；
  多一条 opcode 与一份 trie 常驻内存（启动期构建，词条上限 20000）。
- 回滚成本：低。不配 `GAME_MODERATION_LEXICON` 且把内置表清空即回到「无审核」；
  回执是新增包，旧客户端本就会忽略；无数据结构迁移。

## 已知限制

- `S2C_WELCOME` 不含昵称，服务端改写昵称后**本人**角色卡仍显示原名。正常路径被客户端预检挡在门外，
  只有伪造包会触发，作为可接受降级记录。
- 形近汉字（日/曰）、拼音与谐音替换不在 v1 覆盖范围；`CONFUSABLE` 留了扩展点。
- 缺字省略（`f*ck`）无法命中：去噪后变成 `fck`，与 `fuck` 不等。
- 打码统一用半角 `*`，中日韩字符打码后视觉变窄，是有意取舍（不改字符数，排版不跳）。
- **内置政治表只有占位条目**：不配置外部词库时，真实政治内容不会被拦截。上线前必须由合规方提供词表。

## 复核信号

- 误报集中在某一类正常词（如「去死」「废物」出现在自嘲语境）→ 调整内置表或把该词条降级为外置可选项；
- 出现稳定的绕过形态（形近字、拼音首字母）→ 在 `normalize.ts` 增加一层映射，接口不变；
- 需要图片/语音/昵称头像审核 → 在 `createModerationFilter` 的调用点换成外部服务，协议与 UI 不动；
- 词库条数接近 20000 或启动耗时可见 → 改为按类别懒建 trie，或把词库下沉到数据库（需先推翻 ADR-0004）。
