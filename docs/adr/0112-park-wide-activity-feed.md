# ADR-0112：全园区交互播报与远处事件定位

- 状态：已采纳
- 日期：2026-11-16
- 关联：动作反馈可见性 ADR-0105；NPC 救护链 ADR-0106；护士值班与交接 ADR-0109；
  押送与小黑屋 ADR-0072；系统公告 `S2C_SYSTEM_NOTICE`；协议追加规则见 `README.md`「线协议」

## 背景

园区里所有交互演出都只发给 AOI 内的接收者：救护车出车、保安押送、被人创飞、上香续杯，
摄像机之外的人完全不知道发生过什么。玩家只能看到自己眼前的一千像素，园区的「有人在动」
感在远处是断的。

直接复用 `S2C_SYSTEM_NOTICE` 不够：它没有坐标，做不了小地图定位；它的口径是「进园 / 离园 /
公告」这类系统消息，把「谁坐下了」混进去会让频道列表失去公告语义。

约束：

- 200 人同屏时，坐下 / 挥手 / 跳跃每秒可达数十次，逐条全服广播会直接刷爆下行；
- 近处已有完整动画与音效，通报条不能变成同一件事的第二份演出；
- 不新增落盘状态、不做镜头跳转、不做远程实体渲染；
- 旧客户端必须不受影响：新 opcode 由 `default` 分支静默忽略。

非目标：

- 不做观战镜头或远程实体渲染（成本是渲染与坐标同步，收益只是「看见」）；
- 不做历史动态列表与回放（那是聊天与日志的职责）；
- 不把播报条做成可交互面板（动画与语音已经在现场，文字只补「远处也没错过」）。

反向成本（不做或推迟的代价）：

- 远处发生的救护、押送、老板被踢完全看不见，玩家会以为园区是静止的；
- 想补这块信息只能靠聊天手打，信息密度与可信度都不可控；
- 若拖到实体数量再涨一轮再做，届时要么改 AOI 半径（拉高同步成本），
  要么加全服广播（下行先超预算），两个口子都比现在贵。

## 决策

### 1. 新开一条独立广播通道，不复用系统公告

`S2C_ACTIVITY = 0x5e`：`[op][kind u8][actorId u16][x u16][y u16][len u8][utf8]`，
头部 9 字节 + 最多 120 字节文案。坐标沿用实体同步的 1/8 像素量化，小地图直接可用。

`C2S_ACTIVITY = 0x5f`：`[op][kind u8][sub u8]`，3 字节定长，分支入口先校验字节数再解码，
解码器自身也拒绝非 3 字节——多一个字节就判伪造，不进入业务逻辑。

编号只追加不复用（`ACTIVITY_KIND`）：旧客户端收到不认识的 kind 直接跳过，新服务端不会
因为旧客户端而少发。

### 2. 分级决定去重、限流与可见性

| 分级 | 事件 | 去重窗口 | 桶空时 | 接收者 |
|---|---|---|---|---|
| dramatic | 救护车出车 / 装车 / 上病床 / 治愈、保安派单 / 押送 / 入屋、被创飞、老板倒下 | 500ms | 照发 | 看不见主角的人 |
| life | 老板受击、工牌被赞、上香、续杯、售货机 / 饮水机 / 咖啡机、场所台词 | 2s | 丢弃 | 全体在线者 |
| routine | 坐下 / 躺下 / 起身 / 跳跃 / 入座赌桌与擂台 / 挥手 | 4s | 丢弃 | 看不见主角的人 |

`life` 是纯本机演出（气泡、光晕、台词），身边人也看不到，因此不排除 AOI；
`dramatic` 与 `routine` 用 `viewer.known.has(actorId)` 做差集：眼前就是完整动画，
再刷一条文字等于同一件事说两遍。

全局令牌桶 40 条/秒，桶空时只保强演出。最坏情况下每客户端约 1KB/s，与现有实体同步同量级。

### 3. 生活类反馈需要一个受限上行口

上香、设施气泡、场所台词、拍照全靠客户端本地随机，服务端无从派生，因此开放
`C2S_ACTIVITY`：

- 只接受 `ACTIVITY_REPORTABLE` 白名单里的纯观感编号，权威事件（救护、押送、老板）一律拒绝；
- 每玩家 1 条/秒限流，连按交互键也只留第一条；
- 坐标一律取服务端权威位置，**不接受客户端坐标**；`sub` 只作展示细分；
- 入站闸门表上限同步从 `0x58` 扩到 `0x60`，否则 `0x5f` 会在业务分支之前被当成未知包丢掉；
  闸门按 3 字节定长校验，多一字节直接判伪造。

伪造风险：即使被改包，最坏结果也只是多一句文案，不影响任何判定。为此不引入
领地校验表——为纯观感文案维护一张坐标白名单，成本远高于收益。

### 4. 文案在服务端收口

`formatActivity(kind, { name, region })` 是唯一模板表，未知 kind 返回 `null`，调用方跳过，
绝不显示半句话。文案按 UTF-8 字节预算截断到 120 字节，保证 `len u8` 与实际负载一致。

服务端不复用客户端文案：昵称与区域名必须取权威值，否则伪造昵称可以直接进播报条。

### 5. 客户端两条呈现，共用一个带过期时间的缓冲

```
S2C_ACTIVITY → session 环形缓冲（最多 8 条，6 秒过期）
              ├→ 顶部播报条：同屏 3 条、停留 5 秒、1.2 秒放行一条、强演出插队
              └→ 小地图事件层：视野内菱形 + 脉冲环，视野外贴边楔形箭头
```

- 播报条开关存 `localStorage`，关掉后小地图标记照旧，两者互不牵连；
- 小地图仍是 168px 映射本人 1000px 视野，不改成全图：视野外事件钳到边缘内缩 6px
  并按真实方位旋转箭头，既保住现有可读性，又满足「远处也知道大概在哪」；
- 小地图 4Hz 重绘把事件与地形一起画，不额外起定时器；脉冲相位由 `age` 直接算；
- 强演出事件走 `aria-live="polite"`，生活类与常规类不进读屏，避免刷屏；
  `prefers-reduced-motion` 下位移动效退化为淡入淡出。

## 对抗审查（反例与失效场景）

| 反例 | 后果 | 处理 |
|---|---|---|
| 改包伪造 `C2S_ACTIVITY`，自称老板倒下或押送 | 播报条出现假消息 | 白名单只收纯观感事件，权威事件不走上行口；坐标与昵称只取服务端值 |
| 200 人同时挥手，令牌桶被打空 | 常规与生活类被丢弃 | 同类 4 秒合并 + 只发看不见主角的人；丢的只是文字，本地动画照常 |
| 救护车两个触发点先后命中同一伤员 | 同一条急救助手播两遍 | dramatic 也有 500ms 去重窗口 |
| 旧客户端收到 `0x5e` | 解码表没有该字节 | `default` 分支静默忽略，不影响后续同步 |
| 玩家关掉播报条却仍想定位 | 远处事件完全不可见 | 小地图标记与开关解耦，关播报只收起文字 |
| 视野外事件贴边后箭头方向反了 | 玩家往反方向找 | 投影只做等比缩放 + `atan2`，不翻转坐标；单测覆盖四向与斜向 |

## 备选方案

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 复用 `S2C_SYSTEM_NOTICE` | 零协议改动 | 无坐标，做不了小地图定位；公告语义被玩法动态稀释 | 否决 |
| B. 全服广播所有交互 | 实现最简单 | 200 人时坐下 / 挥手每秒数十条，下行与读屏都被刷爆 | 否决 |
| C. 观战镜头 / 远程实体渲染 | 最直观 | 渲染与坐标同步成本高，且会把玩家从自己的角色上拽走 | 否决 |
| D. 新通道 + 分级 + 按可见性过滤 + 受限上行口 | 远处可读、近处不重复、下行有上限 | 新增两个 opcode 与一张分级表 | 采纳 |
| E. 只做小地图标记、不做文字 | 不占屏幕 | 没有名字与动词，无法回答「谁做了什么」 | 否决 |

## 后果

- 看不见主角的玩家能读到「谁、在哪、做了什么」，近处玩家看到的仍是原来的完整演出；
- dramatic / life / routine 的分级表成为新增事件的唯一入口：新交互忘了分级会落到
  `routine`（只上小地图、不占播报条），不会意外刷屏；
- `C2S_ACTIVITY` 是一个新的上行面，但只有 1 秒 1 条、只影响文案，攻击面可控；
- 断线重连时播报条与事件缓冲随会话重建，不落盘；旧客户端静默忽略两个新 opcode；
- 移动端没有小地图，播报条文案自带区域名，信息不丢失；
- 单测：`shared-types` 模板全覆盖与编解码往返、`game-server` 去重 / 令牌桶 /
  AOI 过滤 / 离线跳过、`web` 队列节流与插队。

## 回滚

30 天内回滚只需三步，且不动既有演出与存档：

1. 删掉 `server.ts` 里 `ActivityHub` 的实例化、注入与 `C2S_ACTIVITY` 分支；
2. 删掉 `client.ts` 的 `S2C_ACTIVITY` 分发与 `sendActivity`，以及 `session` 的上报调用；
3. 下掉 `ActivityFeed` 挂载、小地图事件层与页脚开关。

播报条与小地图标记自动退化为「无事件」，救护车、押送、点赞等既有广播包保持不变。
