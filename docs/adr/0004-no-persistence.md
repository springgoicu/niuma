# ADR-0004：零持久化，世界只在内存，身份只在会话

- 状态：已采纳
- 日期：2026-10-28

## 背景

最初方案是 PostgreSQL + Drizzle 存玩家与令牌。产品目标改为「临时缓存、关掉网页即消失」，
数据库从必需品变成了纯粹的负担：连接池、迁移、部署、数据合规全都要为它让路。

## 决策

- 服务端不接数据库、不写磁盘；`World` 是唯一真相，进程重启即清空。
- 身份不是账号：客户端在 `C2S_HELLO` 中自报昵称与 20 字节外观，服务端做过长度与取值钳制后即可入世界。
- 浏览器只用 `sessionStorage` 存昵称与外观草稿；关闭标签页自动销毁，刷新可恢复。
- 断开连接立即：向所有 `known` 玩家广播 despawn → 移出网格 → 实体归还对象池。

## 后果

- 正面：一条命令可跑，零配置、零迁移；没有 PII 落库；没有连接池抖动。
- 负面：换浏览器或关标签页就无法恢复外观；无法做跨会话排行、好友、举报留证。
- 回滚成本：低。若将来要加持久化，只需在 `PlayerRepository` 端口后接一个实现，
  协议层不需要改动（外观已经是定长二进制，可直接入库）。

## 复核信号

出现「需要跨会话保留角色」「需要审核聊天记录」「需要账号体系」中任意一条时，重新引入持久化。
