# ADR-0018：叫唤与跳——姿态之外的一次性叠加动作

- 状态：已采纳
- 日期：2026-11-03
- 取代：`POSE.Emote` 作为姿态值的用法（`packages/shared-types` 与客户端 `resolvePose` 的旧回落逻辑）

## 背景

叫唤原本被建模成一种**姿态**：按下 C 后客户端把 `Motion.pose` 写成 `POSE.Emote`，服务端把 `state` 里的 pose 置成 4，
440ms 后客户端再把它改写成 `POSE.Idle`。上线后暴露出两个问题：

1. **坐着叫唤会站起来**：叫唤结束回落到 `Idle` 而不是原来的 `Sit`/`Lie`，坐姿丢失；
2. **叫唤本身是蹲跳**：现有 3 帧（13-15）是「蹲下 → 蹦起 → 落地」，用户要的是**只动嘴**，
   并且希望「跳」是一个独立的动作，而不是叫唤自带的位移。

根因不在动画，而在**状态模型**：把一次性动作塞进姿态枚举，姿态就同时承担了「当前身体形态」和「正在播什么」两件事。
只要两者共用一个字段，任何一次性动作都必须记住「播之前是什么」，并负责回滚——这正是 bug 的来源。

## 问题

- wire 上的 `pose` 字段是 3 bit（0-7），看似还能塞 3 个姿态值；
- 服务端当前只在 `C2S_ACTION` 时改姿态，没有「动作到期」的概念；
- 图集只有站姿叫唤帧，坐/躺没有对应画面；
- 远端只能通过 `state.pose` 观察别人，没有独立的表现通道。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 新增 `POSE.SitEmote / LieEmote / Jump` 姿态值 | 不改 bit 布局，packState 签名不变 | 服务端必须替玩家记住「动作前的姿态」并在播完后回滚，多一份状态、多一条时序分支；越权/掉包时会卡在错误姿态；图集照样要加列 | 中 |
| B. 姿态收敛为四态 + state 字节 bit6/bit7 承载叠加动作（采纳） | 姿态与表现彻底解耦，叫唤播完天然回到原姿势，无需回滚；包长、opcode 都不变 | 渲染层多一层选帧优先级；图集扩列 | 低 |
| C. 只改客户端，不动协议 | 改动最小 | 别人看不到你的叫唤与跳，多人场景直接失真 | 低（但功能残缺） |
| D. 把嘴拆成独立图层，叠加张嘴 | 不扩列 | 头部像素会被拆成两层，破坏 `palette.ts` 的 slot 体系与锚点推导，且描边要重算 | 高 |

选 B。A 把「记住上一姿态」的责任推给服务端，等于把当前 bug 换个地方实现；
D 为了省 9 列像素把整套分层染色体系拆开，代价与收益完全不成比例。

## 决策

### 1. 姿态只剩四态

`POSE = { Idle: 0, Walk: 1, Sit: 2, Lie: 3 }`；`ACTION = { Sit: 0, Lie: 1 }`。
叫唤与跳不再走 `C2S_ACTION`，它们随 20Hz 的 `C2S_MOVE` 上行，和朝向、移动标志一起打包。

### 2. state 字节：bit6 = 叫唤，bit7 = 跳

```
bit0-1  direction
bit2-4  pose（Idle/Walk/Sit/Lie）
bit5    moving
bit6    emote   一次性叫唤
bit7    jump    一次性跳跃
```

- `packState(direction, pose, moving, emote = false, jump = false)`；`unpackState` 同步返回两个布尔位。
- 包长仍是 1 字节状态位，无新增 opcode、无额外带宽。
- 旧客户端解析时会忽略这两个高位：最多看不到叫唤与跳，不会错位。

### 3. 服务端只保存与回传，不做到期计时

起止以客户端 20Hz 包里的位为准，服务端在 `Player.applyState` 里重新 `packState`（不原样透传）。
理由：本地计时器与服务端计时器同时存在时，必然出现「本地已结束、服务端还在重发」的打架，
旧实现已经被这个问题咬过一次（`session.ts` 里那段注释就是现场记录）。

服务端只做一条防御：**行走中（pose=Walk 或 moving=true）丢弃叫唤位**，避免滑步时张嘴；
**跳跃位放行**——跳跃是位移动作，「必须停下来才能跳」是把动作模型误当成姿态模型的残留
（2026-11-03 修订，见下方 §5、§6）。

### 4. 图集列预算 16 → 25（version v5 → v6）

```
idle       0-2    不变
walk       3-8    不变
sit        9-10   不变
lie       11-12   不变
jump      13-15   原 emote 的蹲跳几何，闭嘴 —— 拆出来的独立跳跃
emote     16-18   站姿叫唤：只动嘴
sitEmote  19-21   坐姿叫唤：坐姿几何，只动嘴
lieEmote  22-24   躺姿叫唤：躺姿几何，只动嘴
```

- 每段 `frameMs` 合计 440ms，`loop: false`；客户端的播放窗口按 `max(440ms, 图集实际长度)` 计算，
  动画与窗口对齐，不会在末帧停顿或被硬切。
- 叫唤帧**不参与呼吸**：坐/躺的基座本来每两帧抬 1px，叫唤必须去掉，否则「只动嘴」的回归测试立刻失败，
  观感上也会读成「坐着弹了一下」。
- 背面朝向看不见嘴：张嘴那一拍把头（连同耳朵、角）抬 1px，作为朝上叫唤的最低限度反馈，身体不动。

### 5. 渲染优先级：跳 > 叫唤 > 姿态；Walk 只挡叫唤

`overlayTrackFor(overlays, pose, emoting, jumping)` 是唯一选帧入口：
`Jump` 优先，且**不区分姿态**——行走中起跳也走同一条轨，位移继续、腿部在跳跃帧里收起；
叫唤按姿态映射到 `emote / sitEmote / lieEmote`，`Walk` 返回 null（回落到行走帧，避免滑步张嘴）。

已知取舍：跳跃窗口（440ms）内腿部姿势是定格的，横向位移仍在推进，观感是「边跑边蹦」而不是
「跑动中蹬地起跳」。要消掉这一定格，需要把腿拆成独立图层单独选帧，代价与收益不成比例。

### 6. 交互规则

| 输入 | 行为 |
|---|---|
| 站/坐/躺时按 C | 播对应叫唤，姿态不变，播完仍保持原姿势 |
| 站/坐/躺时按空格 | 播跳跃；坐/躺**先起身**（pose→Idle）再跳，结束后保持站立 |
| 行走中按 C | 忽略，不置位，不打断行走 |
| 行走中按空格 | 立即起跳；`pose=Walk`、`moving=1` 都不改，水平位移继续，跳跃帧播完接回走路循环 |
| 开始移动 | 立即清掉叫唤位；**跳跃位保留**，否则边走边跳会被自己的脚步掐掉 |
| 切坐躺 | 立即清掉叠加位 |
| 连按同一个键 | 从第 0 帧重播 |
| 叫唤与跳互斥 | 后按的打断先按的 |

### 7. 跳跃观感：图集腾空 + 客户端弧线（2026-11-03 补充）

- 图集腾空帧从 -3 抬到 **-5**（帧顶安全上限：再高牛角与描边会被 64 帧裁掉），收腿 `lift` 3 → 5，
  腾空帧停留 170ms → 220ms；三帧合计仍是 440ms，列预算不变、图集版本无需升级。
- 客户端在 440ms 窗口内叠一条整数纹素抛物线（峰值 **-7**）：只抬本体与昵称，阴影留在地面，
  腾空时切到宽扁档。蹲伏到顶点总落差约 12 纹素 ≈ 角色身高 1/4，与旧版 3 纹素拉开量级。
- 落地帧同时是扬尘接触帧，复用步行的尘土池，不新增粒子系统。

## 后果

**收益**

- 「叫唤不改动作」由结构保证，不需要记忆与回滚；
- 叫唤与跳各自独立，后续再加表情（挥手、鼓掌）只需加列 + 复用同一对标志位的模式；
- 远端只需看一个布尔位，丢包最多漏一次表现，不会永久张嘴。

**代价**

- 图集从 1024×256 扩到 1600×256，每层切片数 64 → 100（约 13 层，共享同一批 TextureSource，显存不变）；
- manifest 升到 v6，`public/sprites` 必须与 web 包同批发布，否则 `atlas.ts` 的版本校验会直接报错；
- 新增两条回归线：`packages/pixel-assets/src/__tests__/overlay-frames.test.ts`（叫唤只动嘴、跳是整体位移）、
  `apps/web/lib/game/__tests__/clip.test.ts`（选帧矩阵）。

## 回滚（30 天内）

单个提交同时包含资源与代码，`git revert` 即回到 v5。若只想关掉表现而不动协议：
让 `overlayTrackFor` 恒返回 null —— 姿态、协议位、图集都还在，只是不播，属可逆降级。
反向操作（恢复旧的 `POSE.Emote`）需要重跑 `pnpm assets` 并同步服务端姿态上限，属于不推荐路径。
