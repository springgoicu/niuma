# ADR-0027：座位朝向即家具朝向，工位桌按朝向四向贴图

- 状态：已采纳
- 日期：2026-11-11
- 关联：细化 ADR-0020（工位、座位与园区设施）；沿用 ADR-0005（禁负缩放）、ADR-0026（工作区工位）

## 背景

线上观感反馈：**坐到工位上时，角色不是正对电脑**。南排工位的椅子在桌子北侧，人朝南，
镜头看到的是角色的正面、显示器在他背后；东西两列工位的椅子在桌子侧边，人朝西 / 朝东，
镜头看到的是侧坐。床位与凳子被一并点名，希望「人坐哪儿就正对哪儿」。

## 问题

朝向链路本身没有 bug：

- 客户端 `session.sitAt()` 入座即写 `Motion.direction = seat.facing`；
- 服务端 `SeatRegistry.occupy()` 写 `player.applyState(seat.facing, ...)`；
- `applyMove()` 在座位上忽略移动包上报的 direction，朝向不可被改写。

真正对不上的是**布局数据与桌子贴图**：

1. `drawDesk()` 只有一种画法：显示器在贴图北边、屏幕朝南（朝镜头），桌面本体与抽屉前挡板同理；
2. `officeWorkstations()` 却把椅子摆在桌子四周（北排在南、南排在北、西列在东、东列在西），
   于是只有北排（人坐桌南、面朝北）读作「正对显示器」，其余三面分别是背对与侧坐；
3. 改布局把四面统一成朝北会丢掉广场四面环绕的构图；给贴图做镜像 / 旋转又违反 ADR-0005
   （`sprite.scale = -1` 会把 1px 描边拉成半像素），且显示器转 180° 会变成抽屉朝上。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 统一布局：椅子一律在桌南、人朝北 | 贴图一行不改 | 广场四面环绕的构图没了，东西两列工位要重排，走道与门洞留白重新验算 | 低 |
| B. 桌子贴图四向化，保留环绕布局（采纳） | 布局、碰撞、入座规则全不动；四处观感一致 | 多画三套显示器，初始化多烘焙 6 张 96×66 | 低 |
| C. 只锁朝向、不修观感 | 零成本 | 「侧坐 / 背对电脑」依旧存在 | 低 |

选 B。A 为了一个 2D 投影问题改整张地图，代价与收益不成比例；C 没有解决问题。

## 决策

1. **朝向成为工位桌的一等数据**：`DeskInstance` 增加 `facing`，语义是「屏幕朝向 = 入座者面朝方向」；
   新增 `workstation(x, y, facing)` 工厂，椅子锚点由「桌心 − 朝向单位向量 × `chairOffset(facing)`」反推。
   `chairOffset` = 桌半高 + `CHAIR_GAP`（南北）或 桌半宽 + `CHAIR_GAP`（东西）。
   「椅子永远在屏幕背面一侧」由此成为构造性质，布局里不再手写 40 / 64 两个字面量。
2. **广场四面各走一次工厂**：`officeWorkstations()` 用 `Up / Down / Left / Right` 四次调用覆盖四排；
   工作区六工位统一 `Up`。
3. **几何与绘制分离**：新增 `apps/web/lib/game/desk-art.ts`，只回答「显示器在哪条边、观察角度是什么、
   桌面陈设让到哪里」，不 import pixi，可直接单测；绘制留在 `props.ts` 的 `drawDesk(g, lit, art)`。
4. **三种观察角度**：人朝北 → 正面（亮屏 + 代码行，现状）；人朝南 → 背面（素色背壳 + 外框漏光）；
   人朝东 / 朝西 → 侧视（竖窄机身 + 屏幕一侧的亮边与桌面反光）。镜像一律在绘制期按坐标实现，
   不使用负缩放。绘制顺序为「桌面 → 显示器 → 陈设」，显示器才站得住桌面。
5. **贴图按朝向缓存**：`PropsView.build()` 对四个朝向各烘焙 idle / lit（共 8 张），
   每张桌子按 `desk.facing` 取自己那一对；`setSeatOccupied()` 仍只切 idle / lit，占座逻辑不变。
6. **床位与凳子**：三张床统一朝右（`drawBed` 的枕头在右端，头始终落在枕头上）；
   休息室两张凳子由「朝向随机」改为朝南、正对 `sideTable` 茶几；沙发朝南、马桶朝北不变。
7. **朝向权威不改**：客户端预测与服务端占座仍只读 `seat.facing`，座位上的移动包不会改写朝向；
   本次只补回归测试，不动这条链路。

## 后果

- 正面：
  - 四面工位都读作「人正对显示器」，床位头在枕头一侧，凳子面朝茶几；
  - 椅位由朝向推导，改桌子尺寸只需改 `DESK_W` / `DESK_H`，不会再出现「朝向改了椅子没跟上」；
  - 四向几何有单测（显示器贴哪条边、陈设是否被压、是否越出画布），
    「贴错边」这类位图里看不出、又能被肉眼一眼发现的回归，CI 能挡住。
- 负面：
  - 初始化多烘焙 6 张 96×66（约 37k 像素），一次性成本可忽略，但新增朝向必须同时补 art 与测试；
  - 侧视显示器只有 12px 宽，屏幕内容不可见，只能靠亮边与桌面反光读出「亮着」；
  - `DeskInstance.facing` 是必填字段，任何新增工位都必须回答朝向，否则编译失败。
- 回滚：低。删掉 `desk-art.ts` 与 `build()` 里的四向烘焙、回到单张贴图即可；
  `facing` 字段可保留（渲染层不再读取），布局与碰撞数据不受影响。

## 复核信号

- 出现「人坐在桌侧、屏幕却朝镜头」：查 `deskArtFor(facing).screen` 是否仍等于入座朝向的相反一侧
  （`Left → east`、`Right → west`、`Up → front`、`Down → back`）；
- 出现「角色被桌子挡住」：查 y 排序（桌子底边 `desk.y + DESK_H / 2`）与椅子偏移，
  不要靠改贴图高度解决；
- 出现「显示器压住马克杯 / 绿植」：调 `desk-art.ts` 的 `details` 落点，不要挪桌面本体；
- 出现「坐上去屏幕不亮」：查 `setSeatOccupied()` 是否仍按 `seat.desk` 索引到对应的 `DeskSprite`；
- 出现「床上的头没落在枕头上」：先查 `LOUNGE_SEATS` 的床位朝向是否统一为水平朝向，再查 `drawBed`。
