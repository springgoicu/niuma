# ADR-0102：协议解析失败只丢这一条，不得升级为渲染线程致命错误

- 状态：已采纳
- 日期：2026-11-16
- 关联：ADR-0071（渲染后端回退与主线程降级）、ADR-0088（世界事件与画饼冲击波协议）

## 背景

线上红条「ERROR: WORLD EVENT MUST BE 8 BYTES, GOT 9（刷新后自动改用主线程）」在世界事件
每 10 分钟一轮的节奏下必然复现。排查结果是两处定长包的长度漂移：

- `S2C_WORLD_EVENT` 追加 `seed` 字段后实际 9 字节，`decodeWorldEvent` 仍按 8 字节整包校验；
- `S2C_BOSS_SHOCK` 的 `hits` 从一开始就是第 11 字节，解码端只认 10 字节。

README 的协议表与服务端广播一直是 9 / 11 字节，错的只有读端。

真正把「一条包读不懂」放大成玩家可感知故障的是异常路径：`NetClient` 跑在渲染 Worker 里，
`handle()` 没有任何异常边界，抛错冒到 `workers/game.worker.ts` 的全局 `error` 监听，
被包成 `{ t: 'fatal' }`；主线程 `onWorkerFatal()` 把它当成渲染崩溃，先受控重载，
被守卫拦下后 `markRenderFallback()`，本次标签页永久降级主线程渲染。
一次协议字段漂移，代价是整个会话的渲染后端。

## 决策

### 1. 定长包的字节数只有一份事实源

`packages/shared-types/src/constants.ts` 新增 `WORLD_EVENT_PACKET_BYTES = 9` 与
`BOSS_SHOCK_PACKET_BYTES = 11`，编码缓冲与解码校验引用同一常量，注释同步写真实字节数。
回归测试锁死三条线：往返一致、尾部扩展、截断报错。

### 2. 读端只保证「够读固定字段」

定长包解码改为「至少 N 字节」：固定字段读完即返回，尾部多出来的字节忽略。
新字段只能追加在尾部，旧读端读旧字段——与 HELLO / WELCOME 的尾段约定、`decodeVent`
允许 9 或 10 字节是同一条口径。截断仍然立即抛错，保留「包不自洽」的守卫价值。

### 3. NetClient 是解析异常的边界

`handle()` 只加一层 try/catch，原 `switch` 原样搬进 `dispatch()`。异常时按 opcode 记一条
`console.error` 并丢弃该包；同一 opcode 只在首包打完整堆栈，后续静默计数，避免坏包按
tick 刷屏。不调用 `onStatus('error')`：单包坏掉不该铺成玩家可见红条，更不能进入
`worker-client.ts` 的致命判定。

## 备选方案

- **只改两个长度数字**：能止血，但下一次加字段仍会重演，且一条坏包仍可能顶掉渲染线程。
- **读端严格校验整包长度**：等于要求双端永远同时发版；缓存页面 / 灰度窗口必然撞上，
  与既有尾段「读到不认识就停」的兼容做法相反。
- **在 Worker 全局 `error` 里区分协议错误**：需要从错误消息反推来源，既脆又漏；
  异常应该在离发生点最近的边界处理。
- **放宽渲染致命判定**：会把真正的渲染崩溃一起吞掉，与 ADR-0071 的降级链冲突。

## 后果

- 世界事件横幅、红包撒点与冲击波预警 / 结算恢复正常，不再触发重载与主线程降级；
- 缓存旧页面遇到新服务端时，尾部新增字段被忽略而不是整包拒收；
- 坏包只会静默消失，排查依赖 `[net] 0x.. 收包处理失败` 日志；重要报文出问题时玩家感知为
  「这条没生效」而不是「整局崩掉」——这是刻意选择的失败语义；
- 不触碰 `render-mode.ts` / `worker-client.ts` 的致命判定：真正的渲染崩溃仍按 ADR-0071
  换后端重载、再退主线程。
