# ADR-0008：地形进同构契约，碰撞由服务端权威结算

- 状态：已采纳
- 日期：2026-10-30

## 背景

世界是 8192×8192，但地图只有一层：`renderer.buildGround()` 里程序化画一张 256px 办公地板，
之后无限平铺。玩家出生在正中心 ±240px，视野半径 900px，所以绝大多数时候看到的是一片重复地砖。

需要加入森林、湖泊、河流与围栏，并且**这些地形要挡住玩家**。项目的既有约束是：

- 协议冻结：移动包固定 8 字节，没有地形下发；
- 零持久化：世界只活在进程内存里；
- 像素栅格以设备像素为准（ADR-0005），纹理 1:1 生成、nearest 采样。

## 问题

1. 地形几何放在哪，才能让服务端与客户端判定完全一致？
2. 碰撞谁结算，客户端预测与服务端权威怎么不打架？
3. 8192² 的世界，树可能上千棵，怎么渲染才不掉帧？
4. 地形是有前后关系的（树冠要挡住站在后面的人），而现有渲染层是扁平的。

## 决策

1. **地形作为同构契约放进 `@niuma/shared-types/src/world/`**
   - `layout.ts`：手写中心园区坐标（围栏与四门洞、办公广场、土路、梯形河流、湖、木桥、三片森林、区域名），
     树点用 `Math.imul` 派生的 mulberry32 生成——禁止 `Math.random` / `Math.sin` / `Math.cos`，
     否则 Bun(JSC) 与浏览器(V8) 会给出不同结果，双端各画各的地图。
   - `geometry.ts` / `collision.ts`：纯几何与移动求解，无框架依赖。
   - 不新建 `packages/world-map`：当前只有一张图，多一层 package / tsconfig / transpilePackages 装配换不来任何边界收益。
     等出现第二张地图、地图编辑器或布局文件超过数百行，再拆包。
   - 不扩协议：静态世界由双方各自 import 同一份代码即可，服务端下发地形只会增加握手阻塞。

2. **服务端权威 + 客户端同函数预测**
   - `applyMove` 先按时间窗限速截断，再把结果交给 `resolveMotion`；`clampWorldX/Y` 保留为最后一道。
   - 客户端 `tick` 用同一个函数做本地预测，被挡住时不再播放走路动画。
   - 出生点改用 `findFreePoint` 兜底，不会落在水面或栏板里。

3. **碰撞求解：网格索引 + 子步 + 轴分离滑动**
   - 障碍分三类：圆（树干）、胶囊（围栏栏板，2px 厚）、多边形（湖面与河段）。
   - 128px 均匀网格索引，单次查询只遍历邻近桶；200 人 × 20Hz ≈ 4000 次/秒仍可忽略。
   - 4px 子步小于「最薄障碍 + 玩家半径 7」，不会穿模；整段被挡时退化为单轴移动，
     贴墙走是滑行而不是卡死。
   - 桥面是「水域放行区」，桥以外的河段一律不可涉水；桥面两端比河岸各外扩 32px，
     否则角色中心点会被 7px 碰撞半径卡在桥头。

4. **渲染：运行时程序化纹理 + y 排序层**
   - 草地 256、水面 32、土路 128、广场 256 的平铺图块，与四套树、石头、芦苇精灵，
     全部在 `renderer.init()` 内一次性 `generateTexture({ resolution: 1, textureSourceOptions: { scaleMode: 'nearest' } })`；
     帧循环只滚 `TilingSprite.tilePosition`，不再生成纹理。
   - 湖面用多边形遮罩 + 水面平铺；河流是轴对齐阶梯矩形，全部落在像素栅格上。
   - 树与围栏进 `sortableChildren` 容器，和角色统一按**脚底 y** 排序，走到树后会被树冠挡住；
     昵称与气泡拆到独立顶层，避免被树冠吃掉。
   - 树按视口 ± 1 屏裁剪（`renderable` 开关），可见对象保持在百级。

5. **小地图从同一份布局直接绘制**
   - 168×168 画布覆盖 1800×1800 世界像素（正好是 AOI 半径），4Hz 重绘；
     草地/林地/广场/土路/水面/桥/围栏/树点全部由 `WORLD_LAYOUT` 变换得到，和主视图不会不同步。

## 后果

- 正面：地图从一张重复地砖变成可读的园区，围栏与门洞形成明确的通行引导；
  碰撞双端一致，客户端没有「先穿墙再被拉回」的橡皮筋；
  地形是纯代码内容，零持久化、零协议变更、零新依赖。
- 负面：契约包承担了一部分「世界内容」的职责，`shared-types` 不再只是协议与量化；
  世界内容与代码同版本，改地图必须双端一起发布（这本来就是静态世界的语义）；
  排序容器每帧对可见对象做一次 O(n log n)，树越多越贵（已用裁剪压住）；
  水面的多边形遮罩在 WebGPU 下依赖 stencil，低端设备需实测。
- 回滚成本：低。删除 `TerrainView` 图层，并移除 `applyMove` 与 `tick` 里的两处 `resolveMotion` 调用，
  即回到原来的无限地板；地形数据留在包里不影响任何协议。

## 复核信号

- 出现第二张地图、地图编辑器或需要按区域配置规则 → 把 `world/` 拆成独立内容包。
- 200 人压测里 Tick p95 相对本次之前上升超过 20% → 先检查碰撞索引的桶大小与子步上限。
- 玩家反馈「贴着围栏走会抖」→ 检查本地实体的 0.35 收敛策略，改为近距直接吸附。
- 低端设备上湖面遮罩掉帧 → 改成一次性烘焙的湖面纹理（多花约 4MB 显存换掉 stencil）。
