# ADR-0036：北门迎宾出生点、世界地标与 HUD 园区导览

- 状态：已采纳
- 日期：2026-11-11

## 背景

旧版出生圈以世界中心（4096, 4096）为圆心、半径 300，玩家一进场就站在办公广场正中，
四面是开放式办公区的工位环。「出生点不要工位」是这次最直接的反馈：入场第一眼应该看到
园区，而不是一堵桌子。

同时，园区缺少一次性的入场引导：新玩家不知道工作区、卫生间、休息室、会议室分别在哪个方向，
也没有「欢迎来到牛马园」的仪式感。需求是「出生点 + 导航地图（四向箭头）+ 横幅」，
并且导航要同时存在于世界里（地标）与 HUD 里（随时可查）。

## 决策

### 1. 出生点迁到北门，出生圈收进门口袋

- `shared-types/world/layout.ts` 新增 `SPAWN_CENTER = (4096, 3300)`，`SPAWN_RADIUS` 300 → 72。
  整个出生圆落在北向土路与门肩（x 4024–4168 / y 3228–3372），北边留出沙滩，南边不越过办公区北缘。
- 服务端 `spawnPoint()` 只换采样中心，保留 16 次拒绝采样（陆地 / 障碍 / 水面）与 `findFreePoint` 兜底；
  兜底也回 `SPAWN_CENTER`，但**不改** `findFreePoint` 自己的世界中心兜底——那条路径同时服务移动卡死恢复，
  把远处卡住的人传送到入口属于不必要的爆炸半径。
- `config.spawnRadius` 的默认值改为 import `SPAWN_RADIUS`，不再各写一份字面量；
  `GAME_SPAWN_RADIUS` 环境变量覆盖与压测机器人路径不变。
- `REGIONS` 新增「牛马园北门」，排在「办公区」之前：站在门口时状态栏与 HUD 报的是入口，不是办公楼。

### 2. 导航目标只有一个来源

`NAV_TARGETS` 由 `WORKROOM / RESTROOM / LOUNGE / MEETING_ROOM` 四个房间矩形的中心派生，
世界指路牌、HUD 导览卡、单元测试都读这一份。房间挪位置时箭头自动跟着转，
不存在「客户端再写一份坐标」的第二真相。

客户端只做纯计算（`apps/web/lib/game/nav.ts`）：八向档位、从北起顺时针的方位角、
直线距离与 `distance / MOVE_SPEED` 的步行秒数。

### 3. 世界地标与 HUD 分工

- **世界内**：`WelcomeView` 在北门建两块常驻地标——跨门洞的布幡横幅「欢迎来到牛马园」，
  以及门东肩的四向指路牌（四行设施名 + 八向像素箭头 + 「你在这里」）。
  形体在构造期用 Graphics 烘焙成 1:1 纹理，中文用 Pixi `Text` + 系统 CJK 字体栈，
  `resolution` 跟 `devicePxPerTexel` 并在 DPR 变化时更新；按脚底 y 进 `SortLayer`，
  玩家可以走到前面挡住它。与 lamp / sign 一致，**不新增碰撞体**，不挡出生圈。
- **HUD 内**：`WelcomeBanner` 只在第一次 `online` 时出现一次，约 6 秒后淡出，
  断线重连不重复弹；`NavCard` 是可收起的「园区导览」，四行实时方位 + 设施名 + 步行秒数，
  最近目标高亮。桌面常驻在 MiniMap 上方；触摸端默认展开约 8 秒或离开北门口袋后收成一枚「导览」胶囊，
  用户手动开合后不再自动收起。
- HUD 不新增网络请求、不写 localStorage、不打印坐标或昵称。

### 4. 不新增协议包

出生点仍由服务端的 `S2C_WELCOME` 下发，resume / 座位恢复 / 落水回岸的裁决路径完全不变。
本轮全部是共享布局常量、客户端渲染与 HUD，不动 HELLO、不动 AOI、不落库。

## 后果

- 正面：新玩家落在北门口袋，第一眼是横幅、指路牌与门内的园区；四个设施的方位与步行时间
  在 HUD 里随时可查；导航数据与房间布局同源，改地图不会让箭头说谎。
- 负面：出生点不再是「世界中心」，压测与旧文档里「出生半径 240/300」的描述需要按新常量读；
  世界地标多两块常驻纹理与 7 个文字位图（约几十 KB），换来的是入场可读性。
  中文世界文字依赖系统 CJK 字体，字体缺失时由 HUD 导览卡兜底。
- 回滚成本：低。恢复 `SPAWN_CENTER` 为世界中心、`SPAWN_RADIUS` 为 300 即回到旧出生圈；
  客户端删掉 `WelcomeView` 的构建调用与两个 HUD 组件即回到无引导版本，互不牵连。

## 复核信号

- 新玩家仍出现在工位环里：先查 `GAME_SPAWN_RADIUS` 是否被环境变量放大，再查 `spawnPoint` 是否读的是
  `SPAWN_CENTER`；不要靠调大 `findFreePoint` 的搜索环来掩盖。
- 指路牌与 HUD 箭头方向不一致：两边都读 `NAV_TARGETS`，差异只可能来自传入了不同的起点坐标
  （世界牌按牌位算，HUD 按玩家实时位置算），这是预期行为。
- 中文在小屏上发虚：检查 `WelcomeView.setTextResolution` 是否接进了 `syncMetrics` 的 DPR 分支。
- 触摸端导览卡挡住摇杆或动作盘：调 `NavCard` 的 `compact` 定位与自动收起阈值（`LEASH`），
  不要改摇杆热区。
