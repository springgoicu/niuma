# ADR-0072：小黑屋执法——服务端判定、保安押送、送到即放人

- 状态：已采纳
- 日期：2026-11-13
- 关联：NPC 不传送沿用 ADR-0061；保安角色沿用 ADR-0063；押送位移复用 ADR-0003
  的 AOI 与 ADR-0043 的 idle/dirty 同步；零持久化沿用 ADR-0004；系统广播沿用
  ADR-0038

## 背景

园区里出现了「贴着别人反复坐下、站起」的骚扰玩法：不移动、不发言，但每一轮都
把旁边的玩家拽进座位动画，既影响观感又无法用聊天审核覆盖。需求是给园区一处
「小黑屋」，让保安把人请进去，形成一次完整可感知的执法事件。

约束：

- 判定必须服务端权威：客户端判定可伪造，且跨端会出现「别人看到被抓、自己没被抓」；
- 保安绝不能传送（ADR-0061）：追击与拖行都要看得见，瞬移会直接破坏园区可信度；
- 不新增持久化：禁足状态只活在进程内存，断线、重连、重启即清除（ADR-0004）；
- 不扩散寻路：园区已有客户端 A* 导航，但 NPC 一直刻意不做全图寻路；押送是唯一例外，
  范围必须收在「一间隔壁的短途」；
- 小黑屋要能一键回滚成普通空房，不影响地图其它区域与既有导览。

## 决策

### 1. 小黑屋只做地图数据，不新增实体系统

`JAIL = { x: 4320, y: 4790, w: 460, h: 320 }`、西墙门洞、门外铺装、反省点
`JAIL_ANCHOR = (4590, 4980)` 与左右 ±48px 的三个 `JAIL_ANCHORS` 全部放进
`shared-types/world`，与布局测试、服务端、客户端共用同一份坐标。

房间墙体并入 `roomWalls`，铺装并入 `isBlocked` 的可站立判定，区域名并入
`REGIONS`，导览并入 `NAV_TARGETS`。没有独立的地图格式、没有门状态机、没有开关门
动画：门洞就是一块可走的铺装缺口。

北缘距四角院落 74px、南缘距南侧庭院 30px，作为布局测试的硬断言，避免后续搬动
建筑时把通道挤没。

### 2. 判定只认「真人 + 完整坐站循环 + 有见证者」

规则常量集中在 `sim/detention.ts` 的 `DETENTION`，是唯一事实源：

| 常量 | 值 | 含义 |
|---|---|---|
| `WITNESS_RANGE_PX` | 56 | 坐下与起身瞬间，必须有另一名角色在半径内 |
| `CYCLE_WINDOW_MS` | 8000 | 只统计最近 8 秒的循环 |
| `CYCLE_MIN_MS` | 150 | 坐姿下限，挡住连点坐下/起身 |
| `CYCLE_MAX_MS` | 1200 | 坐姿上限，坐久了站起来不算「反复」 |
| `MIN_GAP_MS` | 150 | 相邻循环的最小间隔 |
| `ANCHOR_DRIFT_PX` | 32 | 循环点离首点超过该距离就清零，防止换地方后跨点位累计 |
| `WARN_CYCLES` | 3 | 第 3 次只警告本人 |
| `CONFIRM_CYCLES` | 6 | 第 6 次确认 |
| `RATE_WINDOW_MS` / `RATE_CYCLES` | 3000 / 4 | 3 秒内第 4 次提前确认，压住「加速连点」 |

循环定义为 `Sit → Idle` 的姿态跃迁；`Sit → Lie` 视为被创飞或主动躺下，整轮作废。
`NPC` 与 `wsId === 0` 的离线实体不参与判定。

成本：每 Tick 只做一次姿态比较；只在入座 / 起身的边沿做一次 56px 邻域查询，
不是每 Tick 全量空间查询。

### 3. 三级响应：警告 → 确认 → 派单

- 第 3 次循环：`JAIL_PHASE.Warn` 只发本人，3.5 秒黄条后自动消退，旁人不该知道
  「保安盯上你了」；
- 第 6 次循环或 3 秒内第 4 次：确认不当行为，广播系统提示
  「{name} 被保安请进了小黑屋：园区内不许色色。」（ADR-0038 的 `Detained` 频道）；
- 确认后立刻就近派单；保安全忙就排队，`update()` 每 Tick 重试，
  `DISPATCH_TIMEOUT_MS = 12s` 内等不到人就按证据不足放掉，不阻塞现场。

### 4. 押送状态机与 BFS 边界

单个案子的阶段：`pending → chasing → dragging →（arrive | abort）`。
保安任务：`chase → hold(0.6s 按肩) → drag → arrive`。

- 追击速度 1.3 倍、拖行 0.85 倍基础速度，抓取半径 26px；
- 拖行时被押者在保安身后 22px，位置由服务端每 Tick 直接写，客户端靠 dirty 同步看；
- 追击 12 秒没摸到人、拖行 15 秒没送到、被押者断线、路线不可达，一律 `abort`：
  原地松手、清硬直、恢复站姿，**不传送**；
- 送到反省点后原地停 2 秒，避免保安贴着人立刻再起步。

寻路只服务押送：`npc/escort-path.ts` 在 24px 网格上跑 BFS，8 邻接、禁止切角，
可站立判定复用 `isBlocked`，最后做视线简化。追击每 400ms 且目标位移超过 48px
才重算；拖行路线一次性算好，强制经过门外铺装中心，保证镜头里真的「从门进屋」
而不是从墙外判定到达。

网格约 28k 格，单次 BFS 是毫秒级；启动时 `warmEscortGrid()` 预热，避免第一次
执法把开销塞进某个 50ms Tick。这张网格不向巡逻、社交或玩家导航开放。

### 5. 没有禁足时长：送到反省点即放人

`arrive` 只做三件事：

1. 把坐标写到该案子占用的 `JAIL_ANCHORS` 槽位；
2. 清 `stunUntil`、清座位、落站姿；
3. 广播 `JAIL_PHASE.Released`。

**没有 30 秒计时器，也没有 `jailUntil` 字段。** 小黑屋保留为普通空房：进去之后
移动、聊天、坐下、发泄全部照常，玩家自己走出去。这样做的原因：

- 惩罚的意义在「被看见押走」，不在「关多久」；倒计时会把一次事件拖成 30 秒的挂机；
- 禁足需要服务端计时器、断线清理、重连恢复与客户端倒计时四处对齐，收益不成比例；
- 取消时长后，回滚只需关掉检测与派单，屋子本身不需要任何状态迁移。

押送期间的输入硬直只是「被按肩 / 被拖走」的表现，用 `stunUntil` 做临时上限
（`DRAG_LOCK_MS = 45s`），到达或中止即清零，语义上不是刑期。

### 6. 协议：9 字节阶段包 + Tick 复用

`S2C_JAIL = 0x30`：
`[op][entityId u16][phase u8][flags u8][seconds u16][guardId u16]`。

- `flags bit0 = 本人`：本人那份才允许客户端锁输入，旁人那份只画头顶气泡；
- phase 1 只发本人；2 / 3 / 5 发本人与 1000px 内的旁观者；
- `seconds` 字段保留但恒为 0，为未来可能出现的限时惩罚留位，不占用现有 state 位；
- 押送坐标不放进这条包，继续走 20Hz Tick 的 dirty 同步，不为一次事件新开高频通道；
- 旧客户端不认识 `0x30`，走 default 静默忽略，不影响正常同步。

客户端锁跟随阶段而不是计时：收到 `Escort` 起锁输入、位置完全采用服务端坐标；
收到 `Released` 立刻解锁、落回站姿。半路中止也发 `Released`，因此不存在「卡在
躺姿」的路径。

### 7. 回滚

`GAME_JAIL_ENABLED`（默认 true）关闭后：

- 不创建 `Detention`，不判定、不派单、不发包；
- 保安保留原有巡逻与社交；
- 小黑屋仍是可进入、可导览的普通空房，不需迁移任何状态。

没有保安（`npc.count.guard = 0`）时同样不启用：没人能押送，判定只会永远排队。

## 代价与取舍

- 判定窗口是启发式：真·正常玩家短时间内多次坐下站起也可能被警告，但警告只发本人；
- 「有见证者」把独角戏排除在外，也意味着两人串通时仍会触发，属可接受误判；
- BFS 是园区唯一的 NPC 寻路，维护成本高于复用客户端 A*，换来服务端权威与不穿墙；
- 无禁足时长意味着「惩罚」很轻，但事件的可感知性来自押送过程与系统广播，
  不来自关押时间；
- 客户端在押送期间完全放弃预测，位置按 20Hz 更新，会被看到轻微台阶感；
  这是「被架着走」时的可接受代价，换取零穿墙与零回拉。

## 备选方案（未采纳）

- 保安瞬移到现场或把人传送进小黑屋：违反 ADR-0061，且玩家会看到凭空出现；
- 客户端判定、只上报结果：可伪造，跨端不一致；
- 服务端全图 A* 或复用客户端寻路：超出「押送短途」的边界，Tick 预算不可控；
- 30 秒 / 60 秒禁足：需要计时器 + 断线恢复 + 客户端倒计时三套状态，收益不足；
- 把 `jailUntil` 塞进现有 state 位：位已满，且会让旧客户端把「禁足」误读成别的姿态。
