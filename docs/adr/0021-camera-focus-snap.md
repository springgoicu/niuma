# ADR-0021：相机与角色同源取整，本地移动以预测为准

- 状态：已采纳
- 日期：2026-11-09

## 背景

反馈是「走路时画面抖动严重」：角色相对背景高频横跳，走起来整屏发颤。
ADR-0005 已确立整纹素栅格与设备像素取整，但取整函数分散在渲染层各处，
相机与角色各自调用，没人保证两者落在同一格上。

## 问题

1. 相机在 `updateCamera` 里用 `Math.floor`，角色在 `updateEntity` 里用 `snapTexel`（`Math.round`）。
   两者在每移动 1 世界像素时错开 1 纹素：60fps、165px/s 下 `round` 与 `floor` 每 4 帧翻转一次，
   角色相对屏幕以约 15Hz 横跳 3 CSS px。相机夹紧前世界层也是按同一批整数步进，抖动被完整放大。
2. 本地玩家每收到一次 sync（20Hz）就被按 35% 拉向服务端坐标，偏差超过 8px 直接瞬移。
   服务端不自推进位置，sync 坐标天然是「客户端上包位置」的回声，落后
   `RTT/2 + 一个 Tick + 发送间隔`（localhost 也有 4–8px）。这条校正把网络延迟变成了
   20Hz 的位置锯齿，再经相机硬跟随原样传进画面。

## 决策

1. **相机与角色共用同一吸附函数**。新增 `apps/web/lib/game/camera.ts`：
   `cameraAxis` 负责夹紧 / 视口过宽时居中 / NaN 回退，`cameraFocus` 在其后调用 `snapTexel`。
   `updateCamera` 只用 `cameraFocus`，未夹紧时 `camX === snapTexel(角色坐标)`，
   角色相对屏幕偏移恒为 0；贴边时相机静止、角色连续偏移，不产生量化翻转。
   不做亚像素相机滚动：会破坏 ADR-0005 的整纹素栅格与 nearest 采样。
2. **本地玩家以本地预测为准**。`handleSync` 的本地分支取消逐包按比例拉回，
   只在偏差超过 `MOVEMENT_CONFIG.LOCAL_DRIFT_LIMIT`（128px，约 0.78s 行程）时一次性对齐。
   正常移动的偏差远小于该值（250ms 单向延迟约 58px），因此不会被校正；
   限速截断、地形求解分叉、传送等真实失步仍会被纠正。
3. 远端角色的快照时间线插值、服务端限速、协议与移动速度全部不动。

## 后果

- 正面：角色与昵称钉在屏幕中心，背景以稳定 1 纹素步进滚动；20Hz 回弹消失；
  相机取整规则收敛到一处，后续不再可能改回 floor。
- 负面：真实失步时会出现一次可见的瞬移（异常路径，可接受）；
  极端网络下客户端位置允许领先服务端最多 128px，他人看到的仍是服务端权威位置，
  因此不影响他人观感与反作弊边界。
- 回滚成本：低。把 `cameraFocus` 换回 `Math.floor`、恢复 0.35 逐包校正即可，
  两处都只涉及单个函数。

## 复核信号

- 超过 250ms 单向延迟时出现「角色被瞬间拽回」的投诉：说明 128px 阈值需要按实际链路重估，
  或应改为带 ack 的重放式和解（需要协议加字段，成本更高）。
- 若观感从「抖动」变成「背景步进感明显」：那是 ADR-0005 已接受的取舍，
  要改只能整体转向亚像素相机，属于另一个决策。
