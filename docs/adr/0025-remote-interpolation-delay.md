# ADR-0025：远端角色改为 80ms 固定延迟回放

- 状态：已采纳
- 日期：2026-11-10
- 关联：修订 ADR-0021（相机与本地预测的对齐），取代 `session.ts` 里原 `MOVEMENT_CONFIG` 的三层位移策略

## 背景

远端角色原来的位置策略是「收到就播到最新」：

1. `handleSync` 每收到一条同步，就把上一帧存成 `prev`、新坐标存成 `current`，
   `currentTime` 记为到达时刻；
2. 帧循环算 `progress = (now - currentTime) / (currentTime - prevTime)`，
   在 0..1 之间从 `prev` 线性插到 `current`；
3. 进度超过 1 就改用指数逼近 `k = 1 - exp(-dt × 14)` 继续贴近目标。

因为 `currentTime - prevTime` 就是两包的实际间隔（约 50ms），角色只在 50ms 内追到目标，
然后**停在原地等下一包**。网络抖动（包早到或晚到）因此一比一映射成画面上的
「停一下，再窜一下」。

同一个实现里还有三条互相叠加的补丁：位移 > 320px 时只走 30% 距离
（`SMOOTH_CORRECTION_FACTOR`）、> 1000px 直接瞬移、本地偏差 > 128px 一次性对齐。
前两条实际上是在人为制造「持续追赶」——刚追上又只走三成，观感比不补更差。

另有一处不一致：姿态与叠加位在收到包时立刻写入 `Motion`，位置却要再延迟一个包才走完，
于是会出现「原地踏步再迈出去」。图集没有行走叫唤帧，这个错位尤其显眼。

## 备选方案

| 方案 | 收益 | 代价 | 不可逆性 |
|---|---|---|---|
| A. 继续调 `INTERPOLATION_FACTOR` 与阈值 | 一行参数 | 抖动是「没有缓冲」造成的结构问题，调参只会把停走变成慢走或过冲 | 低 |
| B. 外推（按速度预测下一包位置） | 零额外延迟 | 晚到的包会让角色先冲出去再弹回来，抖动被放大；丢包时越跑越偏 | 中 |
| C. 固定延迟 80ms + 环形快照回放（采纳） | 抖动被吸收成匀速位移，姿态与位移同源 | 旁观者看到的他人晚约 1.6 个 Tick | 低 |

选 C。本项目当前最大的体感问题是「别人走起来一顿一顿」，而不是「我看到别人晚了半拍」；
外推（B）会把前者换成后者里更难接受的一种形态——过冲。

## 决策

新增 `apps/web/lib/game/interp.ts`：

- 每个远端实体维护 `SNAPSHOT_DEPTH = 4` 帧环形快照，每帧 `(到达时刻, x, y, state)`，
  用 `Float64Array` / `Float32Array` / `Uint8Array` 按 `eid × depth + slot` 展平，帧循环零分配。
- 渲染时刻取 `now - INTERP_DELAY_MS`，`INTERP_DELAY_MS = 80`。服务端 Tick 间隔 50ms，
  80ms 留出 ±30ms 抖动余量。
- 在环里找夹住该时刻的两帧做线性插值。早于最旧帧钳到最旧、晚于最新帧钳到最新，
  **不外推**。
- `state` 取自**左帧**（区间开始时的那一帧）：这一帧描述的正是该区间内的姿态，
  与插值位置同源，彻底消除「先迈步后位移」。
- `handleSync` 里的一条包共用一个到达时刻，不再逐条读时钟。
- 删除 `MOVEMENT_CONFIG` 的三层位移分支、`Snapshot` 的 prev/current 双帧存储与
  `Target` 组件。本地玩家完全不走这条路。

### 为什么延迟是 80ms 而不是更小

- 小于 50ms：必然频繁越界到「晚于最新帧」，退化成钳位，也就是停住等包，
  等于把方案 C 打回方案 A；
- 大于 120ms：`VIEW_RADIUS` 1000 下会明显感到「我看到的他和实际位置差半个身位」，
  在同一个工位抢座这类交互上会读错；
- 80ms 是「刚好覆盖两个 Tick + 一次抖动」的最小值，写在常量里，可按实测抖动调。

### 本地玩家不受影响

本地仍是 `resolveMotion` 确定性预测（与服务端共用同一个函数），零额外延迟。
插值只作用于「别人」。

## 后果

- 正面：抖动被缓冲吸收，他人行走连续；姿态与位移同源，不再出现原地踏步再迈出；
  代码净减少——删掉了三层位移分支与两组快照字段。
- 负面：
  - 旁观者看到的他人晚约 80ms（1.6 个 Tick）。两人并肩同走会有轻微错位；
  - 远端叠加动作（叫唤 / 挥手 / 跳）的起止时刻跟着延迟 80ms，
    与本地玩家的即时反馈不同步，但两者本来也没有视觉耦合点；
  - 新入场实体在 80ms 内没有可插值的下一帧，会停在入场位置等第二帧到齐。
    这段静止只有 80ms，且入场本来就有 `addEntity` 的异步开销。
- 回滚成本：低。把 `INTERP_DELAY_MS` 设为 0 即退化为「钳到最新帧」，
  等价于原来的直追行为；要完全恢复旧逻辑则需恢复 `MOVEMENT_CONFIG` 分支。

## 复核信号

- 出现「别人走路一顿一顿」：说明延迟仍小于抖动幅度。先量客户端收到的包间隔分布
  （同步包的 `performance.now()` 差值），再把 `INTERP_DELAY_MS` 往上调，
  而不是去调插值算法。
- 出现「角色从视野边缘平移飘进来」：检查 `handleSpawn` 是否塞了首帧快照。
  没有首帧时 `sample` 会返回 false，实体停在 (0,0)，表现为从地图左上角飞过来。
- 出现「别人叫唤像延迟了一拍」：这是本决策的固有代价。
  若确认不可接受，应改成「叠加位走即时通道、位移走回放通道」，
  但那会重新引入「原地踏步」——两者不可兼得，需要重新评估。
