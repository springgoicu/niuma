# ADR-0023：坐 / 躺开关语义与叫唤音效

- 状态：已采纳
- 日期：2026-11-10
- 关联：ADR-0018（叠加动作与 state 位）、ADR-0019（打招呼叠加）、ADR-0020（工位、座位与园区设施）

## 背景

玩家反馈集中在三处「点了没反应」：

1. 点击「叫唤」只有动作没有声音，项目此前完全没有音频链路。
2. 「坐下」是单向姿势：地面坐姿再按 Z 没有反应，座位坐姿必须靠移动才能起身（ADR-0020 §3 规定「Z 在已入座时无效」）。
3. 动作按钮不反映当前姿态；行走中按叫唤 / 打招呼静默失效；长按 Z 因键盘自动重复会反复坐 / 起。

## 决策

### 1. Z / X 是开关，不是单向姿势

- `Z`：站立 → 坐下（附近有空位优先吸附入座，否则就地坐）；已坐（座位或地面）→ 起身。
- `X`：站立 / 地面坐 → 躺下；已躺 → 起身。
- 座位坐姿按 `Z` 起身会发送 `ACTION.Stand`，由服务端释放座位并广播。
- 本条覆盖 ADR-0020 §3 中「Z 在已入座时无效」这一句；座位权威仍在服务端。

### 2. 座位上按 X 仍然无效，但不再静默

ADR-0020 的「座位上不能躺」保留（服务端 `ACTION.Lie` 在 `seat !== 0` 时直接返回）。
客户端提前拦截并显示不可用态，点击给出「座位上不能躺，先按 Z 起身」的瞬时提示。

### 3. 行走中的动作

- 行走中经过空位按 `Z` 仍然直接吸附入座：吸附是瞬时的，不存在滑步。
- 行走中无空位按 `Z`、按 `X`、按 `E` 不切姿态，改为 1.6s 的瞬时提示（「站定后才能…」），
  避免「设了姿势又被下一帧走路覆盖」的一帧闪烁。
- 行走中按叫唤始终发声，但不播动画：图集没有行走张嘴帧（ADR-0018），套到脚步上就是滑步。

### 4. 叫唤音效

- 使用 Web Audio 实时合成，不引入 mp3 / wav 资源：牛为低频「哞」，马为带颤音的下滑「嘶鸣」。
- `AudioContext` 懒初始化，首次发声一定发生在点击 / 按键手势里，绕开自动播放限制；
  创建失败只 `console.warn` 一次并降级为静音。
- 90ms 节流防止连点叠音；节点播完主动 `disconnect`，不进入帧循环。
- 静音偏好只存客户端 `localStorage`，不参与协议与服务端状态（ADR-0004）。

### 5. 决策落点

- 交互裁决抽成纯函数 `apps/web/lib/game/actions.ts`：输入姿态、入座、行走、空位，输出意图；
  `GameSession.perform()` 只执行意图（改 `Motion`、发包、播音、出提示）。
- 按钮表现（激活态、不可用态、文案「起身」）复用同一个纯函数的 `actionPresentation()`，
  桌面 `ActionBar` 与触屏 `TouchActions` 不再各自判断。
- 本地姿态只在 `(pose, seated)` 变化时通过 `onLocalState` 下发 React，避免 60fps 的 setState。

### 6. 输入层与服务端

- 键盘自动重复（`event.repeat`）只维护按键集合，不再派发动作键；Ctrl / Cmd / Alt 组合直接忽略。
- 打开聊天输入框时清空移动按键，避免收起后角色继续滑行。
- `SeatRegistry.stand()` 在 `seat === 0` 时也把 Sit / Lie 归零到 Idle：
  地面起身不再依赖下一包 20Hz move 才对远端生效。

## 后果

- 协议、姿态枚举、图集与叠加动作窗口均未改动，叫唤仍是与姿态正交的标志位。
- 座位抢座冲突仍以服务端广播为准；起身后位置留在椅子旁。
- `ACTION.Stand` 从「仅释放座位」扩展为「释放座位 + 归零姿态」，旧客户端不发这个包，向后兼容。
- 音效完全在客户端，播放失败只影响听感，不影响交互。

## 回滚

- 前端：还原 `actions.ts` 与 `session.perform()` 即可回到单向姿势；`sfx.ts` 无其他依赖，可整文件删除。
- 服务端：去掉 `SeatRegistry.stand()` 的姿态归零分支，地面起身退化为等下一包 move。
