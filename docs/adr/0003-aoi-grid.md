# ADR-0003：AOI 用均匀空间哈希，跨格才做视野差量

- 状态：已采纳
- 日期：2026-10-28

## 背景

一张 8192×8192 的地图，单人视野 900px。全图广播意味着每个 Tick 向所有人推送所有人的位移，
带宽与 CPU 都随在线人数平方增长，不可接受。

## 决策

- 512px 均匀网格，`Map<cellKey, Set<entityId>>` 作为反向索引；
- 实体移动时只更新所在桶，返回「是否跨格」；
- 只有跨格、上线、下线时才重算视野集合，并与 `known` 集合做差集：
  - 新增：双方互发 `S2C_ENTITY_SPAWN`
  - 移除：双方互发 `S2C_ENTITY_DESPAWN`
- 同步广播时先按格取超集，再用 `known.has(id)` 过滤，保证不会给「看不见的人」发包。

可见性是对称的，因此差量必须同时修正双方的 `known`，否则会出现「我看得见他、他看不见我」的幽灵实体。

## 为什么不用四叉树 / 跳表

地图是均匀的开放平面，实体分布没有明显的层次聚集；四叉树带来的树维护成本与指针跳转
在这个规模下不如固定网格。等世界出现大量静态、非均匀的遮挡物再考虑。

## 后果

- 正面：查询 O(视野内格子数)，广播 O(视野内人数)，与全图人数无关。
- 负面：格子边长与视野半径需要调参；极端密集（单格上千人）时仍会退化。
- 回滚成本：低。`SpatialGrid` 只有 insert/update/remove/queryNear 四个方法。

## 复核信号

单格实体数持续超过 200，或出现需要按朝向裁剪的视野（例如「只看得见前方」）时，评估锥形 AOI。
