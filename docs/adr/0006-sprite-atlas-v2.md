# ADR-0006：图集 v2——16 列帧预算、独立高光层与逐帧动画

- 状态：已采纳（网格尺寸相关的判断已由 ADR-0010 取代：48×48 → 64×64，配件 16 → 20）
- 日期：2026-10-29

## 背景

角色美术此前是「每方向 8 帧」的程序化占位资源：待机 2 帧、行走 4 帧、坐/躺各 1 帧静态图。
反馈是「像黑底上的剪影」——造型读不出结构，动作像幻灯片。

对照 pony.town 这类成熟像素项目，差距不在分辨率（48×48 已经够用），而在四件事：

1. 剪影：头与身子一样宽、四条腿糊成两根柱子、尾巴埋在臀里；
2. 体积：只有「压暗」没有「提亮」，背线与眼神光做不出来；
3. 节奏：四拍行走没有重心起伏，坐/躺完全静止，所有实体同一相位，像广播体操；
4. 场景：角色没有接触阴影，脚下没有反馈，砖面是纯棋盘格。

## 问题

前三条都撞在同一处约束上：ADR-0002 决定用「分层灰度图 + `Sprite.tint`」做调色板替换，
而 tint 是乘法——灰度图最亮只能到 255，也就是**只能变暗，不能提亮**。
想在 48px 的尺度上让背线比本体亮一档，加多少 luma 都没用。

同时帧预算被写死在两处（生成器的 `COLUMNS = 8` 与客户端的 `direction * 8 + frame`），
加一帧要同时改生成器、切片、CSS mask、播放逻辑，等于事实上不可扩展。

## 决策

1. **帧预算升到 16 列，且只有一份真相**：新增 `packages/pixel-assets/src/layout.ts`
   定义 `FRAME_SIZE/COLUMNS/ROWS/CLIPS/poseOfColumn`；生成器据此作画，并把布局写成
   `apps/web/lib/game/sprite-layout.generated.ts`，客户端切片与 SSR 的 CSS mask 都读它。
   列预算：idle 0-2（呼吸 2 + 眨眼 1）、walk 3-8（六拍 80ms）、sit 9-10、lie 11-12、emote 13-15。
2. **新增两个纯白图层** `bodyLight` / `eyeLight`。它们不新增外观字段：
   客户端把主体色往白里混 22%、眼睛色往白里混 70% 当 tint（`lib/color.ts` 的 `mixHex`）。
   代价是每角色多 2 个 Sprite，仍与其余图层共享图集、继续合批、每帧零额外开销。
3. **manifest 升 v2**：`clips` 从 `{ frames, fps }` 改为 `{ frames, frameMs[], loopFrom, loop }`，
   支持逐帧停留与一次性动作；`atlas.ts` 校验版本与行列数，不匹配直接抛错提示重跑 `pnpm assets`
   （宁可白屏报错，也不要静默错帧）。
4. **动画求值下沉到 `lib/game/clip.ts`**：manifest 预编译成累计时间轴，每帧一次顺序查表；
   相位按 `netId` 哈希错开，只有循环动作参与；一次性动作播完钳在末帧。
5. **叫唤（Emote）落地为客户端计时**：协议里 `pose` 早已有 `Emote`(4) 位，服务端也已支持，
   缺的只是渲染。本地播完 440ms 自动回 Idle 并把新状态广播出去；远端不自行回收——
   服务端会持续重发 Emote，本地回收会和重发打架变成无限循环。
6. **镜头层加接触阴影与踏步扬尘**：阴影纹理全局共用一张；尘土是 48 个 Sprite 的固定池，
   帧循环只改 position/alpha/visible，缩放只在 1 与 2 之间跳（亚像素放大会立刻露出插值边）。
7. **配件改为 16×16 且 1:1**：旧版按 16 格构图再 0.75 落到 12 格，等于丢掉三分之一的像素。
   视觉尺寸靠图标内部的留白控制，而不是靠缩放。

## 后果

- 正面：造型有背线高光、眼神光与分段腿；行走有重心起伏与拖尾；坐/躺保留呼吸；
  视野里的角色不再同相位；脚下有阴影与扬尘；配件不再是糊图。
- 负面：图集面积翻倍（384×192 → 768×192），每张 PNG 常驻显存约 590KB，
  两个物种共约 16 MiB，高于旧版约 6.4 MiB。低端设备或移动端首屏多一次纹理上传。
  另外 16 列里 idle 只用 3 列，属于为「不重排图集」付的固定成本。
- 回滚成本：低。`layout.ts` 的 `COLUMNS` 与 `CLIPS` 退回 8 列四拍、删掉 `bodyLight/eyeLight`
  两层的引用即可恢复旧观感；协议、服务端、外观编码都没有改动。

## 复核信号

- 移动端或集显设备出现明显掉帧/首屏发白，说明 16 MiB 常驻显存的取舍需要重新评估，
  优先砍 `bodyLight` 的变体数量（按 tail 变体生成），不砍行走帧数。
- 出现「自己看到的是叫唤、别人看到的是站立」的反馈，说明客户端计时与 20Hz 同步包之间
  存在竞态，需要把 Emote 的持续时间写进协议或服务端状态机。
- 出现「125%/150% 缩放下角色边缘发虚」，说明新增的高光层引入了新的采样点，回到 ADR-0005 排查。
