# ADR-0117：康复者逐帧走出急救站，站内不留人

- 状态：已采纳
- 日期：2026-11-17
- 关联：急救链与工伤护盾沿用 ADR-0084；下床 360ms 逐 Tick 过渡、`NpcRestorePort` 只清状态不写坐标、客户端 `patientLocked` 沿用 ADR-0109；门禁「只挡进不挡出」与「治好自己走出去」口径沿用 ADR-0107（本 ADR 取代其中「离场由谁驱动」一条）；开服一次性清场 `evictIntruders` 沿用 ADR-0114（本 ADR 解释与当年否决的方案 E 的差异）；零持久化沿用 ADR-0004 / ADR-0081；时间口径沿用 ADR-0081

## 背景

现场反馈「护士站里很多人」。核查 `sim/clinic` 与 `npc/director` 确认，"人多"不是排队等车，而是**治疗完成的伤员下床/起身原地停住、越积越多**，分两条线：

1. **真人**：`advanceBeds` 把伤员 tween 到床尾后 `finishStay` → `grantImmunity` 只发状态、不写坐标，`PATIENT_STATE.Shielded` 一到客户端就把 `patientLocked` 置回 false，位置彻底交还玩家。玩家若 AFK 或只是看热闹，就永远站在床尾/落点，服务端零干预。
2. **NPC**：`NpcRestorePort.restore` 只清状态 + 600ms 停顿，随后靠通用漫游自己走。巡逻采样点虽已排除站内（`npc/spots.ts`），门禁也不挡出站，但没有任何「确定出院」动作：卡柜台/围栏角、恢复盯梢、再次被打倒都会延长滞留，站内因此长期留着一批刚治好的人。

两条线共同的缺口是：**急救链管「送进来、治好」，却不管「治好后离开」**。旧口径 ADR-0107 写的是「治好的伤员必须自己走出去」——把离场完全交给玩家自主与 NPC 漫游，实测会堆积；ADR-0114 备选方案 E「每次康复后强制送出站」已因「与 0107 冲突、等于一次瞬移」被否决。用户明确要求真人与 NPC 一视同仁地出院，并接受真人几秒不可操作，故重开此决策。

## 决策

### 1. 在康复收尾的唯一汇合处插入「出院」阶段

`sim/clinic` 的 `finishStay` / `restoreNpc` / `grantImmunity` 是真人与 NPC 康复的共同收尾点。治疗到期、下床 tween（360ms）结束后不立即宣告康复完成，而是先把实体登记进 clinic 内部 `discharges` 表，进入出院阶段：

- 航点由几何派生：`床尾 / CLINIC_DROP` → 护理走廊 → 西门门洞 → 站外铺装 `CLINIC_SPILL_POINT`（`CLINIC_REGION_RECT.x - 60`，仍落在服务广场），不引入寻路、不新增几何；
- 每 Tick 沿航点逐帧推进，复用 `startTween` / `advanceTweens` 的坐标写法：仅位移有效时 `dirty=true`、`grid.update`，按需刷 AOI；位移量级与下床 tween 同档，客户端看到的是连续走出，不是一帧跳。

出院表规模 = 同时在院的康复者数量（个位到小几十），每 Tick O(n) 遍历一次，航点固定约 4 段，无重复寻路。

### 2. 出院期间服务端独占坐标，两类实体各自"占位"

- **真人**：出院期间 `patientState` 保持 `Treating`，客户端 `patientLocked` 继续为 true，本地预测让位服务端，杜绝「服务端推、客户端拉」的坐标打架；走到站外后才发 `Shielded`。代价是护盾/免疫起点与康复播报整体推迟约 1~2 秒（出院时长），**免疫时长仍为 15 秒，玩法数值不变**。
- **NPC**：出院期间保持 `incapacitated=true`，使 `npc/brain.updateAgent` 首行直接 return，不会与服务端位移抢写；姿态可走可站，但不进入漫游。到站外后才走既有 `restoreNpc`（清状态 + `recovery.restore` 续接巡逻/盯梢）。
- **护士**（`ENTITY_ROLE_NURSE`）排除出院，继续 `beginBack` 走回站位常驻——护士是站内固定岗，不是康复者。

`recovery.restore` 的接口与「只清状态不写坐标」语义不变，只是调用时机从「治疗结束瞬间」后移到「出院到站外之后」；`npc/director.test.ts` 中「restore 不写坐标」的断言仍成立。

### 3. 打断与兜底

- `downPlayer` 再次命中、`onDisconnect` 掉线时，与现有 `tweens.delete(playerId)` 同级清理 discharge，否则会出现「出院途中被打倒仍被推着走」「人已离场还占着出院表」。
- 复用 `NURSE_STUCK_MS` 同量级的位移超时：若门洞堵塞/碰撞卡死，到期直接落到站外安全点并结束出院，保证任何异常都不会把人永久留在院内，也不会无限占用出院记录。
- 时间口径一律用传入的服务端 `now`，不用 `Date.now()`。

### 4. 零协议、零持久化、零客户端改动

不新增包类型、不改 `PATIENT_STATE` 值域、不写 `world-state.json`。客户端预期零改动：靠「出院完成才发 Shielded」这一时序，复用既有 `patientLocked` 语义即可，无需新增出院锁或状态广播。

## 与旧口径的差异（本次为何不违反 ADR-0107 / 0114 方案 E）

| 维度 | ADR-0114 方案 E（否决） | 本次（ADR-0117） |
|---|---|---|
| 位移方式 | 一次性「送出站」，观感等于瞬移 | 逐 Tick 连续位移，可见地沿走廊走出 |
| 作用对象 | 运行期任意闲人（持续清扫） | 仅刚治疗结束、下床完成的康复者 |
| 触发时机 | 事后清扫 | 康复收尾的唯一汇合处即时接管 |
| 路径 | 直接落点 | 走门禁走廊与门洞，不穿墙、不塞障碍 |

ADR-0107 的两条规则里，**门禁「只挡进不挡出」与「防闲人进站」完全不变**（从站内往站外走在门禁层天然放行）；本 ADR 只取代「治好后离场由玩家/漫游自行驱动」这一条——离场驱动方改为 clinic，理由是真人与 NPC 的实测滞留证明了自发离场不可靠。其余急救链数值（派车、排队、上床、治疗 3 秒、免疫 15 秒）一律不变。

## 备选方案（未采纳）

| 方案 | 收益 | 代价 | 结论 |
|---|---|---|---|
| A. 服务端逐帧出院 + 延后 Shielded（本 ADR） | 真人与 NPC 同口径；协议/客户端零改动；回滚只需删 discharge 分支 | 护盾起点推迟 1~2 秒；出院期间真人不可操作 | 采纳 |
| B. 客户端新增出院锁 + 新状态广播 | 护盾可按时发、出院期间可显示进度 | 改协议值域 + 客户端分支，跨端状态机同步风险高，收益不匹配 | 否决 |
| C. 只优化 NPC 漫游，真人仍自主 | 改动最小 | 不满足「真人也出院」需求，真人 AFK 仍堆积 | 否决 |
| D. 康复后瞬移到站外点 | 实现最简单 | 复发 ADR-0114 方案 E 的瞬移问题，玩家看到人凭空消失 | 否决 |

## 后果

- 站内不再堆积康复者：治好即沿走廊走出，站体内部只留护士与正在急救链中的伤员；
- 真人出院期间约 1~2 秒不可自主移动，护盾/免疫与康复播报相应推迟，但免疫时长与所有玩法数值不变；
- NPC 出院完成才续接巡逻，比旧口径多 1~2 秒才恢复可接单；`npc/director` 的边界与接口不变；
- 出院是内存态（ADR-0004 / 0081），重启即清空，`world-state.json` 与网络协议零影响；
- 现有测试 `clinic.test.ts` 中「Shielded 时 `isInClinicInterior()===true`」「康复瞬间人在床尾」等断言需更新为「出院瞬间仍在站内、Shielded 时已在站外」，属预期时序变更，不是回归。

## 回滚

删除 `discharges` 表与 `advanceDischarges` 调用，恢复 `finishStay` / `restoreNpc` / `grantImmunity` 原顺序（治疗结束即发 Shielded、位置交还玩家/漫游）即可。协议、落盘、几何零影响，既有测试断言可直接恢复。本 ADR 标记 `superseded by ADR-0107 的「自己走出去」口径`（若整体回退），或保留为历史决策，不改写 ADR-0107 / 0114 原文。30 天内可整体 revert 本 ADR 的提交，无需迁移数据。
