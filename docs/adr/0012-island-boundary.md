# ADR-0012：海岛边界——海岸线进同构契约，海即墙

- 状态：已采纳
- 日期：2026-11-02

## 背景

世界是 8192×8192，草地铺满整个世界矩形，但内容只占 x 852–7602、y 226–7848。
玩家沿任意方向一直走会撞上坐标上限这道看不见的墙，再往前只剩近黑背景；
小地图也把整块画布当草地，看不出「地图到此为止」。

需求是让地图有明确范围：可见、可走、不会露出世界外的虚空。

## 问题

1. 边界放在渲染层，还是放进同构契约？
2. 用矩形还是多边形海岸线？要不要顺手缩小 `WORLD_WIDTH` / `WORLD_HEIGHT`？
3. 海面与草地怎么叠，才不会破坏既有的 y 排序与 1:1 纹理纪律？
4. 相机、小地图、出生点与压测半径怎么跟同一份边界对齐？
5. 碰撞热路径多一次几何判定，Tick 预算还撑得住吗？

## 决策

1. **海岸线进同构契约**
   - `packages/shared-types/src/world/layout.ts` 新增 `ISLAND`：18 顶点手写折线 + 包围盒，
     服务端碰撞、客户端预测、主视图、小地图共用同一份坐标。
   - 沿用 ADR-0008 的原则：静态世界由双端各自 import，不进协议、不落库；
     改海岸线必须双端一起发版。
   - 手写轴对齐顶点，禁止 `Math.random` / `Math.sin` / `Math.cos`，避免 Bun(JSC) 与 V8 末位差异。

2. **收缩可活动陆地，不改世界常量**
   - 陆地收到内容包围盒外 50–80px，四处海湾（北、东、南中、西南）切掉没有内容的空草地，
     每个海湾都留一个朝外的开口，与外海连通。
   - `WORLD_WIDTH` / `WORLD_HEIGHT` 保持 8192：改常量会牵动 u16 定点量化、8 字节移动包、
     AOI 网格与压测脚本，收益只是坐标数字变小。
   - 协议、`clampWorldX/Y`、AOI、移动速度全部不动。

3. **海即墙：碰撞先判陆地，再查既有障碍**
   - `isBlocked()` 开头增加 `isOnLand(x, y, radius)`；海不建成 blocker，
     避免给「无限大的水面」建索引。
   - `resolveMotion()` 的 4px 子步与单轴滑动自动继承海岸线，贴岸走会滑行而不是卡死。
   - `findFreePoint()` 的环形搜索同时受陆地约束；岛外输入先夹回岛屿包围盒再就近搜。
   - 不引入海岸网格：200 人 × 20Hz 每 Tick 约 400 次 `isOnLand`，18 顶点几何约 1.4 万次浮点运算，
     远低于 50ms Tick 周期。若压测 p95 上升超过 10%，再按 128px 网格预分类（见复核信号）。

4. **渲染：海面铺底 + 草地多边形遮罩 + 三层海岸过渡**
   - 海面 `TilingSprite` 按世界矩形外扩 2048（12288×12288），超宽视口贴到岛边也不露黑。
   - 草地仍铺 8192，用 `ISLAND` 多边形 `Graphics` 做 mask 裁成岛；复用湖面遮罩的既有做法。
   - 海岸从外到内：深海 → 浅滩 72px → 沙滩 26px（压在海陆交界线上）→ 草地。
   - 纹理仍是初始化期一次性 `generateTexture`（1:1 + nearest），帧循环只滚 `tilePosition`；
     海面与湖面尺寸不同，`WaterSurface.tile` 各存各的回绕模数。
   - 树、围栏、角色继续按脚底 y 排序，海岸线只影响地面层，不改排序语义。

5. **相机与小地图消费同一条边界**
   - `updateCamera` 把相机中心夹到 `ISLAND.bounds`；视口比岛还宽时居中，NaN 回落到中心。
   - 小地图先铺海色，再用 `ISLAND` 多边形填陆地、描沙滩线，其余图层不变。

6. **出生点拒绝采样**
   - `spawnPoint` 最多重抽 16 次，落海或落进湖面、河面、树干、花箱的点直接丢弃；
     `findFreePoint` 只负责贴岸与极近距离的就近脱困。
   - 压测 `GAME_SPAWN_RADIUS=3000` 时仍保持稀疏分布，不会被兜底塞回广场。
     20000 次采样验证：0 个落点进入障碍、0 次中心兜底。

## 后果

- 正面：地图边界可见；玩家走到海岸被沙滩与海挡住，画面不再出现世界外黑边；
  协议、世界常量、AOI、移动手感零变更；碰撞与渲染仍共用一份海岸线。
- 负面：`shared-types` 继续承担世界内容职责；草地遮罩多一次 draw call，
  WebGPU 下依赖 stencil（湖面已有先例，低端设备需实测）；
  海岸线是手工坐标，改形状要同时看内容包围盒与海湾净距。
- 回滚成本：低。删除 `isBlocked` 的 `isOnLand` 分支与 `findFreePoint` 的陆地夹取，
  再移除 `TerrainView.addSea / addShoreShelf / addShoreSand` 与草地 mask，
  即回到满屏草地；`ISLAND` 数据留在包里不影响任何协议。

## 复核信号

- 200 人压测 Tick p95 相对本次之前上升超过 10% → 引入 128px 海岸网格预分类。
- 低端 WebGPU 设备上草地遮罩掉帧 → 改成一次性烘焙的海岸纹理，去掉 stencil。
- 出现第二座岛、分线或多地图 → 把 `ISLAND` 抽成地图配置，再考虑拆内容包。
- 玩家反馈「贴着海岸走会抖」→ 检查本地实体收敛策略，与围栏的既有复核信号合并处理。
