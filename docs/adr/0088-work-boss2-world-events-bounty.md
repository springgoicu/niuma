# ADR-0088：打工产出、Boss 2.0、世界事件与每日悬赏

- 状态：已采纳
- 日期：2026-11-15
- 关联：[ADR-0082](0082-niubi-coin-economy.md)（牛马币经济与钱包快照）、
  [ADR-0087](0087-hotspot-registry-and-four-buildings.md)（热区注册表）、
  [ADR-0081](0081-server-clock-and-persistent-world-state.md)（园区时钟）

## 背景

经济闭环（ADR-0082）已经能花能赚，但收入来源集中在擂台、击倒与商店，
缺少「日常班味」的稳定产出：坐上工位没事可做，老板只有 10000 点血和一脚一点，
广场上没有全服一起参与的随机事件。与此同时，`EconomyStats.workEffLv` 与 `critLv`
两个属性从上线起就只是商店里的数字，没有任何玩法读它。

这一轮要把这四处补齐，并严格沿用既有约束：服务端零持久化、协议只追加、
热区只有一张表、发币只有一个入口。

## 决策

### 1. 搬砖：服务端只认「坐姿 + 工位 + 间隔」

- `C2S_WORK_CLAIM` 只带一个连击字节，**不带金额**：金额在服务端由
  `workPayout(roll, workEffLv, night)` 算出，客户端连一个可篡改的数字都发不上去。
- 校验三条：`player.seat` 必须落在 `WORKSTATIONS` 那 8 个椅子上
  （`isWorkDeskSeat`）、人还在对应 `work-desk-<n>` 热区的半径 + 240px 延迟余量内、
  距上一次领取 ≥ 6s（比一轮 8s 短 2s，容忍 RTT 抖动）。
- 工效每级 +8%，夜间（园区本地 21:00–06:00）×1.5，单轮封顶 120 币。
- 客户端那 8 秒终端小游戏是纯本地玩法（`work-grind.ts`），
  一轮没敲完不发包；敲完才发一次领取。

### 2. Boss 2.0：命中掉落、暴击与 25% 冲击波

- 每次真实命中：2~5 币，暴击翻倍。暴击率 = `critLv × 5%`，封顶 35%，
  与商店文案同一把尺子（`bossCritChance`）。
- 尾刀（`justDied` 那一次）发 500 币，并用既有大喇叭通道播一条全服弹幕：
  不新增「全服高光」下行包，`S2C_LOUDSPEAKER` 已经具备这个语义。
- 冲击波阈值用「结算后血量是 2500 的整数倍」判定，不在 `BossRuntime` 里另存阈值下标：
  跨日重置、重启续血、单测直接写血量三种情况都不需要额外同步一份状态。
- 触发时全服广播 `S2C_BOSS_SHOCK(phase=Warn)`，2 秒后由主 Tick 结算：
  圈内**没有起跳**（`player.jump` / `jumpUntilMs`）且未倒地的人被震退 48px 并躺地 1.5s。
  跳跃免疫读的是移动包里的跳跃位，客户端无法自证「我跳了」。

### 3. 世界事件：调度器挂 Tick，红包不做实体

- `WorldEventScheduler` 不自己开定时器：挂在主 `setInterval` 上按 `now` 单向推进，
  阶段为 Announce(3s) → Active(红包 45s / 查岗 10s) → Resolve(2s)，周期 10 分钟。
  这样时钟可注入、单测不需要 `setTimeout`。
- 红包雨 25 个点由 `redPacketSpots(seed)` 确定性撒出：服务端与客户端读同一个纯函数，
  服务端只维护 25 位已领取位图 + 距离校验 + 序号校验，领取是 O(1)。
  因此**不需要**为「可拾取物」在 AOI 里新增一种实体类型，也不扩 `S2C_ENTITY_SPAWN`。
- 查岗在倒计时结束那一 Tick 结算：坐在工位椅（`isWorkDeskSeat`）上的真人各发 60 币，
  在广场（`isOnPlaza`）乱晃的最多点名 2 人（走大喇叭，避免刷屏）。

### 4. 每日悬赏：进度只在服务端累计

- 三件事（踢老板 10 次 / 赢 1 局 P2P / 搬砖 2 轮）服务端都亲眼看见过，
  因此进度由 `DailyQuestRuntime` 计数，客户端上报的进度一律不采信。
- 日期键 `serverDayKey` 与老板零点重置、考勤「今日」字段共用同一个时区偏移；
  换日整表清零，`claimed` 每日每项一次。
- 断线即回收：换浏览器回到本地存档的余额，但今日进度从 0 开始——
  与「服务端不记得你是谁」同一条口径。

### 5. 协议与配置只追加

- 新 opcode 从 `0x51` 起：`C2S_WORK_CLAIM / S2C_WORK_RESULT / C2S_QUEST_CLAIM /
  S2C_QUEST_STATE / S2C_WORLD_EVENT / C2S_EVENT_CLAIM / S2C_BOSS_SHOCK /
  S2C_EVENT_CLAIM`；三个新上行包登记进 `net/guard.ts` 定长表，`TABLE_SIZE` 扩到 `0x58`。
- `WALLET_REASON` 追加 28–31（搬砖工资 / 抢到红包 / 踢老板掉落 / 查岗全勤），
  编号永久不复用。
- 所有参数集中在 `packages/shared-types/src/work.ts`：两端预估与结算读同一份常量。

### 6. 像素装扮：6 件配件 + 脚底金光的承载方式

- 头饰 +2（黄金安全帽 / 皇冠）、眼镜 +2（赛博墨镜 / 金丝眼镜）、颈饰 +2（大金链 / 红围巾），
  全部追加在 `catalog.ts` 与 `COSMETIC_CATALOG` 末尾，32 字节外观编码不变，`ATLAS_VERSION` 升到 11。
- 外观编码没有 aura 槽位，因此脚底金光绑在**黄金安全帽**上：
  渲染层按实体头饰判定并程序化绘制呼吸光斑（`fx/aura-gold.png` 是参考稿）。
  好处是远端玩家也能看见；代价是「想要光就得戴那顶帽子」，这在本轮可接受。

## 后果

- 正面：工位从摆设变成稳定收入点；`workEffLv` / `critLv` 终于影响玩法；
  全服事件不需要额外实体同步，流量与 AOI 逻辑零改动；悬赏进度不可伪造。
- 负面：搬砖与查岗都依赖「坐在工位上」这一条，服务端不会校验客户端是否真的在敲字
  （只校验坐姿与间隔），脚本仍可刷出 15~30 币/8 秒的产出——这是「不做账号」下
  能用最小成本换到的防刷上限。
- 回滚成本：低。移除新 opcode 路由、三个运行时与 6 件配件即可回到上一版，
  旧客户端遇到新 S2C 会由 `PACKET_UNKNOWN` 静默丢弃。

## 复核信号

- [ ] 出现「挂机脚本刷搬砖」的举报 → 需要把一轮的打字节奏样本上行给服务端校验。
- [ ] 红包雨期间 egress 明显上升 → 考虑把 25 个点压成位图 + 局部 AOI 广播。
- [ ] 悬赏进度出现「换设备丢失」投诉 → 需要账号或可迁移凭据（与 ADR-0082 同一条）。
- [ ] 冲击波把玩家推穿地形 → 检查是否绕过了 `resolveMotionInto`。
