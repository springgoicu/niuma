# ADR-0099：路面叙事、窄通道净宽与「先走马路」的自动导览

- 状态：已采纳
- 日期：2026-11-15
- 关联：沿用 ADR-0008（位移解算与单轴滑行）、ADR-0013（像素烘焙与灰度开关）、
  ADR-0036 / ADR-0040（导览与自动寻路）、ADR-0091（场所门牌）、ADR-0097（五区与大改）

## 背景

五区、25 个场所与五座区门都已落地，但「跑图」这件事还有三处糙：

1. **路面没有路口语言**：四条主路与六条支路交会处全是同一块土色；生活大街、
   游乐大街、服务广场与企业前庭只有 `fillPaving` 的 40px 井字缝，读起来像一整块灰布；
   广场有路缘，射出去的五个街口却没有斑马线与铺砖过渡。
2. **窄通道贴墙发黏**：企业楼走廊净宽 40px（角色直径 18），两人交错只剩 4px；
   公寓 301/302 之间的巷道也是 40px。更要紧的是 `resolveMotionInto` 只试「整步 → 单轴 x → 单轴 y」，
   斜着撞上 90° 内角时三条全被挡就 `break`，剩余位移全丢——玩家体感是「顶住不动」。
3. **自动导览对着墙硬走**：网格 A* 给的是「最短可通行路径」，会贴墙根、切草地；
   `Navigator` 再逐 16px 路点直线推进，于是频繁触发 700ms 卡死判定，整段导航被取消。
   同时 `NAV_TARGETS` 只有 12 条，家庭影音室、摸鱼亭、护士急救站三处进不了导览卡。

## 决策

### 1. 路面叙事只做客户端，构造期一次成图

新增 `apps/web/lib/game/road-dressing.ts`：从 `WORLD_LAYOUT.paths` 的中心线顶点、
`DISTRICTS[].gate` 与四片街区铺装常量**推导**路口、斑马线与指引箭头，再由
`PropsView.build()` 画进那一张 `ground: Graphics`（贴花之上、y 排序层之下）。

- 路口：48×48 石砖拼花 + 12×6 错缝砖 + 没接路的那几面压 2px 路缘；
- 斑马线：五座街口各 5 道横条，从街口往广场里退 26px，落在石面上；
- 指引箭头：四条主路每 220px 一枚，指向广场；
- 路侧指示桩：五座街口 + 四条主路中点各一根，牌面取 `DISTRICTS[].color`。

**一条都不进 `WORLD_LAYOUT`**：不加 `PropKind`、不写 `PROP_FOOTPRINT`、不进 `solids`，
因此不扰动树点、席位与协议。`?flat=1` 整层跳过，回到旧的纯平铺画法。

夜间灯感只强化 `props.ts` 里 lamp 贴图自带的暖色光晕 + 地面一枚烘焙椭圆，
**不新增 `LightSpec`**：`lighting.test.ts` 已把常驻光源预算钉在 `MAX_LIGHTS = 96`。

冬季在 `terrain.flushEdges()` 的土路分支上加 2px 薄雪内缘 + 7px 密度的 1×1 雪粒，
`?edge=0` 与 `?flat=1` 都会跳过。

### 2. 走廊 40 → 56，公寓巷道 40 → 48

- `CORRIDOR_H = 56`；`CAMPUS_RECT.h = ROOM_H × 2 + CORRIDOR_H = 776`。
  两排房间尺寸分毫不动，多出来的 16px 全部给走廊；`VENT_ROOM` 的 y 由走廊派生，
  `BOSS_ARENA` 与 `BOSS_SOLID` 随之下移，室内余量不变。
  两人交错余量 4px → 20px。
- `APARTMENT_ALLEY = 48`：只把中列 302 / 305 东移 8px，门、出门点、窗表全部从 `rect` 派生。
- **两处坐标改动需要双端同步发布**（服务端碰撞解算与客户端预测同源）。

路面灯柱跟着楼下沿下移 16px：企业楼南墙 3960 → 3976，原来离墙 20px 的两盏灯
（西主路北侧 3300/2900）改为 3996 与 4228 —— 这一对是节日彩旗的挂点，
必须同时挪同样的 16px，否则间距会从 232 变成 216。

### 3. `resolveMotionInto` 增第三级「1px 内角侧移」

整步被挡、两条单轴滑行也被挡时，再试 1px 的微步（原方向一次，垂直两侧各一次，
垂直方向先用 2px 探针决定先试哪边）。**侧移计入位移预算**，所以总位移永远不超过
调用方给的步长——不会被用来加速；服务端 20Hz 的限速逻辑完全不受影响。

### 4. 路网节点图：先走马路，尾段交给 A*

新增 `apps/web/lib/game/road-graph.ts`（惰性构图，首次导航才建）+ `nav-route.ts`（三层规划）：

1. 直线可走且不涉水 → 一个点；
2. 路网图 Dijkstra（约 56 个节点 / 57 条边）+ string-pull → 沿街折线；
3. 尾段看不见目标时从最后一个路点跑一次 `findPath` 收口；图给不出路线就整体回退 A*。

构图规则（全部从既有布局推导，不写第二份坐标）：

- 节点 = 广场心 + 各条路的中心线顶点 + 五座区门 + 四片街区铺装的「内缩 40px 八点环」；
- T 型接点按「落在某段 8px 内」投影插点，让生活大街西延、影音室支路真正接进图里；
- **站不住、或落在建筑内部的点直接不入图**：东主路中心线正好穿过小黑屋，
  那两个顶点会被剔掉，改由服务广场的环形节点绕过去；
- 每条边按 8px 采样 `isBlocked(…, PLAYER_RADIUS)` 校验，走不通就用「中点 + 垂直偏移」探针绕行；
- 收口阶段把还没并进广场那一块的连通块接一条最短可见边（上限 420px）。

终点选择不是「距离最近的节点」，而是 `图上代价 + 到目标的直线 + （看不见目标时）离区门多远`
最小的那个——否则企业区的室内目标会被「直线更近」的游乐大街西端抢走。

### 5. 导览补三处 + 「回中央广场」，不新增协议

- `NAV_TARGETS` 12 → 15：补 `theater` 家庭影音室、`pavilion` 摸鱼亭、`clinic` 护士急救站
  （三处都已有 `VENUES` 条目，只补 `navId`），各配一块入口小门牌（`DOOR_PLAQUES` 9 → 12 块 `board`）。
- **广场不进 `NAV_TARGETS`**：它不属于任何大区，做成目标会破坏 `districts.test.ts` 的
  「目标 ↔ 场所 ↔ 大区」一一对应。改为导览卡底部一条「回中央广场」，
  目标是 `SPAWN_CENTER`，走同一个 `Navigator`（目标类型放宽为 `NavGoal`）。
- 卡死不再一次就放弃：第一次原地重规划（沿路网换一条），第二次才交还控制权。
  `Navigator` 的 `WAYPOINT_RADIUS / ARRIVE_RADIUS / STUCK_MS` 三处常量保持不变。

**不新增协议与操作码**：`navigateHome` 只是渲染线程与主线程之间的一条内部消息，
`0x20 / 0x2a / 0x2b / 0x3d / 0x4d–0x50` 继续留空。

## 后果

- 玩家沿主路跑图时，每段都有可读的地标（路口拼花、斑马线、指引箭头、区色指示桩）；
- 企业楼走廊与公寓巷道不再「贴一下就停」，斜着进墙角也能滑进去；
- 自动导览会沿道路转弯、经区门进屋，卡死率显著下降，且失败时有第二次机会；
- `shared-types` 的三处改动（campus / apartment / collision）与导览目标补全需要**双端同步发布**；
- 路面装饰全部是构造期图元，帧循环成本为 0；新增对象只有九根指示桩与三十来个灯晕精灵。
